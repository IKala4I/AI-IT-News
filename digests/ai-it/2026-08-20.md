## 🛠️ Інструменти

**Claude Code [2.1.237](https://code.claude.com/docs/en/changelog) — вбудований стиль «Concise» і env-змінна, що фіксує дефолтну модель**

У 2.1.237 зʼявився output style «Concise»: Claude веде з результатом, без преамбул і наративу, а роботу робить так само ретельно. Вмикається в `/config` → Output style.

Свіже з 2.1.236, що варто знати:
• `ANTHROPIC_DEFAULT_MODEL` — задає модель, з якої стартують нові сесії. На відміну від `ANTHROPIC_MODEL`, вибір через `/model` усе одно перекриває його й памʼятається між рестартами.
• `notify_when_idle` у cross-session `SendMessage` — попросити іншу сесію Claude Code на цій машині разово стукнути, коли вона звільниться (без полінгу, macOS/Linux).

Concise — для тих, кого дратує «розповідь замість відповіді». А env-змінна зручна, якщо тримаєш дефолт на дешевшій моделі й перемикаєшся на важче руками.

**Cursor [прокачав cloud-агентів](https://cursor.com/changelog/08-19-26): підписки на події, кастомні режими і субагенти на окремих машинах**

Напрямок — від «підкажи в чаті» до «працює саме, поки не зробить». Що приїхало:
• Subscriptions: агент сам підхоплює роботу — стежить за PR, слухає Slack-тред, ганяє за розкладом.
• Custom modes: будь-який skill пінниться як постійний «always on» режим.
• Subagents on their own machines: кожен субагент отримує ізольовану копію проєкту у власному cloud-оточенні.
• `/goal`: довга ціль, яку агент тримає до повного виконання; а steering тепер не перебиває агента посеред дії — фолоуап чекає наступного tool call.

Той самий рух, що й у Claude Code цього тижня. Найпрактичніше — `/goal` і subscriptions, якщо ганяєш агента у фоні й не хочеш смикати його на кожному кроці.

## 💡 Рецепти

**Рецепт: причепи крихітну draft-модель до локальної LFM2.5 і отримай 2-3x швидший вивід**

LiquidAI [виклали LFM2.5-DSpark](https://huggingface.co/blog/LiquidAI/lfm25-dspark) — draft-моделі (~300M) для спекулятивного декодування. Ідея стара й перевірена: маленька модель вгадує кілька токенів наперед, велика лише перевіряє — якість не змінюється, швидкість росте.

llama.cpp:

```bash
llama-server -m LFM2.5-2.6B-F16.gguf \
  -md LFM2.5-2.6B-DSpark-F16.gguf \
  --spec-type draft-dspark --spec-draft-n-max 10 --spec-draft-n-min 0 \
  -fa on -ngl 99
```

SGLang:

```bash
python -m sglang.launch_server \
  --model-path LiquidAI/LFM2.5-2.6B \
  --speculative-algorithm DSPARK \
  --speculative-draft-model-path LiquidAI/LFM2.5-2.6B-DSpark \
  --disable-radix-cache --mem-fraction-static 0.75 --port 30000
```

Заміри з блогу: до 3.18x на H100 (418→1074 tok/s) і ~2.87x на M4 Max (61→139 tok/s). Офіційна фіча LiquidAI, команди — з їхнього блогу; цифри — вендорський замір, не незалежний. GGUF і safetensors уже на HF.

Якщо ганяєш LFM2.5 локально — це майже безкоштовний буст: доплата лише кількасот мегабайт памʼяті під draft-модель.

## 📌 Рухи й безпека

**Фейкове «технічне завдання» на співбесіді ставить RAT, який чистить твої dev-креди**

Свіжий [розбір атаки](https://www.codedge.de/posts/how-to-compromise-your-system-with-a-job-interview): рекрутер у LinkedIn під реальну компанію, «тестове» — TypeScript-проєкт на Bitbucket. Запускаєш локально — і воно:
• тягне RCE-лоадер через `api.jsonbin.io`
• краде креди з браузера і 28+ крипто-гаманців (MetaMask, Phantom, Coinbase…)
• зчитує clipboard, робить скріншоти, керує мишею та клавіатурою
• виносить SSH-ключі, AWS-креди і `.env` з домашньої теки

Це повноцінний RAT (C2 `147.189.174.138`), і він ще й уміє детектити VM. Класична схема під RN/mobile та JS-розробників — саме нашу екосистему.

Порада проста: чуже «тестове» запускай тільки в Docker чи VM без своїх ключів, а рекрутера звіряй з офіційним акаунтом компанії, а не з профілем у ЛС.
