**Qwen [випустили Qwen3.8-Omni-Flash](https://qwen.ai/blog?id=qwen3.8-omni-flash) — текст, картинки, звук і відео в одному запиті, 1M контексту**

Це перша omni-модель команди, зроблена навколо агентності: не просто «зрозуміти контент», а спланувати задачу, покликати тули й віддати результат.

• до години безперервного аудіо-відео всередині одного виклику
• година аудіо коштує на 98% менше, ніж у попередниці Qwen3.5-Omni-Plus; аудіо+відео — на 93% менше
• +19.5 бала в середньому по агентних бенчмарках WildClawBench-MM і UniClawBench
• по аудіо-відео Qwen заявляють рівень, близький до Gemini 3.8 Flash
• текстова якість — на рівні звичайної моделі того ж розміру

Головне застереження: ваг нема і не обіцяли. Тільки API — Qianwen AI Platform і Alibaba Cloud Model Studio, через OpenAI-сумісні Chat Completions і Responses. Заодно відкрили Qwen-Live Harness під realtime-API.

Якщо в тебе є задачі на кшталт «переглянути годинний скрінкаст і витягти кроки» — це перший випадок, коли ціна за годину звуку перестала бути стоп-фактором. Але в пайплайн на довго я б це не вшивав: закритий ендпоїнт, ціна може змінитись.

**PrismML [зарелізили Bonsai 2 27B](https://prismml.com/news/bonsai-2-27b) — 5.9 GB і 98.2% якості повної моделі**

У липні вже була Bonsai 27B, і тоді ternary-версія тримала 95%. Нова побудована на Qwen3.8 27B і піднімає планку:

• 1.76 ефективних біта на вагу: тернарні {−1, 0, +1} плюс FP16-скейли по групах
• 98.2% агрегованої якості full-precision моделі, загальний бал 83.9
• контекст 262K, мультимодальна (текст + зображення)
• 143 токени/с на RTX 5090, 46.8 токена/с на M5 Max
• Apache 2.0, ваги на [Hugging Face](https://huggingface.co/collections/prism-ml/bonsai-2)

Запускається на NVIDIA через CUDA і на Apple-залізі через MLX з власними low-bit кернелами — тобто Mac, iPhone і iPad теж.

▶ [Спробувати демо в браузері](https://huggingface.co/spaces/webml-community/ternary-bonsai-2-webgpu-kernels)

Різниця між 95% і 98.2% — це той поріг, за яким локальна модель перестає бути іграшкою для експериментів і починає закривати реальні задачі офлайн.

**[Cactus Needle 3](https://cactuscompute.com/needle) — модель на 8-29 MB, яка робить tool calls прямо на телефоні**

Один бінарник, від 29M до 121M параметрів. Архітектура «драбинкою»: вибираєш від 2 до 20 шарів, і кожна глибина — окрема робоча модель.

Вміє рівно три речі:
• tool calling — на вхід текст, на вихід JSON-виклик; байтова граматика збирається з твоїх схем і обмежує кожен токен, тож виклик завжди валідний
• структурне витягування — з тексту в типізовані поля (інвойси, бронювання, форми)
• ембединги для локального пошуку й роутингу

Крутиться на iOS, Android, Linux, macOS, Windows і в браузері через WebAssembly. На Raspberry Pi 5 автори міряють 400-4k токенів/с декоду. Ліцензія Apache-2.0.

```bash
pip install cactus-needle
```

Для мобільної розробки це цікаво не «інтелектом», а тим, що інтент-парсинг і заповнення форм більше не обовʼязково тягнути на сервер.

## 💡 Рецепти

**Рецепт: [Qwen-MM-Plugins](https://github.com/QwenLM/Qwen-MM-Plugins) — навчити Claude Code читати картинки, відео і PDF нативно, без API-ключа**

Ідея проста: кожна «здібність» ставиться як Skill плюс опційний MCP-сервер з іменем `qwen-mm-plugins-*`. Установник питає, який у тебе харнес.

```bash
curl -fsSL https://raw.githubusercontent.com/QwenLM/Qwen-MM-Plugins/main/install.sh | bash
```

Підтримуються Claude Code, Codex, Gemini CLI, OpenClaw, Qwen Code, Qoder і CodeBuddy. Спільний конфіг лежить у `~/.qwen-mm-plugins/config`, оновлення — той самий рядок із `bash -s -- update`.

Найцікавіший плагін — `core`, і саме він у дефолтному native-режимі **не вимагає жодного ключа**: читає локальні зображення і кадри відео, візуалізує документи, код, дані й 3D-моделі, вміє метадані, кроп, анотацію боксами та експорт сторінок.

Далі просто згадуєш файл у промпті:

```text
@report.pdf     Summarize page 3 and extract its table.
@lecture-2h.mp4 List the main points with timestamps.
```

Потрібен `uv` — через нього `uvx` доставляє Python-залежності на льоту. Хмарні плагіни (`api`, `search`) уже просять свої ключі.

Провенанс: офіційний репозиторій QwenLM під Apache-2.0, команди дослівно з README, сам не ганяв.

## 📌 Рухи й безпека

**Дослідник [розібрав ZCode](https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/) і знайшов, що той тихо заливає весь твій `.git` в хмару**

ZCode — закритий десктопний харнес від Z.ai на GLM-моделях, який улітку активно радили як безкоштовну заміну Claude Code. ferstar розпакував `app.asar` і показав, що поки ти залогінений, застосунок пакує весь воркспейс і шле на Aliyun OSS.

Що в архіві з розібраного прикладу на 42 411 файлів:
• `.git/lfs/` — 196.1 MB (56.8%)
• `.git/objects/` — 102.2 MB (29.6%)
• власне код — 46.2 MB (13.4%)

Тобто вивозиться не робоча копія, а вся історія: видалені колись ключі, непушені гілки, внутрішні хостнейми. Знімок робиться 62+ рази за сесію. Шифрування є, але ключ загортається RSA-публічкою, яку віддає сервер, а приватна лежить тільки в хмарі — розшифрувати власні дані ти не можеш.

Тумблери в налаштуваннях не рятують: «Optimize Experience» керує дозволом на тренування, «Repo Snapshot Indexing» — індексацією на сервері. Ні той, ні той не вимикає саме завантаження. Лікується на рівні файлової системи:

```bash
rm -rf ~/.zcode/v2/checkpoints
mkdir -p ~/.zcode/v2/checkpoints
sudo chattr +i ~/.zcode/v2/checkpoints   # macOS: chflags uchg ~/.zcode/v2/checkpoints
```

Ціна — перестає працювати checkpoint/rewind; чат, автокомпліт і тули живі.

Мораль ширша за один застосунок: перед тим, як пускати черговий безкоштовний харнес у робочий репозиторій, варто хоч раз глянути, що він шле назовні.
