## 🛠️ Інструменти

**DeepSeek [відкрили Harness](https://deepseek.com/harness/en/) — власний агентний харнес під MIT, у якому все є плагіном**

Запускається без інсталяції, Web UI піднімається на `http://127.0.0.1:3080`:

```sh
npx @deepseek-ai/dsh web
```

Плагінами тут є буквально все — моделі, тули, скіли, сесії, сендбокси, сховище, цикли, планувальник і навіть UI. Тобто будь-яку частину можна замінити конфігом, не чіпаючи вихідники.

Другий цікавий шматок — append-only логи сесій. Кожну взаємодію з моделлю можна не тільки переглянути, а й продовжити, форкнути чи переграти заново. Режимів чотири: Standard з повним набором тулів, Code з оркестрацією на TypeScript, Minimal тільки з bash і редактором, Creator для копання в рантаймі.

Це developer preview, і в репо чесно попереджають про breaking changes. Але 400+ балів на HN за пів дня натякають, що дивитись варто вже зараз — особливо якщо тебе дратує, що інші харнеси не даси розібрати на частини.

**OpenAI [привезли Codex на Linux](https://community.openai.com/t/codex-in-chatgpt-desktop-app-for-linux-is-now-in-preview/1390027) — ChatGPT desktop у preview, у `.deb` і `.rpm`**

Підтримка: Ubuntu 24.04 і 26.04 LTS, Debian 13, Fedora 43 і 44, архітектури x64 і ARM64. Усередині — ChatGPT, Work і Codex в одному вікні: проєкти, робота з файлами, браузерні воркфлоу.

З того, на що скаржаться в треді:
• Fcitx під Wayland ламає введення, лікується флагом `--enable-wayland-ime`
• проєкти, створені в CLI, не показуються у списку десктопного застосунку
• Arch і NixOS у списку немає, як і Flatpak чи AppImage

Паритет з macOS і Windows нарешті закрито — Linux-розробники більше не єдині, хто ганяє Codex тільки з термінала. Preview є preview, але ставити вже можна.

**Cursor [навчили cloud-агентів стартувати з готового середовища](https://cursor.com/changelog/08-13-26) — builds замість setup з нуля щоразу**

На внутрішніх середовищах Cursor заміряли 10x швидший бут і 3x швидший time to first token. Агент більше не збирає оточення на кожну сесію — він заходить у вже підготовлений білд.

Приємна деталь: якщо новий білд зламався через поганий коміт чи оновлення залежностей, агент не падає, а бере останній успішний. У дашборді Cloud Agents зʼявився таб Builds зі статусами, логами, SHA комітів і тим, який саме білд використала конкретна сесія.

Нові середовища вмикають це самі. Для старих — заходиш у таб Builds, а щоб спершу перевірити міграцію, тиснеш **Run setup agent** і дивишся, які зміни конфігу він пропонує.

## 💡 Рецепти

**Дай Claude Code памʼять між сесіями — [MCP Memory](https://github.com/fellowgeek/mcp-memory) на OKF і SQLite FTS5**

MCP-сервер, який зберігає нотатки агента як звичайні `.md` файли у форматі Open Knowledge Format і паралельно індексує їх у SQLite з повнотекстовим пошуком.

Найшвидший шлях — візард, який сам знайде встановлені клієнти (Claude, Cursor, Windsurf, Codex, Antigravity) і пропише конфіг:

```bash
git clone https://github.com/fellowgeek/mcp-memory
cd mcp-memory
python3 setup.py
```

Або руками, якщо потрібен лише Claude Code:

```bash
claude mcp add --scope user memory -- /ABSOLUTE/PATH/TO/run.sh
```

За замовчуванням памʼять ізольована по проєктах: `memory/` з читабельними файлами і прихований індекс `.mcp_memory/memories.db`. Хочеш один спільний стор на все — задай у конфізі клієнта env-змінні:

```
MCP_MEMORY_DB_PATH=~/.mcp_memory/memories.db
MCP_MEMORY_DIR=~/.mcp_memory/memory
```

Агенту дістається пʼять тулів, з яких найцікавіші два: `memory_get_last` на старті сесії підтягує, де ти зупинився, а `memory_update_last` записує чекпоінт на кожній віхі.

Сам не тестив — це сьогоднішній Show HN, ліцензія MIT, усі команди взяті з README репозиторію.

Головне тут — не «памʼять» як магія, а те, що вона лежить у гіт-репо звичайним маркдауном. Можна прочитати очима, поправити руками і закомітити разом з кодом.

## 📌 Рухи й безпека

**GitHub [викотили Agent Plugins 1.0](https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app) — плагін, що пакує скіли і MCP-сервери разом, і не належить жодному вендору**

Стандарт відкритий і керується незалежно від Copilot. Пишеш плагін один раз — ставиш у VS Code, Copilot CLI і застосунку Copilot; старі плагіни працюють без міграції.

Структура проста: `$schema` у `plugin.json`, скіли в теці `skills/`, конфіг MCP у `mcp.json`, а все вендор-специфічне (кастомні агенти, команди, правила) — окремо в `com.github.copilot/`. Саме цей неймспейс і робить плагін переносимим.

Для команд є `managed-settings.json` з `enabledPlugins`, `extraKnownMarketplaces` і `strictKnownMarketplaces` — можна примусово ставити потрібні плагіни і заборонити чужі маркетплейси.

![Agent Plugins 1.0](https://github.blog/wp-content/uploads/2026/08/632063945-b123553f-1488-4dd2-9c3b-20716803f9ca.jpg)

Цікаве не в самому релізі, а в напрямку: скіли і MCP-сервери повільно перестають бути «фічею конкретного агента». Якщо формат приживеться поза Copilot, свій набір тулів можна буде носити між інструментами так само, як зараз носиш dotfiles.
