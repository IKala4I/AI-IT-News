**DeepSeek [додав зір у дешевий flash](https://api-docs.deepseek.com/guides/vision/) — `deepseek-v4-flash-vision-exp` читає скріншоти й графіки за ціною тексту**

Ліміти з доків:
• до 600 картинок на один запит, до 384 токенів на картинку
• 1M контексту, до 384K на вивід
• JPEG, PNG, GIF, WebP; до 8192 px по стороні (4096, якщо картинок 15+)
• картинки можна класти тільки в `user`-повідомлення, не в `system` чи `assistant`
• 48 MiB на тіло запиту інлайном, 200 MiB через Files API

Ціна та сама, що в звичайного flash: \$0.22–\$0.44 за мільйон вхідних на cache miss і \$0.66–\$1.32 за вихідні. Нижня межа — off-peak, верхня — в пікові години (01:00–04:00 і 06:00–10:00 UTC).

```python
model="deepseek-v4-flash-vision-exp"
```

Суфікс `exp` чесно натякає, що це експеримент і API може поїхати. Але 600 картинок за запит — це вже не «опиши фото», а масовий розбір скрінів чи PDF-сторінок за копійки.

## 🛠️ Інструменти

**Claude Code [2.1.238](https://code.claude.com/docs/en/changelog) — полагодили витік памʼяті в довгих сесіях і зрив кастомних output-стилів**

Два фікси, які помітно щодня:
• памʼять більше не росте нескінченно в довгих інтерактивних сесіях — результати тулів субагентів звільняються, щойно виїжджають із вікна показу
• кастомні, проєктні й плагінні output styles більше не зʼїжджають назад у дефолтний голос посеред сесії

З нового по дрібному:
• сеттинг `keybindingFlavor: "readline"` — Ctrl+W у промпті стирає до попереднього пробілу, як у Bash (дефолт `"classic"` без змін)
• `claude mcp list` і `claude mcp get` показують вимкнені сервери як `⊘ Disabled`, а не конектяться до них заради healthcheck
• просто `claude` стартує швидше на macOS, а перевірка апдейтів більше не бʼється за CPU зі стартом

Якщо тримаєш одну сесію відкритою півдня — оновись хоча б заради фікса памʼяті.

**[Bun 1.4](https://bun.com/blog/bun-v1.4) переписали на Rust і дали вбудований headless-браузер**

Перший реліз не на Zig, а на Rust. Найцікавіше для тих, хто пише агентів і автоматизацію:
• `Bun.WebView` — керує сторінками через системний WebKit на macOS або Chrome/Chromium по CDP. Без Playwright і Puppeteer у залежностях
• `Bun.Terminal` — нативний pty, щоб драйвити інтерактивні CLI зі скрипта
• `Bun.cron()` — реєструє задачі прямо в crontab / launchd / Task Scheduler
• `Bun.markdown`, `Bun.JSON5`, `Bun.XML`, `Bun.Archive` — замість купки npm-пакетів

У пакетному менеджері зʼявились `bun audit fix`, `bun dedupe`, `bun prune` і `bun pm licenses`. У тестраннері — `--parallel`, `--shard=M/N` та `--changed`, який ганяє тільки тести, зачеплені твоїм діффом.

```bash
bun upgrade
```

`Bun.WebView` і `Bun.Terminal` — рівно ті два примітиви, яких зазвичай бракує, коли пишеш агента, що має «подивитись» сторінку або подрайвити чужий CLI.

**Codex через Amazon Bedrock [не вміє в prompt caching](https://github.com/openai/codex/issues/37674) — і 85% рахунку йде на cache writes**

Автор ішʼю показує цифри з продакшена за 5–8 серпня: 3 656 запитів, 171.94M токенів cache-write і жодного cache-read. У грошах — \$1 182 із \$1 386 загального рахунку за модель.

Причина: нативний провайдер `amazon-bedrock` у Codex CLI не серіалізує `prompt_cache_options` і не має поля `prompt_cache_breakpoint`. Кеш пишеться, але ніколи не читається. Конфіг: Codex CLI 0.147.0, модель `openai.gpt-5.6-sol`, Bedrock Mantle Responses API в us-east-1.

Мейнтейнери поки не відповіли, воркераунду в треді немає.

Агентні воркфлоу тримають стабільний префікс інструкцій — саме той кейс, де кешування економить найбільше. Якщо ганяєш Codex через Bedrock, іди подивись на розбивку рахунку, не чекаючи кінця місяця.

## 💡 Рецепти

**Рецепт: [oc](https://github.com/only-cli/oc) перетворює сайти на міні-CLI, щоб Claude Code не жер токени на HTML**

Ідея проста: замість сирої сторінки на десятки тисяч токенів агент отримує пронумерований текстовий вигляд і команди для навігації по ньому.

```bash
npm install -g @only-cli/oc   # потрібен Node 20+
oc open news.ycombinator.com  # відрендерити сторінку
oc do 1                       # перейти за лінком [1]
oc read 2                     # повний текст блока [2]
oc find <query>               # пошук по відкритій сторінці
oc next                       # наступна частина сторінки
```

У Claude Code ставиться плагіном:

```
/plugin marketplace add only-cli/oc
/plugin install only-cli@only-cli
```

Або скілом: `npx skills add https://github.com/only-cli/oc --skill web-browsing-cli`

Сам не тестив. Ліцензія MIT, команди — з README проєкту. Версія 0.1 і ~70 зірок, тобто дуже рано. Цифру «1 936 токенів проти 177 685 на сирому HTML» дають самі автори — вендорський замір, не незалежний.

Якщо твій агент часто лазить по доках чи трекерах, це найдешевший спосіб зрізати левову частку токенів на веб-читанні.
