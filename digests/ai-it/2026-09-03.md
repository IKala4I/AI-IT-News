**Meta [зарелізили Muse Spark 1.3](https://research.meta.ai/blog/introducing-muse-spark-1-3) — контриб'юторська версія коштує \$0.10/\$0.20 за Mtok**

Дві версії в Meta Model API:
• `muse-spark-1.3` — \$1.25 / \$4.25 за Mtok, кеш \$0.15
• `muse-spark-1.3-contributor` — \$0.10 / \$0.20, кеш \$0.002

Контекст 1M, мультимодальність нативна: відео, картинки й документи всередині реального середовища виконання. Проти 1.2 заявляють приблизно на 20% менше tool calls і на 25% менше токенів на тій самій роботі. Max reasoning mode ще не викотили — обіцяють після додаткових safety-тестів.

Ваг немає: тільки API, власний термінальний Muse Code і OpenRouter. Ендпоінт `https://api.meta.ai/v1` сумісний з OpenAI SDK, тож підключення в наявний тулінг — це рядок конфігу.

За такий прайс contributor-версія проситься в дешеві субагенти. Що саме означає «contributor», на сторінці моделі не розписано — умови варто дочитати перед тим, як зливати туди робочий код.

## 🛠️ Інструменти

**Cursor [навчився ганяти агентів на твоїх машинах](https://cursor.com/changelog/self-hosted-machines) — код, білди й секрети не виходять із мережі**

Три режими:
• My Machines — підключаєш ноут або VM під власні задачі
• Team pools — іменовані черги воркерів, що масштабуються під навантаження і засинають у простій
• Sandbox-інтеграції — AWS Lambda, Coder, Cloudflare, Daytona, Modal, Namespace, Vercel і E2B

Окремо цікаве: self-hosted воркери тепер уміють computer use на Linux і Mac. З потрібними десктопними пакетами агент клікає, друкує, робить скріншоти і водить браузер.

Сам агент лишається в хмарі Cursor, на локальні машини їде тільки виконання tool calls.

Це пряма відповідь на головне заперечення проти хмарних агентів у компаніях із NDA. Для соло-розробника цінніше інше — computer use на власній машині без окремої VM під це.

**Claude Code [оновився до 2.1.259](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) — організації тепер роздають MCP-сервери централізовано**

Що додали:
• `managedMcpServers` — керована настройка, якою організація підсовує HTTP/SSE MCP-сервери всім користувачам; формат запису той самий, що в `.mcp.json`, а записи з локальною командою просто ігноруються
• `--permission-prompts none` для headless-хостів без людини
• `--json` у `claude plugin validate`
• розпізнавання `glab mr create/merge/close/...` — GitLab merge request тепер показується як `MR !N`

Найважливіший фікс: паралельні сесії більше не затирають одна одній `~/.claude.json`. Workspace trust не скидається, стан MCP і проєкту не губиться, коли ганяєш багато сесій разом.

Ще підтягнули покриття deny-правил Bash — тепер вони ловлять файли, передані як значення опцій (`--ignore-revs-file=.env`, `-f.env`, `@file`), файлові операнди `git diff` і `git grep`, а також компаунди виду `cd DIR && cat FILE`.

Якщо тримаєш кілька сесій відкритими одночасно, апдейт вартий сам по собі.

## 💡 Рецепти

**Рецепт: [ганяти Claude Code без людини](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) і без `--dangerously-skip-permissions`**

Для CI чи cron досі лишався грубий вибір: або хтось сидить і тисне «дозволити», або ти вимикаєш перевірки повністю. У 2.1.259 зʼявився третій варіант:

```bash
claude -p "прожени тести і полагодь падіння" \
  --permission-mode auto \
  --permission-prompts none
```

`--permission-prompts none` означає: усе, що спробувало б спитати дозволу, автоматично отримує відмову. При цьому активний permission mode далі вирішує сам — auto-режим апрувить те, що вважає безпечним, а на решті сесія просто йде далі замість того, щоб зависнути в очікуванні вводу.

Різниця з `--dangerously-skip-permissions` принципова: там дозволено все, тут — рівно те, що дозволив би auto-режим, і ні на крок більше.

Прапорець дослівно з офіційного чейнджлогу 2.1.259, у docs його поки немає; сам не ганяв. `--permission-mode` описаний у CLI reference давно.

## 📌 Рухи й безпека

**NVIDIA [купує Hugging Face](https://blogs.nvidia.com/blog/nvidia-to-acquire-hugging-face/) за \$12.93 млрд**

З анонсу: платформа лишається відкритою для всієї екосистеми, бренд і 🤗 зберігаються, команда лишається на місці.

Ключове речення для нас — «NVIDIA compute will not be required to build on or deploy through Hugging Face». Тобто мульти-клауд і мульти-акселератор нікуди не діваються, вибір фреймворку, хмари й заліза лишається за розробником. Про зміни в цінах не сказано нічого.

Обіцянки при поглинанні — жанр окремий, але поки що Hub, `transformers` і `datasets` працюють як працювали. Реальний тест буде на першому релізі, де щось раптом «краще працює на CUDA».

**Google [прописали в умовах Antigravity](https://antigravity.google/terms/), що доступ через сторонні тули — привід забанити акаунт**

Дослівно з Section 6:

> Using third party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity OAuth) is a breach of this Agreement. Such actions may be grounds for suspension or termination of your account.

Формулювання зʼявилось після хвилі банів: вимикали і безплатні акаунти, і платні підписки. Причина, яку називає Google, — сторонні агентні обгортки давали на сервіс постійне навантаження, під яке його не проєктували й не оцінювали.

Претензія розробників була рівно в тому, що прямої заборони в умовах до цього не було, тож комбінацію з зовнішнім харнесом вважали дозволеною. Тепер заборона є.

Якщо ганяєш Antigravity OAuth через будь-яку сторонню обгортку — це той випадок, коли ризикуєш не підпискою, а гугл-акаунтом цілком.
