**[Whiteboard](https://github.com/devdotfast/whiteboard) — опенсорсний десктопний канвас, де агент малює те, що він зробив**

Підключаєш Claude Code, Codex чи інший агент, і він через SDK малює просто в застосунку: sequence-діаграми, entity-діаграми, лог ухвалених рішень. Клік по елементу діаграми стрибає в код під ним.

Окремо їде semantic diff viewer — порівняння на рівні AST, без шуму від переформатувань і перенесених блоків.

• MIT
• збірки під [macOS](https://install.dev.fast) і [Fedora](https://install.dev.fast/linux)
• автори радять ганяти з GPT-6 Sol або Opus 5.5

▶ [Дивитись демо (1 хв)](https://www.youtube.com/watch?v=ChPn3ftULWE)

Найболючіше в агентних PR — не «чи працює», а «що воно взагалі зробило і чому». Діаграма замість стіни діфу цілиться рівно туди.

**[LaunchVideo](https://launchvideo.io) робить промо-ролик з URL продукту — Opus 5.5 пише фільм кодом, а не генерує відео**

Відеомоделі тут немає взагалі. Opus 5.5 пише один HTML-файл з анімацією, а serverless-агент на OpenComputer рендерить його покадрово в headless Chromium, кодує через ffmpeg і віддає MP4.

Виходить 20–40 секунд приблизно за 4 хвилини, десь 90k вхідних і 15k вихідних токенів на ролик. Код відкритий — [diggerhq/shipvideo](https://github.com/diggerhq/shipvideo), агент описаний трьома тулами на TypeScript.

![Кадр з ролика, зробленого LaunchVideo](https://gzvxcspoxhhgoeog.public.blob.vercel-storage.com/examples/infera-gXTtuX8hOzbsPSy3SAAdqKElG42trA.jpg)

Цікавий не так сервіс, як підхід: там, де просяться генеративні пікселі, моделі віддали детермінований рендерер. Результат можна відкрити, прочитати і поправити руками — з відеомоделі так не вийде.

**Claude Code [у 2.1.282](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) почав казати вголос, коли телеметрія в налаштуваннях щось ламає**

Прямий наслідок історії позавчора. Тепер на старті, а також у `/status` і `claude doctor`, з'являється список telemetry-змінних з settings-файлів проєкту, які були проігноровані або вимкнули телеметрію.

З іншого корисного:
• `maxProseWidth` — обмежує ширину прози Claude у широких терміналах, таблиці й код-блоки лишаються на повну
• полагодили Bash-правила дозволів із `:*` посередині патерну: із settings-файлів вони мовчки не працювали, хоча через `--allowedTools` працювали
• компакшен більше не падає, якщо запит на підсумок відхилили — іде ретрай на фолбек-моделі

Другий пункт — той тип багу, через який місяцями живеш у впевненості, що твої permission-правила працюють. Після апдейту варто перечитати свої `settings.json`.

## 💡 Рецепти

**Рецепт: [jevmem](https://github.com/Avinash-jetwani/jevmem) — автоматична пам'ять проєкту для Claude Code, яка сама вирішує, що варто запам'ятати**

Після кожного повідомлення хук віддає репліку Jev (класифікатор від TypeSafe AI), той відповідає на фіксовані типізовані питання — тут є рішення? обмеження? баг? — а пороги в коді вирішують зберегти чи пропустити. Збережене лягає одним рядком у `JEVMEM.md` у репозиторії; коли ти передумав, старий рядок позначається `[superseded]`, а не зникає.

Спочатку ключ:

```bash
mkdir -p ~/.jevmem && echo 'TYPESAFE_API_KEY=...' >> ~/.jevmem/env
```

Як плагін Claude Code, без пер-проєктного налаштування:

```bash
claude plugin marketplace add Avinash-jetwani/jevmem
claude plugin install jevmem@jevmem
```

Або через npm — тоді підхопить ще Cursor і Codex:

```bash
npm install -g jevmem
cd your-project
jevmem init --tool claude
```

Є ще `jevmem import` — розбирає наявний `CLAUDE.md` чи `AGENTS.md` на окремі твердження і проганяє через той самий фільтр.

Сам не тестив, команди з README. Автор чесно пише, що це v0.5 і всі евали писав він сам. В коментах на HN ідею дешевого швидкого класифікатора замість LLM на кожному турі приймають, але насторожує, що кожна репліка і весь файл пам'яті їдуть на сервіс TypeSafe.

## 📌 Рухи й безпека

**[XSS в ansi2html](https://blog.arusekk.pl/posts/srht-account-takeover/) дозволяв захопити акаунт на SourceHut через звичайний лог білду**

Дірка в обробці OSC 8 — це ANSI-послідовність для гіперлінків. Спеціально зібраний escape виривається з атрибута `href` і підсовує свої HTML-атрибути, після чого `onfocus` виконує JS у браузері того, хто просто відкрив сторінку логу.

Далі ланцюжок: витягти CSRF-токен, перезапустити білди, дотягнутись до deploy-ключів. Автор називає це wormable — жертва може рознести далі, сама того не знаючи.

• вразливі `ansi2html` 1.7.0–1.9.3 і `builds.sr.ht` 0.40.0–0.105.0
• пофікшено в `ansi2html` 1.9.4 і `builds.sr.ht` 0.105.1
• CVE-2026-92973

Якщо десь рендериш логи CI у HTML цією бібліотекою — перевір версію. Лог білду мало хто сприймає як недовірений ввід, а дарма: туди пише кожен, хто може надіслати патч.
