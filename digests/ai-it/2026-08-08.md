## 🛠️ Інструменти

**Anthropic [зроблять auto mode дефолтом у Claude Code з 14 серпня](https://claude.com/blog/auto-mode-default-in-claude-code) для Pro, Max і Team**

Auto mode не питає дозволу на кожну дію, а проганяє виклики тулів через окремий класифікатор, який блокує незворотне, деструктивне і спрямоване назовні твого середовища.

Цифри, якими це аргументують:
• люди схвалюють 97% запитів на дозвіл рефлекторно
• у контрольованому тесті ручна перевірка зловила 13.6% небезпечних команд, класифікатор — 89%
• у сесіях з ручним апрувом ненавмисна шкода траплялась у 2.6 раза частіше

Овергед класифікатора для Pro, Max і Team перестали тарифікувати вже з дня анонсу. Режим і далі перемикається через Shift+Tab, а якщо ти сам колись зафіксував інший дефолт — прилетить одноразовий запит на перемикання. Enterprise і API поки лишаються opt-in, їх обіцяють перевести протягом місяця.

Головне тут не «стало зручніше», а що дефолтна модель довіри змінюється мовчки для всіх — краще розібратись з налаштуваннями до 14-го, ніж після.

## 💡 Рецепти

**Лиши собі чекпоінт перед `git push` навіть в auto mode — [через `permissions.ask`](https://code.claude.com/docs/en/auto-mode-config)**

Правила `ask` і `deny` виконуються ДО класифікатора і завжди дають промпт — навіть коли auto mode увімкнений. Тобто можна не вимикати режим цілком, а вирізати з нього рівно ті дії, які хочеш бачити очима.

У `~/.claude/settings.json`:

```json
{
  "permissions": {
    "ask": [
      "Bash(git push *)",
      "Bash(gh pr create *)"
    ]
  }
}
```

Перевірити, що саме бачить класифікатор після твоїх правок:

```bash
claude auto-mode config
```

Два нюанси з тієї ж сторінки. Блок `autoMode` НЕ читається з `.claude/settings.json` у репозиторії — щоб закомічений файл чи білд-крок не підсунули собі allow-правила. І якщо задаєш `soft_deny` чи `allow` без рядка `"$defaults"`, ти затираєш увесь вбудований список, включно з блоками на force push і `curl | bash`.

Офіційна фіча, все є в документації.
