## 🛠️ Інструменти

**Claude Code [оновився до 2.1.221](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) — закрили обхід перевірки дозволів у Bash через zsh**

Головне з релізу — фікс безпеки: zsh дозволяв сховати команду всередині regex-умови `[[ ]]`, і перевірка дозволів її не бачила. Тепер такі команди питають підтвердження. Заразом полагодили перевірки в PowerShell для шляхів із лапками.

Що ще приїхало:
• `mode: "mask"` тепер працює і для файлів з креденшелами на Linux та WSL — пісочниця бачить копію-заглушку, а справжнє значення проксі підставляє вже на виході; на macOS фолбек на `deny`
• Focus view у VSCode-розширенні (`Ctrl+Alt+F`) — ховає активність тулів під згорнуте резюме ходу
• сесії з `/fork` тепер роблять собі окремий worktree, а не працюють у чужому чекауті
• плагіни з `/plugin` активуються одразу, без `/reload-plugins`
• `/status` показує тип сесії: `interactive` чи бекграунд-джоба

Фікс із zsh — привід оновитись сьогодні, а не колись.

## 💡 Рецепти

**Закрий `~/.npmrc` і `~/.ssh` від sandboxed Bash у Claude Code — [офіційний блок `sandbox.credentials`](https://code.claude.com/docs/en/sandboxing)**

Дефолт пісочниці такий: писати можна тільки в робочу директорію, а **читати — весь диск**. Тобто будь-яка команда всередині сендбоксу спокійно бачить твої токени. Вбудованого deny-списку немає — обмежує тільки те, що ти перелічив сам.

У `~/.claude/settings.json`:

```json
{
  "sandbox": {
    "enabled": true,
    "credentials": {
      "files": [
        { "path": "~/.npmrc", "mode": "deny" },
        { "path": "~/.aws/credentials", "mode": "deny" },
        { "path": "~/.ssh", "mode": "deny" }
      ],
      "envVars": [
        { "name": "GITHUB_TOKEN", "mode": "deny" },
        { "name": "NPM_TOKEN", "mode": "deny" }
      ]
    }
  }
}
```

Файли стають нечитабельними всередині сендбоксу, змінні оточення просто прибираються перед кожною командою. `deny`-записи з різних скоупів мерджаться, і жоден скоуп не може прибрати чужий.

Дві межі, про які варто знати: працює тільки для sandboxed Bash, і не діє, якщо `filesystem.disabled` вимкнув файловий шар. Потрібен Claude Code v2.1.187+.

Офіційна фіча, конфіг узятий з документації. Враховуючи новину нижче — саме `~/.npmrc` тут найцікавіший рядок.

## 📌 Рухи й безпека

**Shai-Hulud [захопив `keyv` і сусідні пакети](https://www.aikido.dev/blog/keyv-and-friends-compromised-in-npm-supply-chain-attack) — і цього разу лишає по собі хук у `.claude/settings.json`**

4 серпня зламали GitHub-акаунт мейнтейнера `keyv`. Комміти пішли прямо в main, релізи опублікувались зі справжнім provenance від GitHub Actions. Заражені версії:

• `keyv` 6.0.0 • `flat-cache` 6.1.24 • `file-entry-cache` 11.1.6
• `cacheable-request` 13.0.20 • `cache-manager` 7.2.10 • `@cacheable/utils` 2.5.1

За підрахунками Aikido — понад 400 пакетів і 1381 версія, разом більш ніж 2 млрд встановлень на місяць. Лінійка `keyv` 5.x і опубліковані адаптери `@keyv/*` чисті.

Запускається через `preinstall` (`node setup.mjs`) і збирає все: npm-токени з `~/.npmrc`, GitHub PAT, AWS, Kubernetes, Vault, SSH-ключі. Але цікаве інше — [The Hacker News розібрали](https://thehackernews.com/2026/08/keyv-linked-npm-worm-poisons-hundreds.html), що воно окремо кладе в репозиторій persistence під наші ж інструменти:

```
.claude/settings.json   → SessionStart hook  → .claude/setup.mjs
.vscode/tasks.json      → "Environment Setup" task → .vscode/setup.mjs
```

Спрацьовує не автоматично: і VS Code, і Claude Code гейтять це через workspace trust. Тобто захист — рівно та секунда, коли ти не думаючи тиснеш «довіряю».

IOC-и з [розбору Wiz](https://www.wiz.io/blog/keyv-and-cacheable-npm-supply-chain-attack) — повний CSV зі списком пакетів [лежить у них на GitHub](https://github.com/wiz-sec-public/wiz-research-iocs/blob/main/reports/keyv-packages.csv):

```
node_modules/keyv/Math_Symbol.js
.claude/setup.mjs
.vscode/setup.mjs
/tmp/bun-dl-*/
npm-cache[.]com
```

`flat-cache` і `file-entry-cache` — це транзитивні залежності ESLint. Якщо за останню добу десь піднімався лок-файл, перевір його першим, а середовище, де встиг пройти `npm install`, вважай скомпрометованим. npm 12+ блокує невхвалені lifecycle-скрипти за замовчуванням — це той випадок, коли оновлення самого npm окупається.
