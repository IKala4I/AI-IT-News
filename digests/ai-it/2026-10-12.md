## 🚀 Моделі

**Meta [зарелізили Muse Wonder](https://research.meta.ai/blog/muse-wonder) — фронтір-серію з контекстом 1 048 576 токенів і двома новими механіками поверх звичайного скейлінгу**

Моделі дві: `muse-wonder-1.0` доступна в Meta Model API і в Muse Code, а Muse Wonder Full — тільки підписникам Muse Code.

Цікаве в анонсі:
• Active Memory — модель сама витягує з попередніх розмов те, що релевантне саме цій задачі
• Active Focus — довгі задачі: пробує альтернативні підходи, продирається через блокери, перепитує перед важливими діями

Міряли на Harvey Legal Agent Benchmark, FocusBench і SWE-Marathon. Ціни за токени ніде немає — ні на сторінці анонсу, ні в доках, там лише «Pay-as-you-go».

Якщо потрібен мільйон контексту і ти не прив'язаний до Claude чи GPT — варто глянути. Але Full сидить за підпискою на Muse Code, тож «просто спробувати в API» вийде лише з молодшою.

## 🛠️ Інструменти

**[Pensieve](https://tedhaley.ca/pensieve/) — локальний семантичний пошук по коду, що підключається до агентів як MCP і вчить їх не грепати**

Індексує файли, git-репо (включно з незакоміченим і worktree) та сесії Claude Code, Codex і Qwen Code. Під'єднує все одною командою:

```
sh -c "$(curl -fsSL https://tedhaley.ca/pensieve/install.sh)"
pensieve integrate recommended
```

Ставить MCP-сервер у Claude Code, Codex, Cursor, Gemini CLI, Windsurf і VS Code, плюс блок «search before you grep» і два хуки.

Заміри автора (Sonnet 5.5, 4 репо від 504 до 34 847 файлів): 2.0 тул-коли на пошук проти 3.4 у grep, потрібний файл знайдено 131/144 проти 123/144, на 18% дешевше. Бенчмарк лежить у `bench/`.

MIT, версія 0.5.9. Застосунок — Apple Silicon і macOS 14+; на Linux тільки бекенд і браузерний візуалізатор.

**[Atticus](https://github.com/SaarthurR/atticus-mac) — голосовий асистент для Mac, що крутиться на твоїй підписці Claude через `claude -p`, без API-ключа**

Тримаєш ⌃⌥Space, говориш, відпускаєш. Розкладає вікна по моніторах, шукає файли за вмістом, читає екран і відповідає, набирає текст у поточний застосунок — але ніколи не відправляє.

```
curl -fsSL https://raw.githubusercontent.com/SaarthurR/atticus-mac/main/install.sh | bash
```

Деталі, які сподобались:
• просте (відкрити застосунок, перемістити вікно, музика) взагалі не йде в AI — 0.08 с
• що попросив один раз, стає вивченим шорткатом і теж біжить без AI
• розпізнавання мови локальне, Apple on-device — аудіо з Mac не виходить
• safe mode крутить команди в пісочниці Claude Code; `rm`, `sudo` і диски заблоковані завжди

MIT, потрібні macOS 26+ і платний план Claude. Автор оцінює ~0.14¢ плану на один запит.

Якщо Claude Code вже стоїть — це найдешевший спосіб дати голос своїй машині, бо окремої підписки не треба.

## 💡 Рецепти

**Рецепт: [ColGrep-Agent](https://huggingface.co/blog/lightonai/colgrep-agent) — повісити локальну 2B-модель пошуку субагентом під Claude Code**

LightOn виклали `colgrep --agent`: модель на 2B сидить між агентом і репо, шукає семантично, сама читає найперспективніші файли, ходить по референсах і віддає назад шляхи, діапазони рядків і код. Агент не грепає сам.

```
brew install lightonai/tap/colgrep && colgrep --install-agent
colgrep init
colgrep --install-claude-code
```

Далі перезапустити Claude Code. Перевірити руками можна так:

```
colgrep --agent "where is the database connection pool configured"
```

`--install-agent` тягне модель одноразово, ~2.5 GB. Хуки саме підказують агенту тул, а не примушують силою.

Заміри LightOn (Claude Code на Sonnet 5.5, 52 питання по 13 репо, по 3 прогони, проти grep):
• 142k → 93k токенів на питання, це −34.3% (95% CI 28–40%)
• 7.3¢ → 4.4¢ за питання з урахуванням кешу
• точність 80.8% проти 83.3% — автори кажуть, різниця статистично незначуща
• час на питання виріс з 13.0 с до 21.6 с

Офіційна фіча від LightOn, команди взяті з README репозиторію, Apache-2.0. Сам не тестив. Важливо: міряли саме пошук по коду, а не end-to-end задачі.

Обмін зважений: платиш секундами, економиш третину контексту. Для монорепо, де агент і так тоне в grep-простирадлах, схоже на вигідну угоду.

## 📌 Рухи й безпека

**У git-історії [zod лежав preinstall-бекдор](https://github.com/colinhacks/zod/issues/6658) — але в опублікований npm-пакет 4.6.6 він не доїхав**

Коміт `d821685` з повідомленням «Fix bugs and improve performance» додавав у `zod` і `@zod/mini` файл `meta.test.mjs` плюс `"preinstall": "node meta.test.mjs"`. Лоадер читав список доменів із захардкоженого Ethereum-контракту через публічні RPC, тягнув звідти payload і виконував його правами процесу установки — список на блокчейні, щоб інфраструктуру не можна було просто знести.

Розпакував опублікований тарбол 4.6.6 з registry: ні `meta.test.mjs`, ні `preinstall`, ні рядків лоадера. Пакет чистий. 4.6.6 вийшов 11 жовтня 16:18 UTC, 4.6.7 — 12 жовтня 16:29 UTC.

За [advisory GitHub](https://github.com/orgs/community/discussions/208477) той самий патерн прилетів ще в `nubjs/nub` і `standard-schema`; до npm дійшов лише `@nubjs/nub@0.9.4`, і його зарізав скан реєстру. Maintainer zod пише, що зламали git push credential, а не npm- чи GitHub-токен.

Патчити нічого не треба. Але врятували тут trusted publishing і скани реєстру, а не пінування версій у лок-файлі — варто тримати в голові, коли наступного разу здасться, що lockfile і є захист.
