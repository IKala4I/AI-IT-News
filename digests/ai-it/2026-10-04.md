## 🛠️ Інструменти

**[Strata](https://github.com/Niko1221/Strata) крутить 125B-модель на геймерській карті з 12 ГБ VRAM — і віддає Anthropic-сумісний endpoint**

MIT. Один інсталятор (`START-HERE.bat` на Windows, `./setup.sh` на Linux) питає модель, розмір контексту і чи треба картинки, тягне ~70 ГБ і підіймає [Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) на `http://127.0.0.1:8080`.

Заміряне авторами на RTX 5070 (12 ГБ) + 64 ГБ RAM: Q2_0 — 94 tok/s на вихід і 2650 tok/s на вхід, IQ3_S — 53 і 1620. На RX 9070 XT — 60 і 1160.

Підключити Claude Code:

```
ANTHROPIC_BASE_URL=http://127.0.0.1:8080
```

Для OpenAI-сумісних тулів base URL — `http://127.0.0.1:8080/v1`, ключ будь-який. Є і MCP-сервер, щоб агент сам стартував і гасив Strata.

▶ [Дивитись](https://github.com/Niko1221/Strata/releases/download/v0.1.10/Pagoda.mp4)

Вчора тут був ds4 від antirez з тією ж ідеєю. Різниця в тому, що Strata цілиться в «подвійний клік і працює» і сама підбирає квантизацію під твою RAM.

**Microsoft і Hugging Face [відкрили ThinkingBox](https://huggingface.co/blog/microsoft/thinkingbox) — сендбокс, що оцінює агента не за відповіддю, а за станом бази після нього**

Формулювання з анонсу: «A trajectory is a claim. Database state is the evidence». Тули описуються як MCP-сервери, агент по них ходить, а перевіряється кінцевий стан бекенда і сайд-ефекти.

Бенчмарк — 507 stateful бізнес-воркфлоу, кожен прогнали 20 разів. Головна цифра не pass@1, а скільки задач пройшли всі 20 із 20:
• Opus 5.5 — pass@1 67.16%, але 20/20 лише 241 задача (47.53%)
• GPT-6 Astra — 231 (45.56%)
• GPT-5.4 — pass@1 65.36%, а 20/20 вже 128 (25.25%)

Ціна за «надійно пройдену» задачу — від \$6.80 до \$24.36.

Код під MIT:

```sh
git clone https://github.com/microsoft/thinkingbox.git
uv venv --python 3.12
uv sync --group dev
```

![ThinkingBox](https://cdn-uploads.huggingface.co/production/uploads/64b8491203124195cd795cad/NStwJm1AafDELVsU4KGwS.png)

Цінне тут не цифри, а метод: якщо твій агент пише в базу, одного прогону для перевірки мало.

**[SCM](https://github.com/allenv0/SCM) — локальний пошук по кожному кадру відео і по фото на macOS**

MIT, ставиться через brew:

```sh
brew tap allenv0/scm
brew install --cask allenv0/scm/scm
```

П'ять режимів: Files (пошук по змісту кадру), Scenes (момент усередині відео з переходом по таймкоду), OCR (текст на картинці), Dialogue (сказані слова через Whisper), LLMs (локальний чат по знайденому).

Vision-модель на вибір: CLIP ViT-L/14@336 за замовчуванням (~435 МБ) і три варіанти SigLIP-2. Ваги тягнуться один раз, далі повністю офлайн — «Your media never leaves the machine».

Apple Silicon, macOS 12+. Найцінніший режим — Scenes: знайти потрібну секунду в годинному скрінкасті без ручного скрабінгу.

## 💡 Рецепти

**Рецепт: [Operator Memory](https://github.com/aerovato/operator-memory) — markdown-мозок для агента замість vector DB**

Ідея з [поста, що зібрав 294 поінти на HN](https://liao.gg/blog/agents-dont-need-memory): агенту не потрібна «памʼять», потрібна документація, яку він читає перед роботою і сам оновлює після.

Ставиться так:

```sh
npm install --global @aerovato/operator-helper
operator-helper install claude-code
```

Далі в новій розмові `/operator:user-init` (один раз на машину), потім у кожному проєкті `/operator:project-init`.

Створює три місця: `.operator/` — приватне знання проєкту, `.operator-shared/` — те, що їде в репо для команди, `~/.operator/user/` — твої правила на всі проєкти. Жодних ембедінгів і фонових агентів. Адаптери є під Claude Code, Codex, OpenCode V1/V2, Pi і DeepSeek Harness.

BSD-3-Clause, npm-версія 1.7.1 від 3 жовтня. Сам не тестив. У коментах на HN сходяться, що підхід правильніший за ембедінги, але головний контраргумент — токени: на великому «мозку» читання і оновлення документів починає з'їдати бюджет.
