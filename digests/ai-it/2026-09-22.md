Три чекпоінти на HF, усі MIT:
• `MiMo-V2.6-Pro-RL` — 1.02T параметрів, 42B активних; 70 шарів, 384 експерти, 8 активних на токен
• `MiMo-V2.6-Flash-RL` — легша версія тієї ж архітектури: 48 шарів, 256 експертів, той самий 1M контексту

На вхід ідуть текст, картинки, відео й аудіо, на вихід — тільки текст. Контекст 1 048 576 токенів підтверджується в `config.json` обох старших моделей.

Artificial Analysis дає Pro [46 балів свого Intelligence Index](https://artificialanalysis.ai/models/mimo-v2-6-pro) — перше місце серед 114 порівнюваних моделей у їхньому рейтингу, при \$0.43/\$0.87 за мільйон токенів через API Xiaomi і 76 токенів/с на вихід.

## 🛠️ Інструменти

**Claude Code [у 2.1.280](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) зробив Opus 5.5 дефолтним — а на Pro і Team Standard дефолт поїхав із Sonnet на Opus**

Що ще змінилось у поведінці:
• рівень effort, збережений до того, як `/effort` став по-модельним, більше не застосовується до нових моделей — Opus 5.5 стартує зі свого дефолту
• Opus 4.7, 4.8 і Fable 5 перестали перебивати `/effort` своїм лаунч-дефолтом у `-p`, Agent SDK і конфігах
• `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` міняє ліміт у 2048 символів на описи MCP-тулів і інструкції серверів

Окремо — фікс, вартий уваги сам по собі: запис через симлінк більше не оцінюється за шляхом усередині дерева. Тепер промпт показує, куди файл реально ляже, а `acceptEdits`, allow-правила і auto mode не апрувлять запис, що приземляється поза проєктом.

Тобто якщо в репозиторії лежить симлінк, що дивиться назовні, до 2.1.280 автоапрув міг спокійно туди записати. Привід оновитись, навіть якщо Opus 5.5 не горить.

#tools

**[Drop](https://droprun.sh/) — Linux-сендбокс, зроблений саме під те, щоб пускати кодинг-агентів з вимкненими дозволами**

Ідея як у virtualenv: створив середовище, зайшов, працюєш як завжди — тільки з namespace-ізоляцією. Твій дистрибутив і встановлені програми доступні, юзернейм зберігається, вибрані конфіги видно read-only.

За замовчуванням: домашка своя і writable, оригінальний `$HOME` read-only (а `~/.ssh` просто не існує), поточна директорія read-write, крім `.git`, яка read-only. Доступ до localhost-сервісів заборонений. Зверху опційно накручується gVisor — юзерспейс-ядро, щоб програма не ходила в хостове.

З туру в документації, дослівно:

```bash
drop init claude
drop run -e claude
# уже всередині сендбокса:
claude --dangerously-skip-permissions
```

Apache-2.0, тільки Linux, потрібен пакет `passt`. Це рівно та відповідь на `--dangerously-skip-permissions`, якої бракувало: не «довіряй агенту», а «хай межі тримає ядро».

**Hugging Face [навчили transformers вантажити llama.cpp-кванти](https://huggingface.co/blog/transformers-llama-cpp-quants) — GGUF заїжджає прямо у `from_pretrained`**

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "unsloth/Qwen3.5-4B-GGUF"
filename = "Qwen3.5-4B-Q4_K_M.gguf"

tokenizer = AutoTokenizer.from_pretrained(model_id, gguf_file=filename)
model = AutoModelForCausalLM.from_pretrained(model_id, gguf_file=filename)
```

Розміри на прикладі Qwen3.5-4B: BF16 — 8.42 GB, Q6_K — 3.53 GB, Q5_K_M — 3.14 GB, Q4_K_M — 2.74 GB. Починати радять з Q4_K_M.

Застереження суттєві: упакований шлях інференсу поки MPS-only, тобто Apple Silicon; з архітектур покрито Qwen3.5 dense і MoE плюс сумісні Qwen3.8; потрібен transformers з main.

```bash
pip install -U "git+https://github.com/huggingface/transformers.git" kernels
```

На MacBook Pro M2 Max з 32 GB швидкість близька до llama.cpp — хоча заміри не зовсім apples-to-apples: у transformers у число входить prefill, llama.cpp звітує лише decode.

Якщо пайплайн уже на transformers, тепер не треба тримати поруч окремий llama.cpp-сервер заради квантів.

## 💡 Рецепти

**Рецепт: [цикл «поміряй, зроби швидше, повтори»](https://minimaxir.com/2026/09/agentic-iteration/) — розігнати Rust-крейт агентом у 7.5–32 рази**

Схема: агент спершу знімає базлайн бенчмарками, потім отримує числову ціль, потім крутиться, поки ідеї не закінчаться. Стартовий промпт дослівно:

```
First, without making any further changes, run the CPU Rust benchmarks
to establish a True Performance Baseline. Then, optimize the crate code
to make it such that ALL CPU benchmarks run atleast 1.2x faster
```

```
REPEAT THIS PROCESS UNTIL BENCHMARK PERFORMANCE CONVERGES
AND YOU ARE OUT OF OPTIMIZATION IDEAS.
```

Критична частина — не промпт, а огорожі в [AGENTS.md](https://gist.github.com/minimaxir/86de3cc8f628079d8337e70924b3411d): ніколи не ганяти бенчмарки паралельно, ніколи не підкручувати самі бенчмарки під метрику, ніякого `target-cpu=native` чи інших `RUSTFLAGS`, завжди `criterion` і завжди release. Без цього агент оптимізує вимірювання, а не код.

Коли ідеї вичерпались, автор докидає «c'mon, try doing a breakthrough» і «you are forbidden from giving up easily». Окремо просить зрізати SLoC на 20% — і це теж давало приріст швидкості.

Цифри: на Opus 4.5 виходило 1.5–2.0×, накопичувально через наступні моделі — 7.5–32× від базлайну.

Провенанс: промпти і цифри з посту автора, AGENTS.md — з його ж гіста. Сам не ганяв.

Головне тут переноситься на будь-яку мову: дай агенту вимірюваний критерій і заборони чіпати вимірювач.
