**[skillzero](https://github.com/kurtextrem/skillzero) — ховає скіли з контексту агента, щоб вони не з'їдали токени просто так**

Кожен скіл світить у контекст назву й опис, навіть якщо ти його ніколи не кличеш. Десяток скілів — і це вже помітні токени плюс ризик випадкового спрацювання.

Тул розкладає їх на три категорії:
• unmanaged — як було
• 👻 hidden — повністю приховані, але викликаються руками
• 📚 collection — група під однією темою, підвантажується ліниво

```bash
npx skillzero            # інтерактивно вибрати папку
npx skillzero .          # для поточної теки
npx skillzero --dry-run  # подивитись, що зміниться
npx skillzero undo       # відкотити все
```

Під капотом дописує `disable-model-invocation: true` у `SKILL.md` і `policy.allow_implicit_invocation: false` в `agents/openai.yaml`. Claude Code, Cursor і Codex. MIT.

Show HN від 14 вересня, відгуків поки нуль — але зміни оборотні через `undo`, тож спробувати дешево.

## 💡 Рецепти

**Рецепт: [хук, що ганяє перевірки у фоні й будить Claude тільки коли впало](https://code.claude.com/docs/en/hooks)**

Звичайний PostToolUse-хук блокує агента, поки не добіжить. Для typecheck на великому проєкті це десятки секунд простою після кожного едиту. Лікується двома полями:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npm run typecheck",
            "async": true,
            "asyncRewake": true
          }
        ]
      }
    ]
  }
}
```

`async: true` відправляє команду у фон і не блокує. `asyncRewake: true` додає головне: якщо процес вийде з кодом 2, Claude прокидається і бачить stderr хука (або stdout, якщо stderr порожній) як system reminder.

Тобто зелений прогін проходить мовчки, а червоний сам прилітає агенту в контекст, поки той уже пише щось інше. Важлива деталь із доків: саме exit 2 — код 1 Claude Code вважає неблокуючою помилкою й іде далі.

Офіційна фіча, все є в документації хуків.

**Рецепт: [підняти контекст в Ollama, бо дефолт може бути 4k](https://docs.ollama.com/context-length)**

Сьогодні на HN [розбір міграції](https://patrickmccanna.net/notes-on-migrating-large-prompts-away-from-anthropic-openai-to-self-hosted-llms/) 35-кілобайтного препромпту з Opus на локальну модель. Одна з головних граблів — контекст в Ollama за замовчуванням крихітний, і агент починає молотити tool calls по колу.

Дефолти прив'язані до VRAM:
• &lt; 24 GiB — 4k
• 24-48 GiB — 32k
• 48 GiB і більше — 256k

Задається при старті сервера:

```bash
OLLAMA_CONTEXT_LENGTH=64000 ollama serve
```

У застосунку Ollama те саме є слайдером у налаштуваннях.

Якщо локальна модель поводиться тупіше, ніж мала б, — перевір це першим. 4k на 24-гігабайтній карті нормальний агентний цикл просто не витягне, і виглядатиме це як «слабка модель», а не як обрізаний конфіг.
