## 🚀 Моделі

**Anthropic [зарелізили Claude Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5) — ціна не змінилась, а на Terminal-Bench 4.0 він обійшов навіть Opus 5.5**

\$2/\$10 за Mtok, кеш-ріди \$0.20, контекст 1M. У [changelog Claude Code 2.1.284](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) він уже дефолтний Sonnet на Anthropic API, і він же тепер крутить безплатний тариф claude.ai.

| Бенчмарк | Sonnet 5.5 | Sonnet 5 | Opus 5.5 |
|---|---|---|---|
| Terminal-Bench 4.0 | 70.6% | 10.3% | 66.4% |
| CursorBench 4.0 | 55.5% | 34.1% | 57.8% |
| GDPval-AA v2.1 | 1844 | 1449 | 1846 |
| OSWorld 2.1 | 80.1% | 57.0% | 81.8% |

Заявлені 30%+ швидкості й до 30% дешевше за задачу — не через прайс, а бо модель витрачає менше токенів і кроків на те саме.

Головне тут не таблиця, а те, що дефолтний Sonnet підтягнули до Opus-рівня на агентних задачах за ту саму ціну. Якщо ти тримав Opus на всьому саме через агентні фейли — час перемірити на Sonnet.

**OpenAI на DevDay [показали GPT-6.1 Sol і почали продавати швидкість окремо](https://simonwillison.net/2026/Sep/29/openai-devday-2026-live-blog/)**

Sol — це \$2/\$10 за Mtok і \$0.10 за кешований інпут, тобто рівно в ціну Sonnet 5.5.

Що ще з цього можна помацати:
• **Ultrafast** — той самий Astra 6, але до 300 токенів/с: 8× швидше за 6× ціни, для Sol обіцяють згодом
• **Decisions API** — модель відповідає за долі секунди, обираючи з готових варіантів; поки прев'ю
• **Dots** — завжди-онлайн агенти з голосом та інтеграціями в Slack, Teams і пошту; на Pro і Enterprise
• **Agents API** отримав Computer Use

Лінк — на лайв-блог Саймона Віллісона з кейноуту: сам openai.com з цієї сесії недоступний, egress-політика віддає 403.

Ultrafast тут найцікавіший: швидкість інференсу вперше стала окремим SKU, а не властивістю моделі. В агентному лупі, де ти чекаєш на кожен крок, 6× ціни може й окупитись — а може виявитись, що вузьке місце було не в моделі.

## 🛠️ Інструменти

**OpenAI [відкрили Codex Security CLI](https://github.com/openai/codex-security) під Apache-2.0 — сканер, який шукає, верифікує і патчить діри в репозиторії**

```
npm install @openai/codex-security
npx @openai/codex-security login
npx @openai/codex-security scan /path/to/directory
```

Ще є `npx @openai/codex-security policy .` — генерує політику під конкретний репозиторій. Треба Node 22.13+ і Python 3.10+. У CI замість інтерактивного логіну — змінна `OPENAI_API_KEY`.

Нюанс, який варто знати до того, як ставити: частина запитів і так званих protected findings відкривається лише через програму Trusted Access for Cyber, і сам тул поки в беті.

Цікаве тут не саме сканування, а що воно тримає стан між запусками: знахідки дедуплікуються, а фікси перевіряються. Тобто це заявка не на разовий аудит, а на щось, що живе в CI.

**Claude Code [у 2.1.285](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) навчився відкривати десктоп-апку з термінала і вимикати WebFetch однією змінною**

• `claude --desktop` — відкрити Claude Desktop на поточній папці, або на сесії з `--continue` / `--resume <id>`
• `CLAUDE_CODE_DISABLE_WEB_FETCH` — вимкнути тул WebFetch
• `claude plugin configure <plugin>` — показує опції плагіна і які з них не задані; нові значення приймає зі stdin через `--values-stdin`

З 2.1.284, якщо пропустив: `/mcp reconnect all` перепідключає всі впалі MCP-сервери одним рухом, а `/usage` і статус-лайн показують ліміт витрат у доларах, а не у відсотках.

`--desktop` виглядає дрібницею, але це перший нормальний мостик між терміналом і GUI: почав у CLI, продовжив у десктопі на тій самій сесії. А `plugin configure` нарешті знімає потребу лазити в `/plugin` руками після кожного інсталу.

## 💡 Рецепти

**Рецепт: [decision-моделі локально в Ollama](https://ollama.com/blog/ollama-now-supports-jev-style-decision-models) — гейт на tool call'и агента без раунд-трипу в клауд**

Ollama 0.35 додав ендпоінт `/v1/systemone` і три моделі: `nimble` (9B від Bespoke Labs), `tev1` (4B) і `tev1:0.8b` від Together AI.

```
ollama pull nimble
```

Найкорисніший юзкейс — спитати локальну модель, чи безпечний виклик, перед тим як його виконати:

```
curl http://localhost:11434/v1/systemone -d '{
  "model": "nimble",
  "state": "run_shell(command=\"rm -rf ~\")",
  "questions": {
    "harm": {
      "type": "noul",
      "instructions": "Could this tool call cause harm?"
    }
  }
}'
```

Відповідь — `{"harm": {"type": "noul", "noul": 0.996}}` за 138 мс, при `output_tokens: 1`. Замість `noul` можна попросити `type: "choice"` з набором `criteria` — тоді на виході лейбл плюс probabilities по кожному варіанту.

Якщо хочеш через SDK, а не curl:

```
export TYPESAFE_BASE_URL=http://localhost:11434
export TYPESAFE_API_KEY=ollama
export TYPESAFE_DEFAULT_MODEL=nimble

uv add typesafe-sdk
```

Офіційна фіча, команди і payload — з блогу Ollama; сам не тестив. Заміри теж їхні: 91 мс на рішення в Pac-Man-прикладі на MacBook Pro M5 Max.

Це прямий апдейт до рецепта з GLM-5.3-Flash із дайджесту 27.09: те, що тоді доводилось робити prefill'ом через API, тепер окремий клас моделей, який крутиться локально. Роутинг, тріаж, модерація, «чи пускати цей tool call» — усе, де раунд-трип у клауд коштує дорожче за саме рішення.
