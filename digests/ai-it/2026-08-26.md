**Z.ai [зарелізили GLM-5.3-Flash](https://z.ai/blog/glm-5.3-flash) — той самий стелс-Ox Alpha, і він перший в Artificial Analysis Intelligence Index**

Цифри з [model card](https://huggingface.co/zai-org/GLM-5.3-Flash):
• 320B параметрів, 18B активних, гібрид sparse + linear attention
• перша нативно мультимодальна модель у лінійці GLM-5
• Terminal Bench 2.1 — 84.3, DeepSWE — 63.4, HLE — 55.3
• ліцензія MIT, ваги на HF, з коробки vLLM, SGLang, TokenSpeed і KTransformers

[Artificial Analysis](https://artificialanalysis.ai/models/glm-5-3-flash) ставить її на #1 зі 173 з індексом 57 — при \$0.15/\$0.50 за Mtok і вікні 400k.

У [треді на HN](https://news.ycombinator.com/item?id=49449507) (456 балів) тон обережніший: хвалять за UI-задачі і ціну, але кажуть, що на довгих ланцюжках міркувань до Opus 4.8 ще далеко, а локально це ~160 GB VRAM на Q4. Там же нагадують, що модель балакуча — 150M вихідних токенів на тестах проти медіанних 64M, тож дешева ставка за токен не завжди означає дешевий таск.

**Qwen [виклали Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) — таймер із учорашнього дайджесту дотік, ваги на місці**

Що змінилось із учора: замість заглушки з відліком — повна model card. Специфікації підтвердились (125B MoE, 6B активних, 51B n-gram-ембедингів плюс 4B MTP), а зверху зʼявились деталі, яких не було: нативні 262 144 токени контексту з розширенням до 1M, Hybrid Attention із Qwen Sparse Attention і вбудований vision encoder. Ліцензія — `qwen-community-1.0`.

Бенчмарки: SWE-bench Pro 62.5, DeepSWE 1.1 58.7, GPQA Diamond 91.7, LiveCodeBench v6 91.9, AndroidWorld 84.5.

Тверезий момент із [HN-треду](https://news.ycombinator.com/item?id=49448210): llama.cpp архітектуру ще не підтримує, PR на `qwen4exp` у роботі. Готові поки лише 1-bit кванти (~72.5 GB), а GGUF від Unsloth просить мінімум 75 GB RAM. На DGX Spark міряють до ~40 t/s.

Тобто «поставлю на вихідних» — це поки радше про vLLM, ніж про Ollama. Власникам 128 GB варто дочекатись 4-bit.

**IBM [зарелізили Granite 4.2](https://huggingface.co/blog/ibm-granite/granite-4-2) під Apache 2.0 — 3B, 8B і 30B з контекстом 512K і перемикачем «думати / не думати»**

Найпрактичніша з трьох сьогоднішніх моделей, бо реально влазить у ноут. Три щільні decoder-only моделі однакової архітектури, різняться лише розміром.

Головне:
• режими thinking / non-thinking плюс окремий low-effort thinking — коротке міркування тільки там, де воно потрібне
• 8B і 30B вміють в агентні сценарії: тул-коллінг у OpenAI-сумісному форматі, редагування коду, термінал, веб-пошук
• 512K контексту на всіх трьох розмірах
• на HF викладені FP8, FP4 і GGUF

Цифри для 30B: SWE-Bench Verified 57%, AIME25 89.17%, RULER 64K 89.96%, MMLU-Pro 77.60%.

![Granite 4.2](https://cdn-uploads.huggingface.co/production/uploads/65cc2c288ebd392213e58899/XHWV2L_wZsFe3ekksCgvQ.webp)

Apache 2.0 плюс GGUF плюс 8B — це рідке поєднання, коли локальну модель можна не тільки запустити, а й покласти в продукт без юридичних танців.

## 🛠️ Інструменти

**Ollama [прикрутили Claude Desktop](https://ollama.com/blog/claude-desktop) — локальні відкриті моделі тепер вмикаються прямо в застосунку Claude**

Ollama виступає third-party gateway, і налаштовувати руками нічого не треба: відкриваєш Ollama, обираєш Claude, вмикаєш тумблер — далі воно саме прописує гейтвей.

Після цього в Claude можна крутити будь-яку модель з Ollama — і локальну, і з їхньої хмари, — а в Settings задати, яка модель підставляється під кожен слот. Вимкнув тумблер — повернувся до звичайного Anthropic-сетапу.

В FAQ окремо кажуть, що телеметрія вимкнена за замовчуванням і що в Ollama Zero Data Retention на всі моделі й сервіси, хмарні включно.

![Claude Desktop + Ollama](https://files.ollama.com/claude-0.png)

Цікаво це не заміною Opus на 8B, а тим, що звичний інтерфейс раптом працює офлайн. Розбір чутливого коду чи NDA-документів — рівно той кейс, де хочеться і UI Claude, і щоб нічого нікуди не полетіло.

## 💡 Рецепти

**Рецепт: посадити Claude Code на GLM-5.3-Flash через `ANTHROPIC_BASE_URL`**

Z.ai тримає Anthropic-сумісний ендпоінт, тож Claude Code можна повністю перевести на GLM без жодних патчів — міняється тільки `~/.claude/settings.json`.

Автоматично, macOS і Linux:

```bash
curl -O "https://cdn.bigmodel.cn/install/claude_code_zai_env.sh" && bash ./claude_code_zai_env.sh
```

Скрипт пропише мінімальний набір:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "your_zai_api_key",
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "API_TIMEOUT_MS": "3000000"
  }
}
```

Руками (працює і на Windows) можна одразу розкласти моделі по слотах:

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "your_zai_api_key",
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash[1m]",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.3[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": 1,
    "API_TIMEOUT_MS": "3000000"
  }
}
```

Що варто знати заздалегідь: потрібен ключ і платний GLM Coding Plan, а зміни підхоплюються лише в новому вікні терміналу. Є ще `npx @z_ai/coding-helper`, який робить те саме інтерактивно.

Офіційна фіча, усе — з [документації Z.ai](https://docs.z.ai/devpack/tool/claude). Сам не тестив; чесна засторога — у самій доці підтвердженою названо версію Claude Code 2.0.14, тобто на свіжих 2.1.x можливі несподіванки.

## 📌 Рухи й безпека

**AWS [купує DuckLabs](https://ducklabs.com/news/2026/08/26/ducklabs-to-join-aws) — команду DuckDB; сам DuckDB лишається MIT під нонпрофітним Foundation**

Оголосили Mark Raasveldt і Hannes Mühleisen, угода закривається на початку вересня. Команда лишається в Амстердамі і продовжує працювати над DuckDB, DuckLake і Quack.

Що обіцяють не чіпати: DuckDB та інші опенсорсні частини «Duck Stack» лишаються безкоштовними під MIT, IP тримає DuckDB Foundation. Peter Boncz з CWI у коментарі підтверджує, що так і буде далі.

Що зміниться: у Foundation зʼявиться technical advisory board із людей зі спільноти, а стек екстеншенів планують відкрити — щоб у DuckDB запускались екстеншени, підписані сторонніми розробниками.

У [треді на HN](https://news.ycombinator.com/item?id=49448321) (695 балів) головна тривога передбачувана: DuckLabs пʼять років демонстративно не брали венчур саме заради незалежності. Згадують MySQL під Oracle і сумніваються, що команда витримає корпоративні процеси.

![DuckLabs to join AWS](https://ducklabs.com/img/blog/ducklabs-aws-blog.png)

Прямого наслідку для юзера сьогодні нема — але якщо DuckDB у тебе в пайплайні, третьосторонні підписані екстеншени варто тримати в голові як найпомітнішу технічну зміну.
