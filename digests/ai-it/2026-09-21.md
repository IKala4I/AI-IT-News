## 🚀 Моделі

**xAI [зарелізили Grok 4.7](https://x.ai/news/grok-4-7) — і того ж дня модель приїхала в GitHub Copilot**

Цифри з анонсу:
• \$2 за мільйон вхідних токенів, \$6 за вихідні
• Fast-варіант — удвічі швидший вихід за удвічі вищу ціну
• CursorBench 4.0 — 46.3%, DeepSWE v1.1 — 71.0%
• HackerBench v0.3 — 3.3% проходження ризикових промптів

База більша, ніж у 4.6, плюс довший RL. Окремо підкреслюють утримання контексту на довгих задачах і новий шар захисту від джейлбрейків. Контекстне вікно в анонсі не назвали.

У [Copilot](https://github.blog/changelog/2026-09-21-grok-4-7-is-now-available-in-github-copilot) модель є на Pro, Pro+, Max, Business і Enterprise — у пікері VS Code, Visual Studio, CLI, JetBrains, Xcode і Eclipse. Білиться за прайсом провайдера. Розкочують поступово, тож може ще не бути видно.

Ставити нічого не треба: якщо ганяєш агентні задачі в Copilot чи Cursor — просто зʼявиться в пікері моделей.

## 🛠️ Інструменти

**Google [відкрили AX](https://agentexecutor.io) — Apache-2.0 оркестратор, щоб ганяти агентні задачі мільярдами**

Чотири примітиви, все декларативно через YAML і kubectl-подібний CLI:
• `Task` — ізольований сендбокс під недовірений код агента, з лімітами CPU і памʼяті
• `Workspace` — заздалегідь підключені гіт-репи, MCP-сервери і скіл-пакети, щоб агент стартував теплим
• `Gateway` — вихідний трафік тільки за явним allowlist хостів
• `Model` — яку LLM юзає сама платформа, креди з k8s-секрета

Є `ax ssh` усередину живого сендбокса, плюс `ax suspend` / `ax resume`.

```bash
go install github.com/google/ax/cmd/ax@latest
ax apply -f examples/task.yaml
ax watch task task123
```

Нюанс: локального режиму немає — потрібен справжній кластер Kubernetes і свій реєстр образів. Тобто це не «спробувати за пʼять хвилин», а радше відповідь на питання «де це все житиме, коли агентів стане багато».

**[Heretic](https://heretic-project.org/) знімає з локальних моделей відмови — автоматично і з мінімальною втратою якості**

Метод — параметризована directional ablation. Рахує різницю середніх активацій на «шкідливих» і «нешкідливих» промптах, ортогоналізує матриці attention out-projection та MLP down-projection, а параметри підбирає TPE-пошуком через Optuna, оптимізуючи водночас кількість відмов і KL-дивергенцію від оригіналу.

Цифри з README на Gemma 3 12B:
• оригінал — 97/100 відмов
• версія Heretic — 3/100 відмов при KL 0.16
• ручні абляції тієї ж моделі — KL 0.45–1.04

```bash
pip install -U heretic-llm
heretic Qwen/Qwen3-4B-Instruct-2507
```

Тримає більшість dense-моделей, частину MoE і гібридів. На RTX 3090 Qwen3-4B обробляється 20–30 хвилин, є `quantization: bnb_4bit` під менше VRAM. Ліцензія AGPLv3.

Головне тут не «зняти цензуру», а що воно робить це автоматично і міряє, скільки моделі коштувала операція.

**Hugging Face [зарелізили tokenizers v1](https://huggingface.co/blog/tokenizers-v1) — від 3 до 30 разів швидше за v0.23 і без жодної зміни в API**

Те саме API, ті самі token ID на виході: оновлюєш залежність — і все. Заміряно однопотоково на Apple M4 Max, на десяти сімействах моделей.

Що зробили під капотом:
• свої спліттери на бітстрімах замість regex-рушія — SIMD жує по 64 байти за операцію
• thread-local кеш слів, щоб не мержити ті самі слова повторно
• переюз буферів у merge-циклі замість алокації на кожен виклик

На восьми воркер-потоках тримає 76% лінійного масштабування. Покриває вісім BPE-сімейств плюс WordPiece і Unigram — усе, що вантажила v0.23.

Якщо токенізація стоїть у тебе в гарячому шляху — підрахунок токенів перед запитом, чанкінг під RAG, фільтр по довжині — це рідкісний випадок, коли прискорення дістається задарма.

## 💡 Рецепти

**Рецепт: [Kev](https://github.com/jaredpalmer/kev) — підняти локальну заміну хостед Jev у себе на машині**

Четвертий день поспіль тема швидких «моделей-рішень», але цього разу з іншого боку. Jev — хостед API, Kev — три відкриті моделі під Apache-2.0 поверх Qwen3.5, які тримають той самий формат запиту (`/v1/systemone`) і крутяться локально.

Відповідають на три типи питань одночасно з одного спільного тексту: yes/no з імовірністю, вибір з опцій і оцінка за шкалою.

```bash
git clone https://github.com/jaredpalmer/kev.git && cd kev
uv sync --extra serve
KEV_DTYPE=bf16 uv run --extra serve python -m kev.serve --run jaredpalmer/kev-4b --port 8009
```

Точність на нових джерелах, з таблиці в README:

| модель | база | accuracy | Brier |
| --- | --- | ---: | ---: |
| kev-0.8b | Qwen3.5-0.8B | 0.684 | 0.460 |
| kev-4b | Qwen3.5-4B | 0.837 | 0.255 |
| kev-9b | Qwen3.5-9B | 0.852 | 0.237 |

Автор чесно пише, що хостед Jev точніший — 0.857 і Brier 0.211. Kev-9B відстає приблизно на 3.5 пункти, зате без вендора.

Сам не тестив: команди і цифри взяті з README репозиторію. Треба Python 3.12+, `uv` і CUDA або Apple Silicon; на Mac під 4B/9B у bf16 просять 32 GB.
