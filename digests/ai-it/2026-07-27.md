## 🚀 Моделі

**Moonshot AI виклали у відкритий доступ [повні ваги Kimi K3](https://huggingface.co/moonshotai/Kimi-K3)** — 2.8-трильйонну MoE-модель, найбільшу відкриту модель у світі

До сьогодні K3 був доступний тільки через API з середини липня. Тепер ваги можна викачати й самостійно хостити: MoE-архітектура на 896 експертів (16 активних на токен), 104B активних параметрів, контекст 1M токенів, нативно розуміє текст, зображення й відео. У MXFP4-квантизації важить приблизно 1.4TB.

На бенчмарках: 93.5 на GPQA Diamond, 88.3 на Terminal-Bench 2.1. Ліцензія — власна "Kimi K3 License", не MIT/Apache, тож не зовсім "відкритий опенсорс" у звичному розумінні. Рекомендовані рушії для self-host — vLLM і SGLang; є й готовий API на platform.kimi.ai за $3/$15 замільйон токенів вхід/вихід (кеш-хіти на вхід — $0.30).

1.4TB і потреба в кластері GPU означає, що для більшості self-host — не варіант, і йтимуть через API. Але факт, що модель такого класу взагалі викотили з вагами у відкритий доступ, — черговий удар по тезі "фронтир тільки в закритих API".

## 💡 Рецепти

**Офіційний рецепт Moonshot: [підключити Kimi K3 напряму в Claude Code](https://platform.kimi.ai/docs/guide/claude-code-kimi)** — той самий CLI, інша модель під капотом

Moonshot зробили ендпоінт сумісним з Anthropic API спеціально для Claude Code — можна лишити звичний CLI, просто перенаправити його на Moonshot.

```bash
export ANTHROPIC_BASE_URL="https://api.moonshot.ai/anthropic"
export ANTHROPIC_AUTH_TOKEN="YOUR_MOONSHOT_API_KEY"
export ANTHROPIC_MODEL="kimi-k3[1m]"
export ENABLE_TOOL_SEARCH="false"
claude
```

Перевірка — командою `/status` всередині сесії: має показати `kimi-k3[1m]` і `api.moonshot.ai`. У `/model` Kimi не з'явиться — перемикання тільки через змінні середовища.

Це офіційна інструкція з документації Kimi API Platform, сам не тестив. Важливо: Anthropic прямо каже, що не підтримує й не перевіряє сторонні gateway для Claude Code, тож це виключно Moonshot-документована інтеграція. Також через цей маршрут поки не працює WebFetch.

Якщо хочеться прогнати довгий рефакторинг через 1M-контекст задешево, не міняючи звичний інтерфейс — швидкий спосіб спробувати без переписування воркфлоу.

## 📌 Рухи й безпека

**MCP отримав [фінальний реліз-кандидат специфікації 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)** — прибрали сесії й `initialize`-хендшейк

Найбільша зміна: більше немає хендшейку `initialize`/`initialized` і заголовка `Mcp-Session-Id`. Кожен запит тепер самодостатній, тож MCP-сервер можна ставити за звичайним round-robin балансувальником без sticky-сесій чи спільного session store.

Що ще: нова Extensions Framework з двома розширеннями "з коробки" — MCP Apps (інтерактивний HTML-інтерфейс у sandboxed iframe) і Tasks (для довгих операцій), повна підтримка JSON Schema 2020-12 для тулів, і формальний deprecation-цикл (12+ місяців) для Roots, Sampling і Logging.

Фінал — 28 липня, tier-1 SDK мають підтримку в цьому ж вікні.

Якщо самі пишете чи хостите MCP-сервер — тулинг доведеться переписати під stateless-транспорт, зате він переживе горизонтальне масштабування без окремої інфраструктури. Якщо просто юзаєте MCP-сервери в Claude Code чи Cursor — просто чекайте апдейту SDK з боку хоста.
