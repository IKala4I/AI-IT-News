**Show HN: [turbo-fieldfare](https://github.com/drumih/turbo-fieldfare) ганяє Gemma 4 26B-A4B у ~2GB RAM на M-серії Mac**

Кастомний рантайм на Swift і Metal, який не вантажить модель у пам'ять цілком: резидентно тримає лише 1.35GB ядра плюс FP16 KV-кеш, а решту експертів стрімить із SSD на вимогу.

```
git clone https://github.com/drumih/turbo-fieldfare.git
cd turbo-fieldfare
swift build -c release
.build/release/TurboFieldfareMac
```

Що треба: Apple Silicon (автор валідував на 8GB M2 MacBook Air), macOS 26 з Metal 4, Xcode 26 і Swift 6.2+, ~14.3GB вільного місця під ваги. Ліцензія коду — Apache 2.0, ваги йдуть на своїх умовах з Hugging Face. Підтримується поки рівно одна модель — Gemma 4 26B-A4B instruct.

Сьогодні це №1 на HN. Якщо в тебе 8-16GB Mac і локальні моделі досі впирались у RAM — уперше є сенс спробувати 26B-модель на такому залізі, платячи за це читанням з диска.

**Simon Willison [показав](https://til.simonwillison.net/llms/mcp-in-claude-and-chatgpt), як підключити власний MCP-сервер у веб-чати Claude і ChatGPT**

Обидва UI вміють MCP, але шлях до налаштувань неочевидний.

• Claude: **+** біля поля вводу → Connectors → Add custom connector → назва та URL сервера, авторизація в Advanced settings
• ChatGPT: Settings → Security and login → увімкнути Developer mode → сторінка Plugins → **+** угорі праворуч → New Plugin з URL і типом авторизації, далі підтвердити попередження про ризик і в чаті вибрати MCP через **+**

Одне обмеження, яке Simon зафіксував окремо: з ChatGPT Advanced Voice mode до MCP-тулів достукатись не вдалось.

Корисно, якщо MCP-сервер уже написаний під Claude Code чи Cursor — той самий ендпоінт можна віддати у веб-чат і не тримати термінал відкритим заради пари запитів.

## 📌 Рухи й безпека

**GitHub [розкатали пачку змін](https://github.blog/security/supply-chain-security/disrupting-supply-chain-attacks-on-npm-and-github-actions/) у npm і Actions, які ламають типові supply-chain атаки**

Найболючіше для щоденної роботи: у **npm v12 install-скрипти вимкнені за замовчуванням** — це breaking change. Легітимні скрипти доведеться апрувити поіменно. Заодно за замовчуванням прибрали залежності через git і remote URL.

Решта змін:
• Dependabot тепер чекає три дні після релізу, перш ніж відкрити PR на апдейт версії — увімкнено за замовчуванням, security-апдейти й далі йдуть одразу
• staged publishing: навіть з валідними креденшелами пакет висить у стейджингу, доки публікацію не підтвердиш окремим 2FA
• high-impact акаунти йдуть у read-only на 72 години після зміни email або використання 2FA recovery-коду
• `actions/checkout` більше не тягне недовірений код з форків у `pull_request_target` за замовчуванням
• кеш Actions став read-only для недовірених тригерів, щоб через нього не можна було дострибнути до привілейованих воркфлоу

Логіка зрозуміла: зламати ланцюг там, де атака масштабується. Якщо в проєкті є пакети з postinstall (а нативних залежностей це стосується майже завжди) — апдейт до npm v12 одного дня завалить білд, і краще перевірити це заздалегідь, ніж ловити в CI.
