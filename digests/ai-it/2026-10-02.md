## 🛠️ Інструменти

**Claude Code [у 2.1.287 відкрив Claude Mods](https://code.claude.com/docs/en/plugins/mods/overview) — плагіни тепер можуть малювати свій інтерфейс і перехоплювати tool call'и**

Mod — це плагін, чиї хуки написані на JS або TS і виконуються всередині процесу Claude Code, а не як зовнішній скрипт. Що це дає:
• панель збоку від транскрипту або смужку над промптом — з табами, кнопками й полями
• перемалювати те, що Claude Code малює сам: рядок tool call'а, спінер, діалог з питанням
• притримати tool call, відповісти на нього самому або відправити запит в іншу модель
• `/command`, що запускає твою функцію одразу, без ходу моделі

Частина вбудованих фіч уже працює так — наприклад `/diff`. Джерела кількох лежать [у репозиторії](https://github.com/anthropics/claude-code/tree/main/mods).

Важливе: mods не в сендбоксі, бачать змінні середовища і можуть схвалити tool call замість тебе. Перед установкою варто прогнати `claude plugin validate ./some-mod` — виведе рядки `hooks:` і `calls:`.

Досі кастомізація Claude Code зводилась до markdown і shell-скриптів. Тепер харнес програмується зсередини — і це ж причина читати код чужого плагіна до install, а не після.

**Earendil [зарелізили Pi 1.0](https://earendil.com/posts/pi-1-0/) — мінімальний агентний харнес, який за добу зібрав понад 1600 поінтів на HN**

З нового в релізі:
• codemode — нативна підтримка MCP, не-LLM моделей (Jev) та image-моделей
• deferred tool loading і cache warming для моделей Anthropic
• extension'и для віртуальних моделей
• системні повідомлення посеред розмови: промпт і набір тулів змінюються з урахуванням транскрипту
• нова тема TUI, фулскрін за замовчуванням

MIT, код на [github.com/earendil-works/pi](https://github.com/earendil-works/pi), ставиться одним рядком:

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

**GitHub [навчив Copilot клікати по десктопних застосунках](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps) — читає вміст вікна, тисне контроли, вводить і редагує текст**

Ще вміє натискати клавіші, скролити й тягати елементи. Сенс — автоматизувати legacy та GUI-only софт, у якого немає ні API, ні CLI.

Де працює: Copilot CLI і застосунок Copilot на macOS та Windows. У CLI:

```
/computer on
/computer show
/computer off
```

У застосунку — Settings → Computer Use → Enable Computer Use, або та сама команда.

Перед тим як узяти застосунок під контроль, Copilot питає дозвіл; список «always allow» можна передивитись і скинути. На macOS сам проводить через видачу прав на Accessibility і Screen Recording.

Public preview. Computer use на своєму ж десктопі — найшвидший спосіб прикрутити автоматизацію до того, що API ніколи не отримає. І найшвидший спосіб дати агенту права, про які потім забудеш.

**DeepSeek [виклали Harness Desktop](https://www.deepseek.com/en/harness/) — опенсорсний харнес під macOS і Windows, де все є плагіном**

Зібраний на архітектурі Cordis «everything is a plugin»: десктопний застосунок плюс веб-UI. Працює з Word, Excel, HTML, TypeScript, Python, PDF і Markdown — тобто не тільки з кодом.

З коробки: дослідження репозиторію, фікси, фічі, прогін тестів, інспекція execution trace з деталями рантайму для дебагу, плагін під заплановані задачі. Плагіни або ставиш офіційні, або просиш написати прямо в чаті — режим Creator mode.

Збірки: [macOS arm64](https://download.deepseek.com/desktop/dsh-latest-macos-arm64.dmg) і [Windows x64](https://download.deepseek.com/desktop/dsh-latest-windows-x64.exe).

![DeepSeek Harness](https://www.deepseek.com/harness/images/deepseek-harness-social.jpg)

Навколо вже є [комʼюнітний реєстр dsh.pub](https://dsh.pub/en/) з 8 998 плагінами — кожен запінений на публічний коміт, з автовалідацією при сабміті. Ліцензії різні, реєстр сам радить дивитись репозиторій кожного.

Цікаве тут не агент, а десктоп із плагінами на документи — ніша, яку термінальні харнеси не закривають.

## 💡 Рецепти

**Рецепт: увімкнути вбудований mod [«You should know»](https://code.claude.com/docs/en/plugins/mods/overview#mods-built-into-claude-code) — side agent, що страхує тебе на довгих задачах**

Поки Claude працює, окремий агент дивиться збоку і, коли знаходить щось, що ти або Claude могли проґавити, показує нотатку над промптом. За замовчуванням вимкнений. Спершу перевір версію:

```bash
claude --version   # потрібно 2.1.287 або новіше
```

Далі в сесії:

```
/plugin enable cc-plugin-you-should-know@builtin
```

Якщо його не видно в `/plugin` → Installed, тисни **Show disabled**. Два застереження з changelog: працює для first-party сесій з увімкненою телеметрією, і для твоєї організації він може бути недоступний.

Там же, поруч, лежать семпли мод'ів від Anthropic — найкорисніший `blast-radius`: притримує ризиковану shell-команду (`rm -rf`, force push), показує, що саме вона зачепить, і дає кнопки «далі» або «скасувати». Приміряти можна на одну сесію, без установки:

```bash
git clone https://github.com/anthropics/claude-code-playground
claude --plugin-dir ./claude-code-playground/claude-code/mods/blast-radius
```

> Офіційна фіча, команди з документації і changelog. Сам ще не ганяв.

Обидва рецепти — про одне: страхування замість уваги. Дешевше, ніж вичитувати кожен diff і кожну команду руками.

## 📌 Рухи й безпека

**Supabase [купує Turso](https://supabase.com/blog/supabase-is-acquiring-turso) — під базу даних, яку агент створює так само легко, як файл**

Головна теза анонсу саме така: створення бази має коштувати агенту не більше, ніж створення файлу. Архітектура Turso це дозволяє — один сервер тримає мільйони баз, що підіймаються на вимогу.

Що з продуктами: Turso продовжує працювати, libSQL (SQLite, перезібраний на Rust) і Turso Database — свою роботу. Для поточних клієнтів нічого не змінюється. Про ціни й терміни переходу в анонсі не сказано нічого.

Glauber Costa і Pekka Enberg переходять у Supabase, Costa очолює напрям agentic infrastructure. Postgres лишається за Supabase, SQLite — за Turso.

![Supabase × Turso](https://supabase.com/images/blog/2026-10-02-supabase-is-acquiring-turso/thumb.png)

Сьогодні діяти не треба. Але якщо тримав Turso як легкий per-user SQLite під мобільний бекенд — тепер це частина чужої дорожньої карти, і варто перечитати її перед наступним проєктом.
