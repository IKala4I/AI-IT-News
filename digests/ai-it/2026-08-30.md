## 🚀 Моделі

**Tencent [виклали Hy4 preview](https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/) — 770B під Apache-2.0, 1M контексту і ваги на Hugging Face**

MoE на 770B загальних параметрів, з яких активні 49B. На HF лежить [`tencent/Hy4-preview`](https://huggingface.co/tencent/Hy4-preview) плюс FP8-версія — разом ~1.56 TB, тож «покрутити локально» це не про ноутбук.

Що є з коробки:
• два рівні міркування — `high` за замовчуванням і `no_think`
• готові рецепти для vLLM і SGLang зі спекулятивним декодингом через вбудований MTP-шар
• API через Tencent Cloud TokenHub і OpenRouter: \$0.834 / \$2.501 за Mtok, кеш-хіт \$0.042

Вимкнути міркування можна прямо в запиті, окрема модель для цього не потрібна:

```python
response = client.chat.completions.create(
    model="hy4-preview",
    messages=[{"role": "user", "content": "..."}],
    extra_body={"chat_template_kwargs": {"reasoning_effort": "no_think"}},
)
```

У власному сліпому тесті Tencent на 203 інженерних задачах (163 експерти) Hy4 набрав 2.99/4.00 проти 2.92 у GLM-5.3 і 2.94 у Kimi K3 — перевага в межах похибки, і це самозвіт вендора.

Ще один відкритий флагман, який можна взяти через OpenRouter і прогнати на своїх задачах, не чекаючи чужих оглядів. Цікавий тут радше мільйон контексту, ніж бенчмарки.

## 🛠️ Інструменти

**[vLLM 0.28.0](https://github.com/vllm-project/vllm/releases/tag/v0.28.0) довів sparse MLA для DeepSeek V4 до end-to-end — і виніс bitsandbytes у зовнішній плагін**

Sparse MLA тепер працює наскрізно: звичайний decode, MTP і спекулятивне декодування через DSpark. Плюс великий заїзд по Kimi-K3 — fused-кернели, Decode Context Parallel, шардинг shared-експертів економить ~17 GiB на GPU.

Перед оновленням прочитай breaking changes — їх цього разу помітно:
• bitsandbytes переїхав у зовнішній плагін
• Transformers піднято до 5.15.0
• викинули `calculate_kv_scales` і `override_attention_dtype`
• `max_num_batched_tokens` за замовчуванням 16384 замість 8192

Якщо в тебе самохост на vLLM — це не той реліз, який ставиться наосліп у п'ятницю. Але сама підтримка DeepSeek V4 без милиць того варта.

## 💡 Рецепти

**Рецепт: прибрати `claude.ai/code/session_…` з власних комітів**

Сьогодні [тред про це](https://github.com/anthropics/claude-code/issues/66504) виліз на головну HN. Claude Code з веб- і Remote Control-сесій дописує в кінець коміта та опису PR лінк на сесію — за замовчуванням і нікого не спитавши. Звичний `attribution.commit: ""` його не прибирає: [окремий баг](https://github.com/anthropics/claude-code/issues/41873) про це закрили як not planned.

Ключ насправді є і його нарешті [задокументували](https://code.claude.com/docs/en/settings-reference) — `attribution.sessionUrl`. У `~/.claude/settings.json`:

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

`commit` і `pr` прибирають трейлер у коміті та рядок в описі PR, `sessionUrl: false` — сам лінк на сесію. Локальні CLI-сесії його й не додавали, тож там це no-op.

Офіційна фіча, є в settings reference. Сам ключ у релізах давно, а в доках з'явився помітно пізніше — звідси й свіжий тред із проханням зробити його opt-in.

Якщо комітиш із Claude Code on the web у публічне репо — це той рядок конфігу, який ставиться до наступного пуша, а не після.
