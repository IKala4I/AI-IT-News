## 🚀 Моделі

**Qwen [виклали Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1) — 7B на генерацію, нативна прозорість і до 10 референсних картинок**

Що вміє:
• генерація і редагування в одній моделі, 2K нативно
• RGBA з альфа-каналом прямо з тексту — без вирізання фону
• локальні правки кружечком, домальованою поміткою або маскою
• до 10 референсів з утриманням ідентичності людей і продуктів

Архітектура компактна: 32 Single-Stream DiT шари, mixed-granularity attention і переюз prefix KV-кешу. Окремо їдуть PE-T2I і PE-I2I — два чекпоінти Qwen3.5-VL 9B, які переписують промпт під задачу.

Головна засторога — ліцензія. Qwen-Image і Qwen-Image-Edit були Apache-2.0, а 2.1 приїхала під Qwen Research License: некомерційно, за комерцію домовляйся окремо. Для пет-проєкту норм, у прод — читай ліцензію.

## 🛠️ Інструменти

**Claude Code [у 2.1.278 перестав білити класифікатор auto mode](https://code.claude.com/docs/en/auto-mode-classifier-billing)**

В auto mode перед кожною ризикованою дією — шелл-команда, мережевий запит — бігає класифікатор безпеки. Досі це були окремі запити, за які платив ти. Тепер сервер робить перевірку в межах звичайних запитів сесії і не тарифікує її.

Кого стосується: Enterprise, Claude API, Bedrock, Vertex, Foundry. На Pro, Max і Team не міняється нічого — там і раніше не білилось.

Якщо між тобою і API стоїть LLM-гейтвей, який ріже незнайомі поля (`safeguards` у запиті, `safeguard_results` у відповіді), сервер до сесії не достукається: Claude Code покаже нотіс і відкотиться на власний класифікатор. Статус видно в `/status`, рядок Auto mode server.

Не питати сервер узагалі:

```bash
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

На Pro чи Max — просто мимо. А якщо ганяєш Claude Code через корпоративний гейтвей, це прямий привід попросити адміна пропускати тіло і хедери як є.

**Cua [виклали CUA-S1](https://huggingface.co/cua-ai/cua-s1-forms) — 706 тисяч параметрів і 2.8 MB, які заповнюють форми замість LLM**

Та сама ідея, що в Jev і Laya: модель не генерує текст, а за один forward pass віддає ймовірність для кожного варіанта. Задача вузька — GUI-форми: на вхід елемент інтерфейсу і список типізованих опцій (`fill ...` плюс фіксовані `check` / `click` / `skip`), на вихід розподіл.

Усередині — byte-level ембединги і 2-шаровий трансформер-енкодер шириною 128.

Цифри з картки моделі: 99.95% top-1 на синтетиці, 100% на маленькому реальному евалі (196 рішень) і 37% на контролі з перемішаним контекстом — тобто модель таки читає елемент, а не вгадує по статистиці опцій. Проти хостед Jev на тій самій задачі — 99.7% проти 83.6%.

Код під MIT, ваги в safetensors, лоадер свідомо відмовляється жерти pickle. Автори чесно пишуть: тренувались на синтетиці, на довільних реальних формах не валідовано.

## 💡 Рецепти

**Рецепт: [laya-coreml](https://github.com/mizorewww/laya-coreml) — гнати Laya на Apple Neural Engine, ~5 мс на рішення**

Вчора була Laya — відкрита модель швидких типізованих рішень. Сьогодні на HN виклали порт під Core ML: ті самі рішення, але на ANE, без Python в інференсі і повністю офлайн.

Заявлені цифри з README:
• 4.98 мс P50 / 5.31 мс P95 на одне мультимовне рішення (M3 Max, ANE FP16)
• 49.1–50.0 рішень/с у живому циклі демо
• у 2.78 раза краща енергоефективність на рішення проти скомпільованого MLX FP16

Вимоги: Apple Silicon, macOS 15+, Python 3.11–3.13. Ліцензія Apache-2.0.

Запуск демо — зі [гіста](https://gist.github.com/fordnox/e592d0f68b543fd044be8e6d040863a0), де автор ганяв це на M4:

```bash
mkdir test-laya && cd test-laya
uv init
uv add 'laya-coreml[demo]'
hf download aac6fef/laya-multilingual-coreml-ane --local-dir models/snake
uv run laya-coreml-snake --model models/snake
```

Сам не тестив: цифри з README репозиторію, команди з гіста, де є скрін і відео запуску.

Якщо в тебе є локальний воркфлоу, де LLM крутиться заради вибору з трьох варіантів — ось чим це міняється.

## 📌 Рухи й безпека

**GitHub [переписали рантайм Copilot з TypeScript на Rust агентами](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/) — 128 PR, 14.5 тижня і один розробник**

Цифри з їхнього ж блогу:
• ~430 000 рядків TypeScript → 832 378 рядків продакшн-Rust
• плюс 468 689 рядків юніт-тестів
• 128 змержених PR і 135 релізів за 14.5 тижня (12 травня — 21 серпня)
• 96.22% попадань у prompt cache

Гнали через GitHub Copilot app і Copilot CLI, моделі ротували: Claude Opus, GPT-5.6 Sol і Claude Sonnet у сесіях, Opus 4.8 / Haiku 4.5 / GPT-5.5 у субагентах. Розробник задавав архітектуру, конвенції і підхід, коду руками не писав.

The Register рахує токени приблизно в \$120 000 плюс три тижні часу розробника і згадує 15.9-кратний приріст пропускної здатності.

Найцікавіше тут не Rust, а що міграцію вели інкрементально: 1.3 релізи на день, кожен PR окремо. Це ближче до відповіді на «як підступитись до легасі», ніж будь-який тред про вайб-кодинг.
