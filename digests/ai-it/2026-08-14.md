## 🚀 Моделі

**Z.ai [зарелізили GLM-5.3](https://z.ai/blog/glm-5.3) — той самий базовий претрейн, що в 5.2, і +20 пунктів на DeepSWE**

Нової архітектури тут немає взагалі: та сама база, ще місяць RL на довгих інженерних задачах. Цифри від вендора:
• DeepSWE v1.1 — 46.2 → 66.9
• Terminal-Bench 3.0 — 4.6 → 28.3
• CyberGym — 77.2% → 84.5%
• ExploitBench — 24.4% → 54.4%

У [доках](https://docs.z.ai/guides/llm/glm-5.3) контекст 1M і вихід до 128K. Thinking вимкнути не можна, є три рівні зусиль: low / high / max.

Головний нюанс — ваги. GLM-5.2 у червні виклали під MIT майже одразу, а тут обіцяють «приблизно за два тижні», після safety-хардненгу. Ціни за токен теж ще немає: модель поки тільки в [GLM Coding Plan](https://docs.z.ai/devpack/overview) від \$18/міс, працює через Claude Code, Cline і OpenCode. Запити до GLM-5.2 і 5.1 тепер автоматично роутяться на 5.3. В OpenRouter її ще немає — перевірив, у списку моделей порожньо.

На HN 900+ балів, і найгучніша гілка не про бенчмарки, а про те, що західні моделі відмовляються від security-роботи, тож люди йдуть на GLM і Kimi. Якщо це твій кейс — чекай ваг, авторутинг на 5.3 у Coding Plan уже працює.

## 🛠️ Інструменти

**Claude Code [2.1.232](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) — форк субагентів увімкнено за замовчуванням, з успадкуванням розмови і prompt cache**

Раніше субагент стартував з чистого контексту і мусив перечитувати те, що головна сесія вже знала. Тепер форк успадковує і розмову, і кеш промпту — тобто дешевше і без повторного Read.

Ще з помітного:
• `@`-згадка дає пряме повідомлення між сесіями через `SendMessage`; імена сесій унікальні в межах машини, дублікати отримують варіант `name-word-word`
• налаштування перейменували: `additionalMarketplaces` / `allowedMarketplaces` замість `extraKnownMarketplaces` / `strictKnownMarketplaces`
• `/code-review` на високих рівнях зусиль тепер виконується фоновим агентом
• закрили обхід дозволів у PowerShell і у Git Bash під Windows через симлінки; вкладені репозиторії більше не успадковують довіру — кожен підтверджуєш окремо

Неінтерактивні агенти в інтерактивних сесіях відтепер ідуть у background mode. Тобто дефолтна поведінка змінилась одразу для всіх, хто ганяє субагентів — і якщо ти рахував токени на попередній логіці, цифри поїдуть униз.

## 💡 Рецепти

**Anthropic [розписали, як не палити токени в Claude Code](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions) — і головне там про prompt cache**

Кеш живе, поки початок запиту збігається байт у байт. Ламають його: зміна `/model` (у кожної моделі свій кеш), зміна `/effort` (він частина ключа), fast mode, і час — година на підписці, п'ять хвилин на API-ключі. Звідси головне правило: модель і effort вибирай на старті сесії, а не посеред.

Далі — конкретика, яку можна вставити прямо зараз.

Вимкнути thinking на одну сесію, якщо попереду тупа механічна робота:

```bash
MAX_THINKING_TOKENS=0 claude
```

Повернути автокомпакт на 1M-моделях (потрібен Claude Code v2.1.221+):

```
/autocompact 200k
```

Замість `/compact` після кількох невдалих ходів — `/rewind` до місця перед ними: він відрізає тільки хвіст, усе до нього лишається в кеші й коштує нуль. `/compact` переписує всю розмову, тому платиш завжди.

Ще з посту: `BASH_MAX_OUTPUT_LENGTH` керує порогом, після якого вивід команди (за замовчуванням 30 000 символів) їде у файл замість розмови; @-згадка файлу вставляє його без окремого Read; а шумну задачу, яку віддаєш раз за разом, варто оформити окремим субагентом з `model: haiku`.

Офіційний пост Anthropic від сьогодні, всі команди — звідти.

![Maximizing the value of your Claude Code sessions](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a7f1f51730ca89a4d571062_og_maximizing-the-value-of-your-claude-code-sessions.jpg)

Найкорисніше тут — не список команд, а те, що `/model` і `/effort` названі прямо частиною ключа кешу. Звичка «перемкнути модель посеред задачі» коштує грошей, і мало хто про це думає.

**[Graft](https://github.com/NanoNets/Graft) будує граф кодової бази один раз — і Claude Code перестає щоразу перечитувати репо**

Ідея проста: агент не досліджує проєкт заново кожну сесію, а отримує готовий семантичний граф у вигляді теки звʼязаних markdown-файлів.

Установка — дві команди:

```bash
npm install -g @nanonets/graft
graft init
```

`graft init` питає, які агенти підключити, будує теку `graft/` і кладе хуки та statusline у `.claude/`. Подивитись, що саме буде змінено, до запису:

```bash
graft init --dry-run
```

Тільки Claude Code, без питань:

```bash
graft init --agents claude
```

Сама тека `graft/` іде в `.gitignore` — це локальний кеш, як `node_modules`. Комітиш лише обвʼязку в `.claude/`, а колега генерує свій граф через `graft build`.

У README на 162 прогонах заявляють −42% токенів, −46% викликів тулів і −60% часу, а на SWE-bench Verified 66% проти 54% у холодного Claude Code. Цифри вендорські — це сьогоднішній Show HN, ліцензія MIT, телеметрії немає; сам не ганяв, усі команди з README.

Якщо в тебе великий монорепо і кожна сесія починається з десяти grep-ів — це рівно та проблема. На маленькому проєкті сенсу мало.
