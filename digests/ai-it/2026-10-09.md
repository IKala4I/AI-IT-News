## 🛠️ Інструменти

**[Python 3.15.0 вийшов](https://www.python.org/downloads/release/python-3150/) — з явними лінивими імпортами, UTF-8 за замовчуванням і вбудованим `frozendict`**

Що з інтерпретатора цікавить найбільше:
• PEP 810 — explicit lazy imports, щоб швидше стартувати
• PEP 686 — UTF-8 тепер дефолтне кодування
• PEP 814 — `frozendict` як вбудований тип, PEP 661 — тип `sentinel`
• PEP 798 — розпакування всередині comprehension-ів

У стандартній бібліотеці з'явився Tachyon — семплінговий профайлер високої частоти, і окремий пакет для профайлінг-тулів (PEP 799).

Експериментальний JIT підтягнули: за замірами зі сторінки релізу, ~7-8% прискорення на x86-64 Linux проти звичайного інтерпретатора і 11-12% проти tail-calling на AArch64 macOS. macOS-бінарники тепер ставлять free-threading за замовчуванням.

Застереження звідти ж: на macOS 27.0 IDLE та інші tkinter-застосунки можуть вішатись на діалогах.

Ліниві імпорти — головне, якщо пишеш CLI на Python: старт скрипта зазвичай з'їдають саме імпорти.

**Claude Code [у 2.1.295](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) вчить хуки блокувати дію, коли вони самі впали, і показує стан сесії в табі термінала**

143 рядки в одному релізі. Що вибрав:
• `onFailure: "block"` для command- і HTTP-хуків: хук, який не стартував, вийшов за таймаут або віддав неочікуваний код, тепер блокує дію
• Program Status Protocol (OSC 7501) — термінали, які його вміють, показують, чи Claude працює, чи чекає на тебе, чи закінчив
• `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` обмежує, скільки unattended retry mode пересиджує 429 і 529
• описи MCP-тулів, що вантажаться через tool search, ріжуться на 16 384 символах замість 2 048
• полагодили файл, що вважався прочитаним після `cat`, який нічого не вивів, і Edit, що вважав файл прочитаним, коли вміст змінився без зміни mtime

Два останні фікси — найцінніше для auto mode: там агент дивиться файли через Bash, а не через Read.

**Microsoft [виклали MXC](https://github.com/microsoft/mxc) — пісочницю під SDK, в якій можна запускати код від моделі, плагіни й тули**

Не окремий бінарник, а залежність, яку вбудовуєш у свій застосунок: описуєш тип контейнера, правила і команду, а MXC валідує запит, вибирає бекенд і запускає. Політики — на файлову систему (read-only, read-write, denied), мережу і UI (кліпборд, дисплей, GUI). Бекенди за замовчуванням: `seatbelt` на macOS, `bubblewrap` на Linux, `processcontainer` на Windows 11.

Пакети вже в трьох реєстрах — `mxc-sdk` на crates.io, `Microsoft.Mxc.Sdk` у NuGet, `@microsoft/mxc-sdk` у npm:

```ts
import { spawn, type ContainerRequest } from '@microsoft/mxc-sdk/v1';
const child = await spawn(request);
```

З README варто запам'ятати одне: `--audit` повністю вимикає захист пісочниці для аналізованого ворклоуду, тож на недовіреному коді його не вмикають.

Це той самий MXC, на якому вчора в GA вийшло local sandboxing для Copilot: у ченджлогу GitHub прямо сказано «Local sandboxing is powered by Microsoft eXecution Container (MXC)». Якщо пишеш агента з shell-доступом — ізоляцію можна взяти готову, під MIT.

## 💡 Рецепти

**Рецепт: повісити [таймер prompt-кеша](https://www.aitmpl.com/component/mods/observability/prompt-cache-control) над промптом Claude Code**

Моди — плагіни з хуками на JS/TS, які міняють сам Claude Code — [тепер увімкнені за замовчуванням](https://code.claude.com/docs/en/plugins/mods/overview): 2.1.287+ у терміналі, 2.1.286+ у десктопі. Дослівно з доків: «If you set `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` during early access, remove it» — нові версії цю змінну просто ігнорують.

Корисний сторонній мод — `prompt-cache-control`. Він малює смугу над промптом: відсоток попадання в кеш за останній запит, скільки токенів прочитано/записано/нових, зворотний відлік до згасання і підказку (їхати далі, `/compact` чи `/clear`). Плюс панель `/cache` з таблицею по турнах.

```
npx claude-code-templates@latest --mod observability/prompt-cache-control
claude
```

Подивитись, у які події він вліз і які виклики робить, ще до запуску:

```
claude plugin validate .claude/skills/prompt-cache-control
```

Опції (`ttl`, `warnSeconds`, `compactAtTokens`, `band`, `status`, `toast`) читаються тільки з user- або managed-налаштувань — project-настройки мод не бачить.

Те, що моди вийшли з early access — з офіційних доків. Сам мод сторонній, я його не тестував: команди й опції взяті зі сторінки мода в каталозі, залінкованої вище.

Сенс простий: на підписці кеш живе годину, на API-ключі чи кредитах — п'ять хвилин. Коли він згас, увесь накопичений контекст обробляється заново, і в довгих сесіях з перервами це помітно. Таймер прямо каже, коли дешевше дотиснути задачу зараз, а коли починати нову сесію.

## 📌 Рухи й безпека

**[Deno йде в Cloudflare](https://deno.com/blog/cloudflare) — рантайм підтримають ще рік, Deno Deploy вимкнуть через пів року, JSR лишається**

Ryan Dahl пише прямо: вся команда переходить у Cloudflare, і подальшу розробку вкладають у спільну платформу з Workers і Durable Objects, а не в окремий рантайм і хостинг. Конкретика з посту:
• рантайм — ще рік щомісячних релізів з багфіксами і безпекою, далі Deno Land припиняє розробку; код лишається опенсорсним, і вони кличуть охочих продовжити
• Deno Deploy працює ще пів року, потім вимикається; платним клієнтам обіцяють допомогу з міграцією на Cloudflare Workers
• JSR продовжує працювати, інфраструктуру переносять у Cloudflare
• rusty_v8 підтримують і далі, з планом вбудувати його у workerd

Мотив у пості — агенти: Durable Objects дають дешеве serverless-виконання, персистентний стан і WebSockets в одному місці, і саме туди цілить новий проєкт celld.

Якщо щось крутиться на Deno Deploy — пів року на переїзд, і це вже не «колись». Якщо тільки рантайм чи JSR — поки без змін.
