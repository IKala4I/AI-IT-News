Для Free і Go: дефолтною стає Luna, а ліміт на текстові чати знімають зовсім (з поправкою на антиабуз). Картинки, файли й голос ліміти зберігають. Зʼявилась кнопка Think для складніших питань.

За внутрішніми замірами на фінансових, медичних і юридичних промптах відповіді з хоча б однією фактичною помилкою трапляються на 62% рідше в Luna і на 68% рідше в Sol, ніж у GPT-5.5 Instant.

Зміни тільки в чаті ChatGPT — Work, Codex і API не зачепило.

Слайдер зусиль — те, чого бракувало: більше не треба вгадувати, який режим клікнути під конкретне питання.

## 🛠️ Інструменти

**Claude Code [доїхав до 2.1.224](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) — плагіни з zip по хешу, `/teleport` і зняте обмеження на 200 субагентів**

Що приїхало в 2.1.224:
• новий тип джерела плагінів — `archive`: HTTPS-zip з опційною перевіркою SHA-256 (рецепт нижче)
• ліміт у 200 спавнів субагентів прибрали — довгі сесії більше не впираються в стелю
• маскування кредів у сендбоксі стало розумнішим: JWT-aware маскування і переписування підпису AWS SigV4
• звіт про порушення сендбоксу тепер показує конкретний заборонений файл чи хост, а не просто «denied»
• залатали обхід deny-правил файлової системи на Linux і macOS

У 2.1.223 до цього додали `/teleport` (він же `/tp`) — витягнути хмарну сесію в поточний CLI, не перезапускаючи Claude Code. Плюс закрили обхід перевірки дозволів у Bash через приховування команд і невидимі Unicode-символи в промпті дозволу.

Обидва релізи — здебільшого про діри в пісочниці. Якщо ганяєш агентів без нагляду, це апдейт на сьогодні.

**Cloudflare [відкрили бету Kitesurf](https://blog.cloudflare.com/kitesurf/) — браузер, написаний під агентів, який крутиться на Workers у WebAssembly**

Ідея: Chromium для агентських задач надто важкий, тож його переписали під ізоляти. Цифри від Cloudflare — у 3-7 разів менше CPU і памʼяті, але в 1.7-1.8 раза повільніше по wall-clock на рендері.

Ламати нічого не треба: Kitesurf говорить по Chrome DevTools Protocol, тож Puppeteer і Playwright підхоплюють його через параметр `browser=kitesurf` на ендпоінтах Browser Run. Той самий параметр працює і на скріншотному ендпоінті Quick Actions.

Є [публічний плейграунд](https://kitesurf.cloudflare.app/): вбиваєш URL, дивишся рендер, PNG, PDF чи HTML, поруч — DevTools із панеллю памʼяті по ізоляту. Ліміт на навігацію — 20 секунд CPU і 60 секунд загального часу.

Бета безкоштовна з лімітами на акаунт. Опенсорсу поки немає, обіцяють «щойно будемо готові».

![Kitesurf](https://blog.cloudflare.com/_emdash/api/media/file/01KZBWYMKT77FDVB07PHA3R5WM.png)

Найцікавіше — агента можна посадити на Kitesurf через `chrome-devtools-mcp` і не тягати локальний Chrome взагалі.

## 💡 Рецепти

**Став плагіни в Claude Code із zip і [пінь їх по SHA-256](https://code.claude.com/docs/en/plugin-marketplaces) — новий тип джерела `archive`**

Раніше маркетплейс міг вказувати тільки на git-репозиторій, тобто на рухому ціль. Тепер у `marketplace.json` можна покласти конкретний архів:

```json
{
  "name": "my-plugin",
  "source": {
    "source": "archive",
    "url": "https://artifacts.example.com/claude-plugins/my-plugin-2.1.0.zip",
    "sha256": "6bfa50e3d2e00c052b46abe51fff89346ac803e45771f76dcf6df1ab74cca5e1"
  }
}
```

Якщо завантажений файл не збігається з піном, Claude Code відмовляє в установці й кидає `Plugin archive integrity check failed`.

Що варто знати:
• тільки HTTPS — `http://`, loopback, link-local і хости хмарних метаданих відхиляються, і кожен редірект перевіряється так само
• архів більший за 256 MiB не поставиться
• `.claude-plugin/` має лежати або в корені zip, або в єдиній теці першого рівня — глибше Claude Code не шукає
• без поля `version` роль версії грає сам `sha256`; якщо `version` є — після зміни архіву бампай і його, інакше юзери сидітимуть на кеші

Офіційна фіча, є в документації; приїхала в 2.1.224.

Після історій із Shai-Hulud це не про зручність, а про те, щоб оновлення плагіна не приїхало непоміченим.

## 📌 Рухи й безпека

**Datasette [закрив SQL-ін'єкцію](https://github.com/simonw/datasette/releases/tag/0.65.3) у 0.65.3 і 1.0a38 — зачіпає інстанси з публічними й приватними таблицями в одній базі**

Суть діри: юзер з доступом до будь-якої публічної таблиці міг через raw SQL дочитатися до приватних таблиць тієї ж бази, обійшовши систему дозволів.

Simon Willison окремо радить не зупинятись на апдейті: якщо тримаєш приватні таблиці поруч із публічними, вимикай дозвіл `execute-sql` на цій базі — навіть із фіксом.

Вузька історія, але якщо в тебе десь висить Datasette як внутрішній вʼювер даних, це п'ятихвилинна перевірка.
