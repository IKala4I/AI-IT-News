**Коли знадобиться:** додаєш банер, interstitial чи rewarded-рекламу або переїжджаєш на новий Google Mobile Ads Next-Gen SDK і не хочеш вручну копіювати ID з дашборда.

**Як виглядає:** [за документацією](https://developers.google.com/admob/android/next-gen/agent-skills) одна команда ставить шість скілів, від get-started до validate:

```
npx skills add google/skills/skills/ads
```

**+** офіційні плейбуки від Google, які працюють в усіх твоїх агентах

**−** документація тільки для Android, про iOS і React Native там ні слова. MCP-сервер, через який агент сам створюватиме ad units, поки в ранньому тесті, ширший доступ обіцяють на початку 2027-го

Якщо монетизуєш нативний Android через AdMob, тепер міграцію на нове SDK можна просто віддати агенту. Для крос-платформних проєктів поки чекаємо.

## 📌 Важливо знати

**Фейковий рекрутер [надсилає розробникам «тестове завдання»](https://getjump.me/posts/03-huntrole-fake-take-home/): це розширення `huntrole.assessment-tool` з офіційного VS Code Marketplace, яке краде ключі й вбудовується в Cursor та Antigravity**

Розширення показує безневинний код, а виконує інший. Воно забирає змінні оточення, токени GitHub і паролі з браузера, а потім ставить бекдор у npm і в файли VS Code, Cursor та Antigravity. Видалення розширення бекдор не прибирає. 16 листопада в нього було 126 установок, і воно досі в Marketplace.

Перевір себе командами з посту:

```
code --list-extensions | grep -i huntrole
ls -la ~/.node_modules/ 2>/dev/null | grep -i npm-ws
find ~ /Applications \( -name "*.inz.cjs" -o -name "*.inz.orig" -o -name "*.inz.tmp" \) 2>/dev/null
```

Якщо щось знайшлось, з іншого пристрою зміни всі ключі й паролі, а машину перевстанови. І ніколи не став розширення чи пакети з «тестових завдань».

## ✨ Цікавинка

**OpenAI [розповіла](https://openai.com/index/step-toward-defining-the-standard-model), як GPT-6 Astra провела доведення для кандидата на строге визначення Стандартної моделі (теорії, якою фізики описують усі відомі частинки) на ґратці, тобто на сітці точок замість неперервного простору.** Десятиліттями це не вдавалось, бо слабка взаємодія по-різному «бачить» ліві й праві частинки, а на сітці цю асиметрію важко зберегти. Фізик Nathaniel Craig з UC Santa Barbara, який зараз запрошений науковець в OpenAI, запропонував стратегію, а модель перетворила її на конкретну конструкцію і повне доведення. До [статті на arXiv](https://arxiv.org/abs/2610.09093) додано формалізацію в Lean (мові, де кожен крок перевіряє комп'ютер), а сам Craig чесно називає результат «відповіддю в принципі, а не на практиці»: частина ключових перевірок ще попереду.
