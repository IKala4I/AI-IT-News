## 🚀 Моделі

**OpenAI [зарелізили GPT-6 Astra](https://openai.com/index/gpt-6-astra/) — \$10/\$50 за Mtok і 1M контексту**

Ціни один в один як у Claude Fable 5.1. За [прайсом OpenAI](https://developers.openai.com/api/docs/pricing): \$10 за Mtok входу, \$50 за вихід, кеш \$1, batch — половина тарифу, Fast mode — подвійний. Це рівно 2.5× від GPT-5.6 Sol.

Параметри: `gpt-6-astra`, контекст 1 050 000 токенів, до 128K на вихід, cutoff — 30 квітня 2026.

Головна цифра анонсу — 99.9% на ARC-AGI 3, але [Simon Willison нагадує](https://simonwillison.net/2026/Sep/3/gpt6-astra/): це на власному «Provider Adapter harness» OpenAI, на дефолтному вийшло 62.7%. На Artificial Analysis Intelligence Index Fable 5.1 поки попереду — 66 проти 61.

Розкатують хвилями: спершу trusted-access організації, далі ChatGPT Plus/Pro/Business/Enterprise, broader API access — «coming soon».

За такий прайс це не модель «увімкнув і забув». Поки що для більшості це анонс, а не інструмент — доступу в API немає.

**IFM [виклали K2 Horizon](https://ifm.ai/blog/k2/) — шість відкритих моделей від 0.9B до 375B під Apache 2.0**

Флот: 375B-A23B, 36B-A4B, 32B, 7B, 3.7B, 0.9B. Спільна архітектура, словник і тулінг, тож перемикання між розмірами — це зміна назви моделі, а не переписування пайплайну.

Цікаві не бенчмарки, а обсяг відкритого: ваги, проміжні чекпоінти, тренувальний код, конфіги, логи і дані (або рецепт їх складання) — включно з agentic post-training. Автори кажуть, що це перший відкритий флот, де видно повний процес, а не тільки фінальний чекпоінт.

GGUF і FP8 збірки вже на Hugging Face: `IFM/K2-Horizon-7B-GGUF`, `IFM/K2-Horizon-32B-GGUF`, `IFM/K2-Horizon-MoVA-36B-A4B-GGUF` і решта.

0.9B цілять у годинники й окуляри, 3.7B і 7B — у телефони, 32B і 36B-A4B — у локальну машину.

GGUF у день релізу — рідкість. 7B чи 32B можна затягнути в llama.cpp сьогодні ввечері й подивитись самому.

## 🛠️ Інструменти

**Claude Code [оновився до 2.1.260](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) — `/diff` збоку і чесна причина промахів кешу**

Нове:
• `/diff` — панель поруч із діалогом у fullscreen, показує незакомічені зміни прямо поки Claude редагує
• `/cost` і поле `prompt_cache` у статуслайні тепер називають ймовірну причину промаху кешу: змінились визначення тулів, змінився system prompt, простій довший за TTL
• `ctrl+l` / `cmd+k` у fullscreen чистить транскрипт як `clear` у терміналі

Головний фікс — безпековий: правила `Edit`/`Write`/`Read`, у шляху яких є дужки, мовчки відкидались як невалідні, і «read-only» папка насправді лишалась записуваною. Там же прикрили автоапрув zsh-команд, що ховали підстановку в присвоєнні `REPORTTIME`, `REPORTMEMORY` чи `DIRSTACKSIZE`.

Ще відкотили вчорашню зміну з 2.1.259, через яку `Read()` deny-правила застосовувались до аргументів Bash — і `npm run build` падав під правилом `Read(./**/build/**)`.

Якщо тримаєш deny-правила на шляхи з дужками — оновлюйся не відкладаючи.

**GitHub [відкрили Project HydraFusion](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/) — Copilot CLI сам вирішує, скільки моделей кинути на задачу**

Три патерни, які харнес обирає в рантаймі:
• Single — одна модель робить задачу
• Cascade — дешевша пише чернетку, і якщо не тягне, ескалює на сильнішу
• Critique — одна пише, рев'ювер з іншої родини моделей критикує, перша переписує

Вмикається в Copilot CLI трьома командами, далі в списку вибираєш `HydraFusion (Research Preview)`:

```
/update
/experimental on
/model
```

Цифри з анонсу: TerminalBench 2.1 — на 67% дешевше і +4.9 бала якості, DeepSWE — на 36% дешевше при −1.5, CheckpointBench — на 65% дешевше при −0.1. Платиш за токени кожної моделі за її звичайним тарифом.

Обмеження написане чесно: заточено під перший хід і одну задачу за промпт, довгі ітеративні сесії — наступний етап.

Research preview на всіх планах Copilot. Те, що всі роблять руками — «спитай дешеву, перевір дорогою» — тут просто вшите в харнес.

## 💡 Рецепти

**Рецепт: [спільна памʼять для Claude Code і Codex](https://huggingface.co/blog/funes) — локальна, у вигляді датасету**

Hugging Face виклали Funes — окремий бінарник (не MCP-сервер), який індексує трейси сесій агента і віддає їм тул `recall`. Тобто агент дістає рішення й міркування з минулих сесій, а не тільки з поточного контексту.

Встановлення і підключення:

```bash
curl -fsSL https://huggingface.co/buckets/huggingface/funes/resolve/install.sh | sh
funes add claude
```

Замість `claude` можна `codex`, `pi` або `hermes`. Щоб підчепити спільну памʼять із HF-датасету:

```bash
funes add codex acme/funes-memory
```

Є ще `funes ask` — питати памʼять напряму, без агента.

Ембединги й реранкінг крутяться локально, памʼять лежить як Lance-датасет на диску і стає HF-датасетом тільки якщо ти сам її розшарив. Жодних зовнішніх API для індексації.

Найцікавіше — крос-агентність: індекс один, тож перескочив з Claude Code на Codex і контекст поїхав із тобою.

Команди дослівно з анонсу HF; сам не ставив. Це `curl | sh` — перед запуском варто відкрити URL і почитати скрипт.
