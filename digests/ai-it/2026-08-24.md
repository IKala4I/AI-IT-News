**Claude Code [відкрив `/design`](https://code.claude.com/docs/en/whats-new/2026-w34) як research preview — Claude малює редаговані артборди прямо з CLI**

Даєш бриф — Claude публікує канвас із кількома варіантами UI як артефакт і друкує лінк. Відкриваєш, крутиш елементи руками, обираєш один і кажеш імплементити.

```
> /design redesign the composer based on what people actually use it for
```

Працює в CLI і в Claude Code Desktop, потрібна версія 2.1.233+, доступно на Pro, Max, Team і Enterprise.

**OpenCode [довів субагентів до пуття](https://github.com/sst/opencode/releases/tag/v1.18.20) — впалий тул субагента більше не повертає порожнечу, а віддає `task_id`, з якого можна продовжити**

Що приїхало за три релізи:
• впалі виклики тулів у субагента піднімаються з резюмованим `task_id` замість пустого результату
• на запити дозволів від субагентів тепер можна відповідати прямо в `opencode run`
• ретраї на відповідях із `finish_reason: network_error` та варіаціях написання
• для Cerebras зберігається `max_completion_tokens` без зайвих обрізань
• у [1.18.22](https://github.com/sst/opencode/releases/tag/v1.18.22) від 24 серпня прибрали `textVerbosity`, що летів у OpenAI-сумісних провайдерів, які його не підтримують

Головне тут — перше: коли ганяєш кілька субагентів паралельно, мовчазний фейл одного з них раніше означав перезапуск усього ланцюжка.

**Codex CLI [0.149.1](https://github.com/openai/codex/releases/tag/rust-v0.149.1) — картинки більше не з'їдають контекст під час remote compaction**

Реліз від 24 серпня, чотири коміти, змістовний один: під час віддаленої компакції з'явився бюджет на збережені картинки, щоб історія зі скріншотами не тягнула за собою більше контексту, ніж задумано.

Решта — службове: викликам `exec` дали глобальну опцію класифікувати нові й форкнуті треди, а відчеплені запити до памʼяті тепер помічаються як `memory_consolidation`.

Дрібниця, але відчутна для тих, хто годує агента скріншотами UI — саме такі сесії найшвидше впиралися в стелю контексту.

## 💡 Рецепти

**Рецепт: підняти `claude remote-control` як сервер і стартувати сесії з телефона — кожну у власному git worktree**

```bash
cd ~/projects/my-app
claude remote-control --spawn worktree
```

Процес лишається в терміналі в серверному режимі, друкує URL сесії, а пробіл показує QR. З `--spawn worktree` кожна створена на вимогу сесія отримує окремий git worktree, тож дві паралельні задачі не б'ються за ті самі файли (потрібен git-репозиторій). Перемикати `same-dir` / `worktree` можна на льоту клавішею `w`, а свою назву задати через `--name "My Project"`.

Друга половина рецепта — свіжа: будь-яка машина, на якій крутиться `claude remote-control`, тепер показується карткою пристрою вгорі вкладки Code у застосунку Claude. Тапаєш, обираєш директорію — і сесія стартує на твоєму залізі. Сам Remote Control при цьому вийшов із research preview.

Обмеження, які варто знати заздалегідь: тільки Pro, Max, Team і Enterprise, API-ключі не підходять, і не працює на Bedrock, Vertex, Foundry чи з кастомним `ANTHROPIC_BASE_URL`.

Офіційна фіча, усі команди — з [документації Claude Code](https://code.claude.com/docs/en/remote-control). Сам не тестив.
