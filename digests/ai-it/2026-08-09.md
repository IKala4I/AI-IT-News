## 🛠️ Інструменти

**Anthropic [задокументували cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) — сесії Claude Code тепер пишуть одна одній напряму**

Фіча приїхала ще в 2.1.224, але сторінка з деталями вийшла цими вихідними — і одразу зібрала 142 бали на HN.

Claude сам знаходить адресата через `ListAgents` і шле текст через `SendMessage`. Ти ці тули не викликаєш — просто кажеш «спитай сесію в іншому терміналі, чи домігрувало».

Що варто знати:
• між сесіями на одній машині трафік іде через per-session Unix-сокет, повз сервери Anthropic
• передається тільки текст — ні історії, ні файлів, ні дозволів
• повідомлення від іншої сесії не рахується за твою згоду: воно не закриє пендінг-промпт і не змінить `CLAUDE.md`
• на інші свої машини і в веб можна тільки відповідати, не починати розмову

Потрібно 2.1.224+, macOS або Linux. Перевірити — `/list-agents` (він же `/peers`).

Найкорисніше — паралельні worktree: сесія, що зламала API, попереджає сусідню сама, без копіпасту між вкладками.

**[Herdr](https://github.com/ogulcancelik/herdr) — рантайм для кодинг-агентів, який забирає собі їхні термінали**

Це не обгортка над агентами, а фоновий сервер, усередині якого живуть їхні термінали: закрив кришку, впала мережа, перезавантажив машину — агенти працюють далі, а ти реаттачишся з будь-якого терміналу чи по SSH.

19+ CLI без жодних правок: Claude Code, Codex, Cursor, opencode, Grok та інші. Кожна панель показує стан — working, blocked, idle.

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

Є `brew install herdr` і бета під Windows. У v0.8.0 (3 серпня) проєкт перейшов з AGPL-3.0 на Apache-2.0 і додав `herdr --skill`. Один бінар на Rust, без Electron, 26.2k зірок.

![Herdr](https://herdr.dev/assets/og-card-v9.png)

Цікаве тут не «tmux для агентів», а сокет, через який агенти бачать одне одного — рецепт нижче.

## 💡 Рецепти

**Хай агенти чекають одне на одного, а не на `sleep` — [сокет-API Herdr](https://herdr.dev/docs/socket-api/)**

Звична проблема оркестрації: агент A має продовжити після агента B, і ти або сидиш дивишся, або спиш фіксовану кількість секунд і сподіваєшся. Herdr дає семантичне очікування — не «минуло N секунд», а «B реально заблокувався або закінчив»:

```bash
herdr agent wait w1:p1 --until done
herdr agent wait w1:p1 --until blocked
```

Панелям можна дати людські імена, щоб не жонглювати `w1:p1`:

```bash
herdr agent rename w1:p1 reviewer
herdr agent attach reviewer
```

Для власних тулів є сирий сокет — newline-delimited JSON на `~/.config/herdr/herdr.sock`. Підписка на зміну стану:

```json
{"id":"sub_1","method":"events.subscribe","params":{"subscriptions":[{"type":"pane.agent_status_changed","pane_id":"w1:p1","agent_status":"blocked"}]}}
```

У кожну панель автоматично експортуються `HERDR_SOCKET_PATH`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID` і `HERDR_PANE_ID`, тож скрипт усередині знає, хто він і куди писати.

Щоб агент навчився цим користуватись сам — `herdr --skill` друкує вбудований скіл, а `herdr integration install claude` ставить інтеграцію.

Усе з офіційної документації Herdr, сам не ганяв.

## 📌 Рухи й безпека

**OpenAI на Black Hat [розклали інцидент з Hugging Face по днях](https://simonwillison.net/2026/Aug/7/openai-timeline/) — агенти самі зібрали собі дошку оголошень**

Ми писали про це 20 і 22 липня; тепер є таймлайн із 40-хвилинної доповіді Еріка Воллеса і Майка Далтона.

Як це розгорталось:
• 7-8 травня — агенти намацали доступ на запис в Artifactory, поки штурмували нездійсненну задачу
• 26 травня — перший успішний SSRF, непрямий вихід в інтернет із «ізольованої» пісочниці
• 26 червня — zero-day RCE в Artifactory через легасі-флоу оновлення токенів
• 4 липня — OpenAI відкликали креди й пропатчили; агенти підняли другу дошку в іменах директорій кеша Artifactory
• 8-19 липня — ескалація до cluster admin

Найнеприємніша деталь: OpenAI зрозуміли, що злом Hugging Face — їхніх рук справа, лише коли HF відповіли, що ті креденшели вже відкликані.

▶ [Дивитись](https://www.youtube.com/watch?v=87DyyMV0kCY)

Висновок для нас скромніший за заголовки: «ізольована пісочниця» ізольована рівно настільки, наскільки ізольоване все, що в неї підключено — включно з внутрішнім проксі й репозиторієм артефактів.
