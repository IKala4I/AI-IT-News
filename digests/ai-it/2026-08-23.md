## 🚀 Моделі

**Хтось нарешті [поміряв, чому локальна модель тупить](https://forum.level1techs.com/t/why-your-local-llm-feels-dumber-than-it-is/253917) — і винна не модель, а те, як ти її запускаєш**

Автор під ніком thr3e ганяв Qwen3.6-27B на RTX PRO 6000 через vLLM (CUDA graphs, prefix caching і MTP вимкнені) і дивився, де саме розходиться вибір токенів.

Три заміри:
• attention-бекенди — FlashAttention 2, Flash Inference і Triton дають різні токени, і розбіжність кластерами вилазить після ~40k контексту
• KV-кеш — на BF16 усе чисто, int8 після помилки виправляється, а int4 ламає tool calls намертво і відтворювано: модель не закриває function envelope
• ваги — INT8 W8A16 обійшов і офіційний FP8, і NVFP4 від NVIDIA; у NVFP4 близько 50% перевернутих токенів уже на 88k і зірваний tool calling

У коментах на HN (417 балів) головна порада простіша: не квантизуй KV-кеш заради економії і не вір дефолтам — Ollama досі стартує з 4K контексту, поки ти думаєш, що в тебе 128K.

Якщо ганяєш локальну модель під агентні задачі і вона «якась дурна» — це найдешевша гіпотеза для перевірки: спочатку підніми точність кешу, потім уже міняй модель.

## 🛠️ Інструменти

**Claude Code показував «effort 10» на high — [Anthropic каже, що це тест шкали](https://news.ycombinator.com/item?id=49404033), а не зріз якості**

Учора користувачі помітили, що поруч із сесією числове значення effort впало до 10 — рівно те число, яким раніше позначався low. Тред на HN зібрав 196 балів і 171 коментар з класичним «модель знову порізали».

Thariq з команди Claude Code відповів прямо в треді:

> We sometimes test API serving configs in Claude Code before rolling them out, and one running now maps the numerical effort value differently. That's why Claude may tell some of you it's at "10" on high. The scale isn't 0-100, the number isn't meaningful on its own, and the effort you selected is the effort you're getting.

Тобто це серверний конфіг-тест, шкала не 0-100, і обраний рівень ти й отримуєш. Якщо бачиш реальну регресію — просять слати `/feedback` з ID сесії, обіцяють кредити.

Практичний висновок нудний, але корисний: число біля effort зараз ні про що не говорить, орієнтуйся на сам вибраний рівень. Заодно нагадування, що серверні A/B тести їдуть на живих платних сесіях без опції відмовитись — саме це в коментах дратувало найбільше.

**Simon Willison [зарелізив LLM 0.33](https://github.com/simonw/llm/releases/tag/0.33) — шаблони тепер можна складати один на одного**

Головне з релізу:
• `-t/--template` можна повторювати, і шаблони застосуються по черзі
• `llm embed` і `llm embed-multi` навчились приймати `--key`, а в Python — `key=` на кожен виклик
• `llm logs` тепер показує вивід серверних тулів окремою секцією Tool results
• для Responses API зʼявилась опція `reasoning_summary` зі значеннями `auto`, `concise` і `detailed`
• переїзд на openai 3.x і httpx2 — те, що позавчора тимчасово залатали в 0.32.1

Складання шаблонів — найкорисніше. Один шаблон тримає налаштування моделі, другий — сам промпт, і вони більше не дублюються:

```bash
llm -m gpt-5.6-luna -o reasoning_effort high --save lhigh
llm "Generate an SVG of a pelican riding a bicycle" --save pelican
llm -t lhigh -t pelican
```

Якщо в тебе назбиралась купа майже однакових шаблонів, які відрізняються лише моделлю чи reasoning-рівнем — оце воно і є.

**Codex CLI [0.149.0](https://github.com/openai/codex/releases/tag/rust-v0.149.0) — інтерактивний дашборд агентів і черга повідомлень у чужу сесію**

Зʼявився `codex agents` — окремий інтерактивний екран, де можна шукати, стартувати, відкривати, перейменовувати і зупиняти таски. Плюс `codex queue`, який шле повідомлення в уже наявну локальну чи віддалену сесію.

У TUI додали керування робочою текою:

```bash
codex agents          # дашборд тасок
codex queue           # кинути меседж у наявну сесію
codex doctor          # тепер діагностує проксі, мережу і стан десктоп-апки
```

Всередині сесії — команди `/cd`, `/pwd` і `/cwd`. Vim-режим підтягнули до `cw`, `c$` і `cc`, а resumed і forked треди тепер відновлюють свій permission profile, а не мовчки падають на дефолтний.

Дашборд закриває головний біль тих, хто тримає кілька агентів паралельно і губиться, який де. Далі вже вийшли альфи 0.150.0, але стабільна — ця.

## 💡 Рецепти

**Рецепт: [harness-subagent](https://github.com/ptmrio/harness-subagent) дає Claude Code віддати задачу Codex або Grok як одноразовому субагенту**

Скіл, що вчить батьківського агента написати бриф, віддати роботу іншому CLI одним шотом і самому звести результат. Підтримує claude, codex, grok, cursor-agent — потрібно, щоб потрібний CLI був у PATH і залогінений.

```bash
npx skills add ptmrio/harness-subagent -g
```

Дефолти можна прописати в `~/.config/harness-subagent/config.toml` (є `assets/config.example.toml`), задавши, кому яку задачу віддавати: спеку, UI-імплементацію, код-рев'ю.

Ідея в README чесна: батько має саме синтезувати знахідки, а не проксіювати вивід субагента — інакше сенс різних моделей губиться. Типовий кейс — адверсаріальне рев'ю плану чужою моделлю.

Сам не тестив, MIT, репозиторій свіжий і на HN майже без уваги — тобто це радше «спробувати на вихідних», ніж перевірений часом інструмент. Але сама схема «одна модель під іншою» коштує пʼять хвилин на перевірку.
