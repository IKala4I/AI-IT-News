## 🚀 Моделі

**Gemini [навчився дивитись відео «агентно»](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-agentic-video-in-gemini/) — мінус 66% вартості й 88% токенів на тому самому аналізі**

Замість того щоб молоти відео з фіксованим FPS, модель тепер сама вирішує, які фрагменти передивитись уважніше, а які проскочити.

Цифри з анонсу:
• до −66% вартості аналізу
• до −88% спожитих токенів
• до +7% точності

Працює на Gemini 3.7 Flash, 3.6 Flash і 3.5 Flash-Lite — і для завантажених файлів, і для YouTube-лінків. Доступно через Gemini API в AI Studio та Gemini Enterprise Agent Platform, за звичайним токенним прайсом, без окремої плати за фічу.

Якщо ти колись рахував, скільки коштує прогнати годинну лекцію через модель, — це та зміна, після якої задача з «дорого» стає «нормально». Найочевидніший юзкейс: пошук конкретного моменту в довгому відео замість ручного скрабінгу.

**Один розробник [натренував трансформер за півтори години](https://mvakde.github.io/blog/44-on-arc-1/) на одній RTX 5090 — і взяв 44% на ARC-AGI-1**

Загальний цінник експерименту — 67 центів разом з інференсом. Модель крихітна: 8 шарів, 3D RoPE, пер-таск ембединги і SwiGLU.

Схема проста: пари вхід-вихід із сітками конвертуються в послідовність токенів, модель тренується авторегресивно. Аугментація — перестановки кольорів і діедральні симетрії, у сабміт ідуть два найчастіші виходи.

За словами автора, це обганяє чимало LLM і йде нарівні з TRM/HRM — при радикально меншому компʼюті. На ARC-2 скромніше: 7%. Код відкритий.

Приємне нагадування, що не кожну задачу треба нести у фронтир-модель. Поріг входу тут — вечір і одна відеокарта, тож це рідкісний випадок, коли ресерч-пост можна не просто прочитати, а відтворити.

## 🛠️ Інструменти

**Hugging Face [виклали 207 WebGPU-кернелів](https://huggingface.co/blog/webgpu-kernels) окремим npm-пакетом — інференс у браузері без Python**

`@huggingface/kernels` тягне оптимізовані кернели прямо з Хабу і ганяє їх на WebGPU. Ліцензія Apache-2.0, самі кернели лежать в організації [webgpu-kernels](https://huggingface.co/webgpu-kernels).

```bash
npm install @huggingface/kernels@preview
```

```javascript
import { getKernel } from "@huggingface/kernels";

const add = await getKernel("webgpu-kernels/ai.onnx.Add", { version: 1 });

const { c } = await add({
  a: { data: new Float32Array([1, 2, 3, 4, 5, 6]), shape: [2, 3] },
  b: { data: new Float32Array([10, 20, 30]), shape: [3] },
});
```

Разом із пакетом заїхав Fleet — краудсорсний бенчмарк, який збирає, як ці кернели поводяться на реальних GPU користувачів.

Поки що preview і рівень абстракції низький: це будівельний матеріал для рантаймів, а не готове «запусти LLM у вкладці». Але якщо ти дивився в бік локального інференсу на клієнті — тепер є на що спертись.

▶ [Дивитись Fleet](https://webgpu-kernels-fleet.hf.space/)

## 💡 Рецепти

**Рецепт: `/boost` в Antigravity — багатоагентний пайплайн під складний баг**

Google [задокументували](https://antigravity.google/docs/boost/) окрему команду для задач, де звичайна однопрохідна відповідь не тягне: рейс-кондішени, глибокий рефакторинг, пошук першопричини по кількох файлах.

Під капотом три фази. Оркестратор розбирає промпт на підзадачі, спеціалізовані субагенти паралельно роблять імплементацію, дослідження і локальну перевірку, далі результат зводиться і валідується тестами.

Викликається командою з описом задачі:

```
/boost Investigate the race condition in the session cache and implement a thread-safe fix with tests.
```

В Antigravity CLI так само — `/boost` у промпт-боксі плюс опис.

Джерело: офіційна документація, сам не тестив. Доступно на платних планах у Antigravity 2.0 і в CLI.

Корисно знати сам патерн, навіть якщо ти не в Antigravity: «розбий на субагентів і зведи через тести» — це рівно те, що зараз руками конфігурять у Claude Code чи Cursor. Тут воно сховане за однією командою.

## 📌 Рухи й безпека

**Нова хвиля Shai-Hulud: [зламали `@7nohe/openapi-react-query-codegen`](https://research.jfrog.com/post/shai-hulud-trinitite/) — 150K завантажень на тиждень**

JFrog назвали хвилю Trinitite. 28 серпня в npm залетіли десять шкідливих релізів приблизно за 20 хвилин.

Отруєні версії: 0.5.4, 0.5.5, 1.6.3, 1.6.4, 2.2.1, 2.2.2, 3.0.3, 3.0.4 і дві пре-релізні. Останні безпечні — 0.5.3, 1.6.2, 2.2.0, 3.0.2.

Що робить малварь:
• краде токени GitHub, npm, PyPI, RubyGems, хмарні креденшели, SSH-ключі та CI-секрети
• стартує навіть із вимкненими install-скриптами — через обфускований `binding.gyp`
• тримається через user-level systemd-сервіси і чіпляється до Claude і VS Code
• має revoke trap: при відкликанні токенів може знести домашню теку

Порядок дій від JFrog саме в такій послідовності: спершу ізолювати машину, і лише потім відкликати токени. Далі — прибрати сервіси персистенції, запінити безпечні версії, перезібрати лок-файли і ротувати креденшели з чистої системи.

Ключова деталь — не кидайся першим ділом ревокати токени. І окремо неприємне: `--ignore-scripts` тут не рятує, тож лок-файл доведеться перевіряти на конкретні версії руками.
