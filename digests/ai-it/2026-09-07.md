## 🛠️ Інструменти

**Автор mise [зарелізив packslip](https://jdx.dev/posts/2026-09-05-introducing-packslip/) — підписаний маніфест релізу, з якого приїжджають і completions, і agent skills**

Вендор кладе поруч із релізом підписаний через Sigstore маніфест: які архіви качати, де всередині лежить бінарник, які до нього йдуть completions і скіли. mise вже тримає packslip як tier 1 backend — вище за `github` і `aqua`, без плагінів і без запису в курованому реєстрі.

```sh
mise use -g packslip:github.com/jdx/hk
mise completion zsh --tool hk --install
```

Найцікавіше — скіли: тул привозить власний `SKILL.md`, що відповідає саме встановленій версії. Качаються вони автоматично, а от підкладати їх агенту треба окремо — автосинк вимкнений за замовчуванням:

```sh
mise skills ls
mise skills sync --dir .agents/skills
```

Перша спроба зробити скіли частиною пакета, а не окремим репо, який ти синхронізуєш руками. Підпис каже, звідки взялись інструкції, але не каже, що вони підходять твоєму проєкту — читати їх усе одно доведеться.

**Trail of Bits [виклали coop](https://github.com/trailofbits/coop) — одноразові VM, де Claude Code і Codex мають повний доступ до тулів, але не до твого хоста**

Rust-CLI, що піднімає ізольовану віртуалку під проєкт: усередині Docker, git, компілятори й пакетні менеджери, зовні — нічого твого.

```shell
curl -fsSL https://raw.githubusercontent.com/trailofbits/coop/main/install.sh | bash
coop setup
cd ~/code/my-project
coop up
coop claude   # або coop codex
```

Під капотом Firecracker на Linux і Lima на macOS (`brew install lima` ставиш сам, інакше `coop setup` впаде). Тестували на macOS arm64 і Linux x86_64, збірка під Linux arm64 є, але неперевірена. Apache-2.0.

У треді на HN людина, що юзає coop щодня, хвалить саме за те, що агент не бачить інших проєктів і особистих файлів — і одразу чесно додає, що «мотивований агент, імовірно, зміг би звідти вибратись».

Альтернатива devcontainer'у, коли хочеться межу жорсткішу за контейнер і не хочеться ганяти агента з `--dangerously-skip-permissions` просто в себе на машині.

**VS Code 1.136 [навчився дотискати пул-реквести](https://code.visualstudio.com/updates/v1_136) — Agent Merge сам розбирає рев'ю-фідбек, впалі перевірки і конфлікти**

Фіча в preview, вмикається налаштуванням `chat.agentMerge.enabled`. Агент бере PR і робить те, що зазвичай доробляєш сам: править за коментарями рев'ю, чинить червоні чеки, розрулює merge-конфлікти і перезапускає воркфлоу.

Поруч в експериментальних:
• мультирутові воркспейси для Copilot і Claude-агента — `chat.agentHost.copilotAgent.multiRootEnabled` і `chat.agentHost.claudeAgent.multiRootEnabled` (хуки поки живуть тільки в одній папці)
• чати групуються ієрархічно всередині батьківської сесії, з підсвіткою тих, що чекають на аппрув

Точка, де агент перестає бути «напиши код» і стає «доведи PR до зеленого». Найцікавіше буде подивитись, як воно поводиться на конфліктах, де обидві сторони чіпали ту саму логіку.

## 💡 Рецепти

**Рецепт: [ставити agent skills одним CLI](https://github.com/vercel-labs/skills) замість розкладати папки по агентах руками**

Приводом став [тред на HN](https://news.ycombinator.com/item?id=49589914) — 250+ апвоутів і 230+ коментарів про те, як люди взагалі тримають скіли. Консенсус простий: окремий git-репозиторій плюс симлінки в папки агентів. CLI `skills` від vercel-labs робить рівно це, але сам, і знає 77 агентів — Claude Code, Codex, Cursor, OpenCode, Copilot, Zed і далі за списком.

```bash
npx skills add vercel-labs/agent-skills
npx skills add vercel-labs/agent-skills -a claude-code codex
npx skills list
npx skills update
```

Кладе симлінками (`--copy`, якщо треба копії), `-g` — глобально замість проєкту. Джерелом може бути що завгодно: `owner/repo`, повний GitHub чи GitLab URL, шлях до конкретного скіла всередині репо, `git@`-адреса або локальна папка. Приватні репо тягне вже налаштованими git-креденшелами.

Команди — з README репозиторію, сам не тестив. У треді на HN тул згадують серед робочих варіантів; альтернативи звідти ж — `mise skills sync` і просто самописні симлінки.
