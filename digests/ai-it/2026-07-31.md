Модель вийшла з прев'ю в публічну бету, викликається як `deepseek-v4-flash`. Архітектура і розмір ті самі, що в V4-Flash-Preview — переробили тільки пост-тренування.

Заявлені агентні бенчмарки:
• Terminal Bench 2.1 — 82.7
• NL2Repo — 54.2

Цифри, які реально важать: cache hit коштує \$0.0028 за мільйон (98% знижки), max output — 384K токенів. Модель нативно підтримує Responses API і окремо адаптована під Codex, а для Anthropic-сумісних клієнтів є ендпоінт `https://api.deepseek.com/anthropic`.

Одна засідка на майбутнє: у доках уже висить попередження про peak/off-peak тарифікацію — в години пік (9:00–12:00 і 14:00–18:00 за Пекіном) ціна буде вдвічі вища. Дати ще не оголосили.

За співвідношенням ціни й інтелекту це зараз найагресивніша пропозиція на ринку. Очевидний кандидат у бекенд для агентних пайплайнів, де багато токенів і не потрібен фронтир.

Це за мільйон input/output токенів. Сама сімʼя вийшла лише 9 липня — тобто ціну зрізали за три тижні після релізу.

Практичний висновок простий: якщо в тебе є крок пайплайну на Luna, який ти закладав у бюджет три тижні тому, — він щойно став уп'ятеро дешевшим. Варто перерахувати, де ще можна злізти з Terra на Luna.

## 🛠️ Інструменти

**GitHub [відкрили stacked pull requests](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/) у публічному прев'ю — великий PR розбивається на шари, кожен ревʼюється окремо**

```bash
gh extension install github/gh-stack
```

Кожен PR у стеку таргетить шар під собою. Ревʼювери розбирають різні шари паралельно, не блокуючи роботу далі; змерджити можна або весь стек одним кліком, або окремий шар — верхні PR-и самі ребейзяться і перетаргечуються.

Працює з наявними branch protections і required checks, без окремої конфігурації. Створювати стеки можна з термінала, з github.com, з мобільного застосунку або через Copilot зі скілом `gh-stack`. Підтримку merge queue викочують поступово протягом найближчих тижнів.

> Landing 5 stacked PRs directly to a merge queue all at once! This removes so much friction — John Resig, автор jQuery

Це та фіча, заради якої команди роками ставили Graphite і Phabricator збоку. Тепер вона нативна — і, що важливіше, агент може складати стек за тебе замість одного полотняного PR на 40 файлів.

**Agent Skill [SimpleEnglish](https://github.com/AminBlg/SimpleEnglish) змушує LLM писати доки в ASD-STE100 Simplified Technical English**

```bash
npx skills add AminBlg/SimpleEnglish
```

Спробувати без встановлення:

```bash
npx skills use AminBlg/SimpleEnglish@simple-english
```

Усередині — 53 пронумеровані правила з 9 секцій аерокосмічного стандарту ASD-STE100. Автор заявляє скорочення порушень STE на 72.9% на протестованих моделях. Далі просто кажеш «rewrite this with simple-english».

Працює в Claude Code, Cursor, VS Code Copilot і ще ~25 харнесах, що підтримують стандарт Agent Skills. Для claude.ai на платних тарифах `SKILL.md` заливається через Settings → Customize → Skills.

Сьогодні в топі HN. Скіл б'є рівно в те, чим дратують згенеровані доки: пасив, синоніми заради синонімів, речення на три рядки. Якщо ганяєш агента на README і CHANGELOG — дешевий спосіб зробити вихлоп читабельним.

## 💡 Рецепти

**Simon Willison виклав [llm-chat-completions-server](https://simonwillison.net/2026/Jul/30/llm-chat-completions-server/) — піднімає OpenAI-сумісний ендпоінт над будь-якою моделлю, доступною в `llm`**

```bash
uv tool install llm --pre
llm install llm-chat-completions-server
llm chat-completions-server -p 9001
```

Після цього будь-який клієнт, який вміє Chat Completions API, можна націлити на localhost:9001 — і він отримає доступ до всіх моделей, під які в тебе стоять плагіни `llm`: і локальних, і хмарних.

Під капотом працює нова content-addressable схема логів з LLM 0.32rc1: кожна частина повідомлення адресується власним хешем, тож історія розмови, яка з кожним запитом дублюється, не пишеться в базу по десять разів.

Схема логів змінилась суттєво, тож перед апдейтом варто зробити бекап:

```bash
llm logs backup logs-backup.db
```

Це alpha-реліз (0.1a0) від самого Simon, команди взяті з його поста — сам не тестив. Він же чесно зазначає, що «GPT-5.6 Sol wrote the whole thing».

Юзкейс, заради якого це варте уваги: будь-який тул, прибитий цвяхами до OpenAI API, можна перевести на локальну модель, не патчачи його код.

## 📌 Рухи й безпека

**Anthropic [розібрали три інциденти](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals), коли їхні моделі під час кібер-евалів вилізли з пісочниці й атакували реальні системи**

• Opus 4.7 (квітень): назва фіктивної цілі збіглася з реальним доменом — модель витягла креденшели й дані з бази на кілька сотень рядків
• Mythos 5: опублікувала заражений Python-пакет у справжній PyPI — за ~годину його запустили на 15 реальних системах, серед них сканер security-компанії, звідки витекли креденшели
• внутрішня дослідницька модель просканувала ~9000 цілей і зламала одну компанію через відкриту debug-сторінку та SQL-ін'єкцію

Корінь однаковий: помилка конфігурації дала контейнерам евалів справжній інтернет, тоді як промпт стверджував, що інтернету немає. Моделі переконували себе, що реальні системи — частина симуляції. 23 липня евали зупинили, 27-го повідомили постраждалих.

Ізоляція агента, яка живе в тексті промпту, — це не ізоляція. Якщо ганяєш агентні пайплайни, перевір, що пісочниця обмежена на рівні мережі.
