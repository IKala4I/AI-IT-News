**Homebrew [зарелізили 7.0.0](https://brew.sh/2026/09/13/homebrew-7.0.0/) — з власним сканером вразливостей і кінцем епохи Intel**

Головне для щоденного використання:
• `brew vulns` — перевірка встановлених formulae по базі OSV.dev, без окремого тапу чи гему
• `install`, `reinstall` і `upgrade` тепер накладають завантаження на підготовку пакетів, `brew bundle` теж — менше простою між пакетами
• `brew install --dry-run` показує, що саме поставиться, однаково для formula і cask
• на macOS закрутили sandbox: cask більше не запускає застосунки, Mach-сервіси й UNIX-сокети в обхід (GHSA-5263-whxq-77hp)
• на Linux Bubblewrap замінили на Landlock — без додаткових залежностей

Ламається теж: macOS 10.15 і старіші не підтримуються взагалі, Sonoma 14 і Intel-Маки поїхали в Tier 3, нові bottles для Intel перестануть збирати після вересня 2027.

```bash
brew update
brew vulns --severity=high --deps --fix-available
```

Найцікавіше — саме `brew vulns`: аудит залежностей переїхав у CLI, окремий тул більше не потрібен. Є ще `--brewfile`, `--fix-type` і `--list-skipped` для дірок у покритті.

**[AgentsDock](https://agentsdock.net/) — IDE, щоб тримати Claude Code, Codex і Cursor на віддаленому сервері й заглядати туди з телефона**

Агенти крутяться на твоїй машині або сервері, а ти чіпляєшся клієнтом: десктоп (macOS, Linux, Windows) чи мобільний (iOS, Android). Можна стартувати й резюмити чати, дивитись живу активність, ставити наступну задачу в чергу, гортати файли й дифи, тримати персистентні термінали. Кілька клієнтів під'єднуються до одного сервера.

Зроблено під дослідницькі задачі, тому результати джобів показує інлайн — графіки й відео прямо в інтерфейсі. Зараз бета (1.0.0-beta.1), [код відкритий](https://github.com/ZhengyiLuo/AgentsDock), але загальної ліцензії в репозиторії поки немає.

![AgentsDock](https://agentsdock.net/assets/og-card.png)

Приваблює тут не IDE, а можливість глянути статус довгого прогону з телефона, не відкриваючи ноут. Для команди відсутність ліцензії — стоп-фактор, для себе можна пробувати.

**[gPTY](https://github.com/godot-pty/gpty) — термінальний мультиплексор на Godot і Rust, у якого є MCP-сервер**

Замість tmux — тайлова сітка панелей із власним рендером: незалежні шели з повним кольором і скролбеком, поруч можна класти в'ювер коду й дерево файлів. Скролбек, налаштування, воркспейси та профілі автозберігаються в SQLite/JSON.

Цікаве для нас — публічний API: воркспейсом можна керувати через JSON-RPC IPC-сокет, CLI або MCP-сервер. Тобто кодинговий агент сам розкладає панелі й читає вивід. Є окрема панель спостереження за агентом із lifecycle-подіями та inspector-панель для Q&amp;A під час дебагу.

Бінарники під Linux, macOS і Windows лежать у GitHub Releases — ні Godot, ні Rust ставити не треба. Ліцензія GPLv3+ з винятком для плагінів і конфігів.

Мультиплексор з MCP «з коробки» — рідкісна штука: агент у панелі керує самим воркспейсом, а не лише своїм шелом. Сирувато, але напрямок правильний.

**Рецепт: [показати в статусбарі Claude Code, скільки коштує наступний турн](https://github.com/Field-Logic-Ltd/ClaudeStatsBar)**

Проблема, яку ловить автор: відсоток заповнення вікна нічого не каже про ціну. Сесія на 486k з мільйонного вікна читається як комфортні «49% зайнято», хоча кожне наступне повідомлення тягне 49k токенів ще до того, як ти щось надрукував.

```bash
git clone https://github.com/Field-Logic-Ltd/ClaudeStatsBar.git && cd ClaudeStatsBar
./install.sh
```

Інсталятор вливає `statusLine` у `~/.claude/settings.json` — з бекапом і без перезапису наявного. Руками те саме:

```json
{
  "statusLine": {
    "type": "command",
    "command": "/absolute/path/to/ClaudeStatsBar/statsbar.py",
    "padding": 0
  }
}
```

Далі в рядку видно модель і розмір вікна, бар контексту, токени на турн, множник відносно найдешевшої точки сесії та залишок 5-годинного і 7-денного вікон. Пороги крутяться через `CC_CTX_WARN` і `CC_CTX_HIGH`, `CC_SHOW_COST` вмикає оцінку в доларах.

Джерело — Show HN від 11 вересня, MIT, чистий Python без залежностей. Сам не тестив.

**Рецепт: [замкнути кожного субагента у власний git worktree](https://code.claude.com/docs/en/worktrees)**

Коли кілька агентів правлять один чекаут, вони починають топтати файли один одного. У Claude Code це лікується одним рядком у фронтматері кастомного субагента в `.claude/agents/`:

```markdown
---
name: refactorer
description: Applies mechanical refactors across many files
isolation: worktree
---
```

Після цього Claude Code блокує такому агенту Edit/Write у головний чекаут і будь-яку Bash-команду, чий cwd туди веде. Ворктрі створюються під `.claude/worktrees/` і гілкуються від дефолтної гілки; `worktree.baseRef: "head"` змусить гілкуватись від поточного HEAD.

Друга половина рецепта — щоб свіжий чекаут не був порожнім. Файл `.worktreeinclude` у корені проєкту (синтаксис як у `.gitignore`) копіює в кожен новий worktree gitignore-нуті файли:

```text
.env
.env.local
config/secrets.json
```

Офіційна фіча, все є в документації. Руками той самий ефект дає `claude --worktree feature-auth`.
