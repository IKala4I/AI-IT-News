**Google [випустила Gemini 4 Hydrogen](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/), швидку модель для щоденного кодингу й агентів. За індексом Artificial Analysis вона не поступається флагманській Argon**

![Gemini 4 Hydrogen](https://storage.googleapis.com/gweb-uniblog-publish-prod/images/gemini-4-hydrogen__key-art__lockup__16-9.width-1300.jpg)

Що нового:
• \$1,50 / \$7,50 за 1M вхідних / вихідних токенів, ціна однакова на всьому контексті в 1M. В AI Studio є безкоштовний тариф
• у 2,5 раза швидша за Gemini 3.8 Flash і більш ніж уп'ятеро рідше вигадує факти
• правки точкові, сусідні файли не переписує, а великий репо читає паралельними запитами
• з 1 грудня Carbon і Argon в API [дорожчають удвічі](https://aistudio.google.com/docs/pricing), до \$4 / \$20. Для Hydrogen подорожчання не заявлене

Де спробувати: API і AI Studio (`gemini-4-hydrogen`), Android Studio, застосунок Gemini. [В Antigravity](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/) модель доступна на AI Pro і Ultra, а у виборі моделі з'явився **Orchestrator**: сильніша модель планує, а Hydrogen редагує код і ганяє тести. Google каже, що якість майже як у Carbon, а квоти йде на 24% менше. Orchestrator (Carbon) доступний тільки на Ultra, на Pro є Orchestrator (Argon).

Після 1 грудня це найрозумніший дефолт для API-фіч на Gemini. На AI Pro прожени Orchestrator на довгій задачі.

Модель вийшла 9 листопада, але в дайджест ще не потрапляла.

Що нового:
• \$8 / \$40 за 1M вхідних / вихідних токенів, це [на 20% дешевше](https://simonwillison.net/2026/Nov/9/llm-anthropic/) за Fable 5.1

• на FrontierSWE v2, тесті на реальних інженерних задачах, набирає 69,9% проти 62,3% в Opus 5.5
• fast mode у Claude Code генерує до 2,5 раза швидше, але коштує вдвічі дорожче

Де спробувати: claude.ai і Claude Code на платних планах (на Pro Fable може зайняти не більше половини тижневого ліміту), API (`claude-fable-5-2`), AWS, Google Cloud і Azure. Mythos 5.2 — це та сама модель без частини запобіжників щодо кібербезпеки й біології, але доступ до неї мають тільки перевірені організації.

Anthropic сама радить починати з Opus 5.5, а Fable брати на найважче: великий рефакторинг, міграцію чи баг, на якому Opus застряг.

## 🛠️ Інструменти

**Claude Code [отримав експериментальний Code Mode](https://code.claude.com/docs/en/code-mode): Claude більше не викликає інструменти по одному, а пише шматок JavaScript, який робить усі виклики за один крок**

**Коли знадобиться:** однакова правка в десятках файлів, пошук, результати якого треба відфільтрувати перед читанням, або кілька незалежних команд, які можна запустити паралельно.

**Як виглядає:** потрібна версія 2.1.323+ (native build):

```bash
CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude
```

Код, який написав Claude, можна подивитися через `Ctrl+O`.

**+** Claude не читає кожен проміжний результат, а одразу отримує потрібну частину виводу
**−** працює тільки в інтерактивному `claude` у терміналі: без `-p`, VS Code, Desktop і хмарних сесій. Продовжити таку сесію теж можна тільки з увімкненим Code Mode

Пробуй на масових правках у некритичному репо: фіча експериментальна і може зникнути в будь-якому релізі.

## 💡 Рецепт

**В Anthropic радять [одне речення, після якого Claude Fable 5.2 прибирає дублікати коду](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#say-who-owns-the-code), а не множить їх**

Якщо в промпті не сказано, чий це код, модель дописує нове поруч зі старим, навіть коли дублює наявне. А якщо сказано, що кодбейс її, вона зводить дублікати в одну спільну функцію приблизно в 75% запусків. Без речення так буває менш ніж у 10% запусків. Ось воно:

```text
You are the owner and long-term maintainer of this codebase, and its design is up to you.
```

У Claude Code його найпростіше додати в `CLAUDE.md` проєкту:

```bash
echo 'You are the owner and long-term maintainer of this codebase, and its design is up to you.' >> CLAUDE.md
```

Але за це доведеться заплатити:
• вихідних токенів стає на 70-80% більше
• з'являються зміни, яких ніхто не просив (переважно тести й документація), а інколи змінюється поведінка фічі
• у підсумку PR дрібні зміни часто не згадуються, тож читай сам diff

Якщо на робочому репо потрібен мінімум змін, не додавай це речення. Правило «No drive-by refactors» поруч з ним його не скасовує.

Це офіційна порада з документації Anthropic, але там мова про системний промпт. Чи так само працює через `CLAUDE.md`, сам не перевіряв.

## ✨ Цікавинка

**AWS [випустила офіційний емулятор своєї хмари](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html), весь код якого написали й протестували AI-агенти. Понад 200 сервісів працюють у ньому локально, офлайн і безкоштовно.** За перші три тижні рій агентів зробив [29 684 коміти](https://simonwillison.net/2026/Nov/11/aws-emulator/). Люди побудували для агентів «риштування» і вирішують, який результат вважати правильним, а агенти самі ганяють тести проти справжнього AWS і латають розбіжності. Swami Sivasubramanian з AWS розповідає, що агент чотири ночі не міг перебудувати рушій реплікації, на який у нього з колегою колись пішло чотири місяці, а коли отримав специфікацію і тестове середовище, впорався за дві години.
