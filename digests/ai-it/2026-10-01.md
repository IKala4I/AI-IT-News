## 🚀 Моделі

**Google [зарелізили Gemini 4 Argon](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/) — ліміт на вихід підняли з 64K до 1M токенів**

Головна цифра тут не бенчмарк, а output limit: мільйон токенів в одній траєкторії. Решта з анонсу:
• DeepSWE v1.1 — 77.9%, SOTA
• CWE-bench v1 (лагодження вразливостей) — 68%, перше місце ділить
• AutomationBench від Zapier — 51.3%, перше місце
• LVBench (довге відео) — 91.7%, SOTA

Вступна ціна — \$2 за Mtok входу і \$10 за вихід, кешований вхід на 95% дешевше. Далі стане \$4/\$20.

А тепер погане: Argon роздають «перевіреним cyber-захисникам» через Fairwind Program і внутрішнім командам Google. Публічно обіцяють спочатку платним API-клієнтам і підписникам AI Ultra, без дати.

![Gemini 4 Argon](https://storage.googleapis.com/gweb-uniblog-publish-prod/images/g4_30-09-26_key-art_blog.width-1300.png)

1M на вихід — нова категорія для довгих агентних прогонів: рефакторинг на весь репозиторій можна не різати на шматки. Але спробувати сьогодні нічого: ні в Vertex AI, ні в AI Studio, ні в Gemini CLI його немає.

**Cloudflare [виклали Clef](https://blog.cloudflare.com/clef-decision-models/) — відкриті decision-моделі під Apache-2.0**

Decision-модель — не чат, а дешевий гейт: даєш стан і набір питань, отримуєш по логіту на кожен дозволений варіант. Типи питань три: `noul` (так/ні), `choice` і `score`.

Два розміри на базі Qwen: Clef на Qwen3.8-27B і Clef-flash на Qwen3.5-9B. Медіанна латенсі — 209.3 мс і 38.8 мс, P95 — 238.6 і 122.4. У прикладі з блогу класифікація домену зайняла 2.2 с проти 4.7 с у GPT-OSS-120B.

API сумісний з Jev, тож на Workers AI це просто:

```bash
curl https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/ai/run/@cf/cloudflare/clef \
  -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"model": "clef", "state": "...", "questions": {...}}'
```

Локально — з [картки на Hugging Face](https://huggingface.co/Cloudflare/clef) (треба torch 2.11, transformers 5.10.2, pillow для картинок і відео):

```python
import sys, torch
from huggingface_hub import snapshot_download

path = snapshot_download("Cloudflare/clef")
sys.path.insert(0, path)
from joint_schema_model import load_release_model

model, processor = load_release_model(path, device="cuda")
```

![Clef](https://blog.cloudflare.com/_emdash/api/media/file/01M3TJV43SPQCPKJ6GBXFCDKNE.01M3TJV53VYDMVNCZDPH1FBFYN.png)

Два дні тому [Ollama](https://ollama.com/blog/ollama-now-supports-jev-style-decision-models) додала рантайм для таких моделей — тепер є і відкриті ваги під них. Якщо ганяєш агента з ризиковими tool call'ами, гейт на 39 мс замість раунд-трипу в клауд виглядає привабливо.

## 🛠️ Інструменти

**[Magnitude](https://github.com/magnitudedev/magnitude) — рушій локального інференсу, який тюнить ядра під твоє залізо перед запуском моделі**

Не передзібрані кернели під класи заліза, як у llama.cpp, а компіляція на твоїй машині. Apache-2.0, Rust, у десктопному застосунку вже є CLI `magnitude`.

Цифри з анонсу:
• Metal — декод швидше на 92% (30 → 57 tok/s на M4 Pro), prefill на 9%
• CUDA — декод на 19%, prefill на 23%
• на 27% менше пам'яті на агента
• KV-кеш квантують у стилі TurboQuant: 8 біт на keys, 4 на values

Одним кліком підключається до Pi, OpenCode, Codex, Claude Code і Cline, решта — через OpenAI-сумісний API.

![Magnitude](https://magnitude.dev/og-image.png)

Чесно про цифри: [в коментах на HN](https://news.ycombinator.com/item?id=49911995) результати суперечливі. На M5 Max хтось отримав 161 tok/s проти 175 у llama.cpp, тобто повільніше, і Rapid-MLX обігнав обох. Автори визнали дірку в Metal 4 matmul на M5+, мульти-GPU немає зовсім.

Ідея правильна, але поки лотерея: на M4 виграш схожий на заявлений, на M5 — навпаки. Перед переїздом з llama.cpp заміряй на своєму залізі.

**GitHub [розкатали HydraFusion на VS Code і застосунок Copilot](https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app)**

Апдейт до [вересневого релізу](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/): місяць тому оркестратор (Single / Cascade / Critique) жив тільки в Copilot CLI, тепер він у редакторі й у застосунку. Додали прозорість: видно прогрес у реальному часі й статус під час довгих задач.

Плани: Pro і Pro+ отримують самі, на Business та Enterprise адмін має увімкнути preview-фічі.

У VS Code 1.140+ вибирається з пікера моделей. Якщо його там немає — увімкни налаштування:

```
chat.copilot.hydraFusion.enabled
```

У застосунку Copilot — онови, в Settings знайди «HydraFusion», увімкни і далі вибери в пікері.

Досі research preview, тож чекати стабільності не варто. Але оркестрація з критиком з іншої родини моделей — рівно той патерн, який люди збирають руками через субагентів; тут він вже в пікері.

## 💡 Рецепти

**Рецепт: Claude Code [у 2.1.286](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) сам запускає твій скіл `verify` перед кожним комітом**

Рядок із changelog: «when your project or user skills include one named `verify`, Claude is now told to run it right before committing, except for docs-only and tests-only commits». Тобто достатньо завести скіл з такою назвою — і агент перестане комітити, не прогнавши твої перевірки.

Файл кладеш за [стандартним шляхом для скілів](https://code.claude.com/docs/en/skills):

```
.claude/skills/verify/SKILL.md
```

Усередині — frontmatter і твої інструкції. `allowed-tools` тут важливий: без нього агент питатиме дозвіл на кожен запуск.

```yaml
---
name: verify
description: Runs this repo's checks before a commit.
allowed-tools: Bash(npm *)
---

Run each of these and fix anything that fails before committing:

1. `npm run lint`
2. `npm run typecheck`
3. `npm test`
```

Команди в тілі — приклад, підставляй свої. Виняток для docs-only і tests-only комітів вбудований, тож на правку README воно не зриватиметься.

> Офіційна фіча з changelog, формат скіла — з документації. Сам ще не ганяв.

Найдешевший спосіб прибрати «агент закомітив зламане»: один файл замість рядка в CLAUDE.md, який модель може й проскочити.

## 📌 Рухи й безпека

**Figma [пускає до свого remote MCP-сервера тільки клієнтів з власного каталогу](https://www.figma.com/mcp-catalog) — решта ловить 403**

Сервер живе на `https://mcp.figma.com/mcp`, і [за гайдом Figma](https://help.figma.com/hc/en-us/articles/32132100833559-Guide-to-the-Figma-MCP-server) список підтримуваних клієнтів — це саме каталог. У ньому близько двох десятків імен: Claude Code, ChatGPT, Codex, Cursor, VS Code, Copilot CLI, Grok, Zed, Warp, Devin, Replit, Kiro, Xcode (beta), Android Studio.

Кого немає — тому закрито наглухо. [Адаптер для Pi](https://github.com/nicobailon/pi-mcp-adapter/issues/49) отримує плейнтекстовий `HTTP 403 Forbidden` ще на dynamic client registration, тобто на еджі, до OAuth-хендлера. Персональні токени не приймаються, свій OAuth-app не дістане скоуп `mcp:connect`. Залишається десктопний сервер, про який Figma сама пише, що він «primarily for specific use cases for organizations and enterprises».

[На HN](https://news.ycombinator.com/item?id=49922729) це зайшло погано: кажуть, що allow-list суперечить самій ідеї MCP. Практичний висновок простий: якщо твій агент не в каталозі — Figma для нього закрита, і це тепер критерій вибору харнеса.
