## ⚛️ React

**Oxc [навчився React Compiler](https://oxc.rs/blog/2026-08-18-react-compiler-support) — 22 правила в oxlint і окремий пакет `oxc-transform-react` для автомемоізації**

Тобто компілятор більше не прив'язаний до Babel. Лінтерні перевірки, зібрані з валідаційних пасів самого компілятора, вмикаються в `.oxlintrc.json`:

```json
{
  "plugins": ["react"],
  "categories": { "correctness": "error" }
}
```

Трансформ доступний або напряму через `oxc-transform-react`, або у Vite через `@vitejs/plugin-react` 6.1.0+ з `react({ compiler: true })`. Автори міряють «більш ніж у 10 разів швидше за Babel»: файл, що жував 100 мс, компілюється за 10.

Готове не все: правила `config` і `gating` не імплементовані, категорії `fbt` і `memoized-effect-dependencies` теж, а в коді лишається 57 конструкторів Todo-діагностик.

Для RN це поки про веб-частину стеку, не про Metro. Але напрямок ясний: React Compiler відв'язується від Babel, і рано чи пізно це докотиться і до нас.

## 📱 React Native та Expo

**Software Mansion [випустили Reanimated 4.6.0](https://github.com/software-mansion/react-native-reanimated/releases/tag/4.6.0) — з підтримкою RN 0.87 і CSS-колбеками, які нарешті стріляють на нативі**

Головне:
• RN 0.83–0.87, у парі з Worklets 0.12.x
• вісім колбеків CSS-анімацій і транзишенів (`onCSSAnimationStart`, `onCSSTransitionEnd` та компанія) тепер працюють на iOS і Android
• новий воркет `contrastColor` — рахує, що дасть кращий WCAG-контраст на заданому тлі: `'white'` чи `'black'`; працює і в `useAnimatedStyle`, і на JS-треді
• експериментально: opacity-транзишени на Android можуть їхати через `ObjectAnimator` повз animation loop — приблизно як Core Animation на iOS

Breaking changes у релізі не заявлено, тож апдейт має бути безболісним. Якщо ти вже переїхав на RN 0.87 — це той реліз, який тобі потрібен; рецепт з platform transitions нижче.

#reactnative

**Callstack [зарелізили Rozenite 2.2.0](https://github.com/callstackincubator/rozenite/releases/tag/v2.2.0) — панелі плагінів тепер можуть жити в окремому вікні**

Проблема, яку це лікує, знайома: React Native DevTools перезавантажують панель Rozenite щоразу, коли перезапускається JS VM — Fast Refresh, що зачепив натив, краш, ручний reload. Стан панелі щоразу з нуля.

Standalone-апка чіпляється до девайса напряму, повз DevTools, і ці релоуди переживає. Ставиться окремим пакетом:

```bash
npm install -D @rozenite/electron-app
npx rozenite open
```

Команда покаже всі девайси, підключені до Metro, і відкриє вибраний в Electron-вікні. Є `--host`, `--port` і `--deviceId`.

Доки чесно кажуть «Experimental… may change in future releases», і повного набору фіч React Native DevTools тут немає. Але якщо половина твого дебагу — це Network чи TanStack Query панель, спробувати варто.

## 🧰 Бібліотеки й тулінг

**Bun [зарелізив 1.4](https://bun.com/blog/bun-v1.4) — з вбудованим React Compiler і без жодного Babel**

`bun build --react-compiler` (або `reactCompiler: true` в `Bun.build()`) дає автомемоізацію «19× швидше за Babel-плагін на великій React-кодбазі».

Решта, що зачіпає щоденну роботу:
• `optimizeImports: ["antd", "@mui/material"]` — виріз невикористаних ре-експортів з barrel-імпортів
• `--metafile-md` — Markdown-звіт про найбільші модулі і ланцюжки залежностей
• `bun install` заявлено як 15–33× швидший за npm/yarn/pnpm; додались `bun audit fix`, `bun dedupe`, `bun prune --production`
• `bun test --parallel`, `--shard=1/3` і `--changed=main` — ганяти тільки те, що зачепили зміни

![Bun 1.4](https://bun.com/og/blog/bun-v1.4.png)

Breaking changes не заявлено. Для RN Bun усе ще не заміна Metro, але як менеджер пакетів і тест-раннер у монорепо — цілком робочий варіант.

**Software Mansion [довели enriched-markdown до 1.0](https://github.com/software-mansion/enriched-markdown/releases/tag/v1.0.2) — нативний рендер і редактор Markdown для RN без WebView**

• **Що замінює:** WebView-рішення для Markdown. Рендер іде через платформенні текстові API — Swift на iOS, Kotlin на Android, плюс веб. CommonMark і GFM, LaTeX, підсвітка коду через tree-sitter і стрімінг для LLM-чатів.
• **Наскільки стабільно:** на npm це `react-native-enriched-markdown@1.0.2` від 20 серпня, 968 зірок. 1.0 приніс фундамент блокового редагування і нативний iOS-рендерер — тобто мажор свіжий, не вилежаний.
• **Чим покращить:** нативний текст замість WebView — це відсутність окремого рантайму під кожен markdown-блок.

⚠️ **Міграція:** у 1.0.2 [прибрали вбудований Expo config plugin](https://github.com/software-mansion/enriched-markdown/releases/tag/v1.0.2) — `app.plugin.js` і теку `plugin/`. Конфіг (`enableMath`, `enableCodeHighlight`, `codeHighlightLanguages`) переїхав у блок `enriched-markdown` у `package.json`; старі build-флаги ще працюють, але вже deprecated.

Гарний кандидат, якщо рендериш відповіді LLM у RN і досі тягнеш це через WebView. Тільки закладай, що API 1.x ще рухатиметься.

## 📲 Платформи і стори

**Google [попереджає про ліміти памʼяті на апку](https://android-developers.googleblog.com/2026/08/app-broader-memory-limits.html) — Android 17 почав з Pixel, наступного року це буде вся екосистема**

Механіка така: коли апка впирається у свій ліміт, система жме її сторінки в zRAM — і це видно як джанк. Якщо тиск триває, процес просто вбивають. Розпізнати можна через `ApplicationExitInfo.getDescription()`: причина `REASON_OTHER` з описом, який містить `MemoryLimiter:AnonSwap`.

Конкретних порогів у мегабайтах Google не називає — тільки те, що ліміти залежатимуть від конфігурації девайса, від 4 ГБ до 16 ГБ+. Що радять: дивитись Android vitals у Play Console, підключити Firebase Crashlytics 20.1.0+ і знімати хіп-дампи через `ProfilingManager` за тригерами `TRIGGER_TYPE_ANOMALY` і `TRIGGER_TYPE_OOM`.

Для RN це неприємніше, ніж для нативу: JS-хіп Hermes, Shadow Tree і кеші зображень легко складаються в сотні мегабайт. Варто вже зараз глянути, скільки твоя апка тримає на бюджетному Android.

## 💡 Рецепти

**Пустити opacity-транзишени на Android повз animation loop у Reanimated 4.6**

Флаг статичний, тож живе в `package.json` і вимагає ребілду нативу:

```json
{
  "reanimated": {
    "staticFeatureFlags": {
      "ANDROID_CSS_PLATFORM_TRANSITIONS": true
    }
  }
}
```

Далі — `pod install` для iOS і повний ребілд нативної апки.

Що це дає: за релізом 4.6.0 і [доками](https://docs.swmansion.com/react-native-reanimated/docs/guides/feature-flags), транзишен їде як `ObjectAnimator`, який пише значення прямо у платформенну в'юху, а не через цикл анімацій Reanimated.

Звідки: офіційна сторінка feature flags і release notes 4.6.0. Флаг помічений як експериментальний і вимкнений за замовчуванням; на платформу поки маршрутизується тільки `opacity`, решта властивостей лишається в animation loop.

**Фоновий трекінг локації в Expo, який не вмирає після свайпу з recents**

З [розбору в блозі Expo](https://expo.dev/blog/how-to-build-a-resilient-activity-tracker-with-expo) — дві опції, на яких найчастіше горять:

```js
await Location.startLocationUpdatesAsync(BACKGROUND_LOCATION_TASK, {
  accuracy: Location.Accuracy.High,
  timeInterval: 5000,
  distanceInterval: 0,
  foregroundService: {
    notificationTitle: 'Activity in progress',
    notificationBody: 'Tracking your walk',
    killServiceOnDestroy: false,
  },
  activityType: Location.ActivityType.Fitness,
  showsBackgroundLocationIndicator: true,
  pausesUpdatesAutomatically: false,
});
```

• `killServiceOnDestroy: false` — foreground service переживає змах апки з recents
• `distanceInterval: 0` — тримає повну частоту семплів; автор окремо називає значення на кшталт 10 метрів пасткою, бо Android починає економити GPS
• `activityType: Fitness` на iOS підказує системі профіль руху

Пакети: `expo-location` і `expo-task-manager`, задача реєструється через `TaskManager.defineTask`. Дозволи: Always на iOS, `ACTIVITY_RECOGNITION` на Android 10+ і `FOREGROUND_SERVICE_LOCATION` на Android 14+.

Звідки: гайд Expo від 17 серпня, код узятий звідти дослівно.
