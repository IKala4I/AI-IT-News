## ⚛️ React

**React [закрив критичний RCE](https://github.com/react/react/security/advisories/GHSA-xqc2-xf4c-x3h3) у Server Components — CVSS 9.5, без автентифікації**

Уразливі пакети: `react-server-dom-webpack`, `react-server-dom-parcel`, `react-server-dom-turbopack` версій 19.0.0–19.0.8, 19.1.0–19.1.9, 19.2.0–19.2.8 і 19.3.0. Пофікшено в 19.0.9, 19.1.10, 19.2.9 та 19.3.1. Воркераунду немає, рекомендація одна — оновлюватись негайно.

Тригер вузький: тільки коли відповідь транспортує кілька typed arrays і серед них є значення, підконтрольне атакеру. Але експлуатація — без логіна, без взаємодії юзера, низька складність.

Якщо твій React живе без сервера або ти не юзаєш фреймворк чи бандлер-плагін з підтримкою RSC — тебе це не торкається. Чистий React Native сюди не входить.

Минулого тижня я написав, що в 19.3.1 «єдина зміна — покращили транспортний протокол RSC». Це неправда: реліз закриває саме цей RCE плюс DoS у Server Functions. Тримаєш RSC-сервер — патч не опційний.

## 📱 React Native та Expo

**iPhone Duo вийшов 23 жовтня, і Expo того ж дня [виклав гайд](https://expo.dev/blog/supporting-iphone-duo) з підтримки**

Головне, що ламає наявні лейаути: у book-подібних орієнтаціях iOS переносить статус-бар, таб-бар і тулбар у вертикальний рейл на одному з країв. Рейл забирає 84pt зліва або справа.

Що з цього випливає:
• `Stack` і `NativeTabs` з Expo Router iOS розкладає сам; кастомні JS-хедери та таб-бари отримують лише базовий safe-area, а `TabList` у рейлі не підтримується
• `preferredPlacement` на `NativeTabs` приймає `sidebar`, `tabBar` або `automatic`
• `useVerticalBarEdgeIOS()` з `expo-status-bar` віддає `leading`, `trailing` або `null` — але в розкладеному портреті теж `null`, тож детектором Duo він не є
• `expo-hinge` і `useHinge()` дають кут і статус завісу: `closed`, `partiallyOpen`, `fullyOpen`
• вікно в лівому Split View — 469pt; перевір горизонтальні карусельки й абсолютно позиційовані вʼюхи

Потрібні SDK 58, Xcode 27.1 і EAS-образ `sdk-58` або `latest`.

![iPhone Duo support in Expo](https://cdn.sanity.io/images/9r24npb8/production/527bd8851cf2d5614b7042acdf83127c97e351f2-2400x1350.png)

Стандартний Expo Router зі `Stack` і `NativeTabs` переживе це кількома правками. Кастомні бари — закладай окремий спринт: Apple у цій формі фактично змушує віддати бари системі.

**Xcode 27 викинув Simulator.app — Expo [залатав CLI](https://expo.dev/blog/xcode-27-device-hub-expo-device-hub) і дав власний дашборд девайсів**

Expo CLI відкривав симулятор по імені `Simulator.app`, якого в Xcode 27 більше немає — замість нього Device Hub. Через це перестала працювати клавіша `i`, і доводилось бутити симулятор через `simctl`, втрачаючи fast refresh. Тепер CLI детектить Device Hub сам, апгрейд на SDK 58 лікує це без жодних конфігів.

Заодно вийшов `expo-device-hub` — dev tools плагін, що відкриває в браузері дашборд локальних симуляторів та емуляторів: лайв-відео з тапами й набором тексту, бут і шатдаун, графіки CPU, памʼяті й мережі, перемикачі appearance, Liquid Glass, розміру тексту та accessibility.

```bash
npx expo install expo-device-hub
npx expo start
```

Далі — лінк «Expo Device Hub» у виводі CLI або `Shift + M`. Без Expo-проєкту працює як `npx expo-device-hub`.

Наскільки стабільний: pre-1.0, автори прямо пишуть «Expect changes to the dashboard between releases», доків поки нема — тільки README. SDK 57+, MIT. iOS-симулятори потребують macOS з Xcode, Android-емулятори працюють будь-де з Android SDK, стрімінг фізичних iOS-девайсів у цей реліз не потрапив.

![expo-device-hub](https://cdn.sanity.io/images/9r24npb8/production/cc20182d3b8a406a9d49205db075cd95a7ae245f-2400x1350.png)

На Xcode 27 апдейт CLI обовʼязковий, інакше `i` просто не працює. Дашборд — опційна приємність, але графіки CPU поруч із живим екраном закривають те, за чим зараз лазиш у Xcode окремо.

#expo

**Expo [представив expo-app-intents](https://expo.dev/blog/introducing-expo-app-intents) — Siri, Shortcuts, Spotlight і Apple Intelligence для RN-апок**

Пакет підключає Apple App Intents: екшени в Siri та Shortcuts з догортанням відсутніх параметрів, вибір даних апки як параметра, схеми Apple (наприклад, драфт листа) і контент апки у Spotlight із привʼязкою до екрана.

Декларації інтентів пишуться на Swift — Xcode читає їх на етапі білда. Expo компілює файли з папки `app-intents/` через inline modules, без ручного копання в Xcode-проєкті.

```bash
npx expo install expo-app-intents
npx expo-app-intents init --examples counter
```

Або вручну в `app.json`:

```json
{
  "expo": {
    "plugins": ["expo-app-intents"],
    "experiments": {
      "inlineModules": {
        "watchedDirectories": ["app-intents"]
      }
    }
  }
}
```

Наскільки стабільний: альфа, автори пишуть, що API ще змінюватиметься. iOS 16.4+, гайд писаний під Xcode 27 та iOS 27, потрібен dev-білд — в Expo Go не працює.

Два мінуси на вході: Swift у проєкті і новий нативний білд на кожну зміну фраз. Але це перший офіційний шлях до Siri з Expo без власного нативного модуля.

## 🧰 Бібліотеки й тулінг

**TypeScript [випустив 7.1 beta](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/) — тайпчек до 1.9× швидше і до половини менше памʼяті**

```bash
npm install -D typescript@beta
```

Цифри з анонсу, 4 потоки тайпчекера і `--noEmit`: mui-docs 22.2 → 11.9 с і 8093 → 4079 MiB, sentry 19.6 → 15.1 с, vscode 21.6 → 17.7 с.

Решта:
• `--target es2026` стабільний, `--lib es2026` додає `Math.sumPrecise()`, `Iterator.concat()`, `Array.fromAsync()`, `getOrInsert` на Map і WeakMap, base64/hex на `Uint8Array`
• Content Mappers — плагін-пойнт для Vue, Svelte, Astro, MDX і CSS Modules; реєструється в `tsconfig.json` під `contentMappers`, вмикається через `tsc --runExternalCode`
• import attributes в ambient-модулях: типи їдуть за атрибутом `type: "css"`, а не за розширенням файлу
• новий API розбитий на ентрі-пойнти `typescript/sync`, `async`, `fs`, `ast`

⚠️ **Міграція:** дві поведінкові зміни можуть насипати помилок — перегенеровані DOM-типи в `lib.d.ts` і суворіші distributive conditional types, де параметр у гілці умовного типу тепер звужений, звідси «Type 'B' does not satisfy the constraint 'A'». [Анонс із прикладами фіксів](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/)

RC обіцяють десь за місяць. Content Mappers для RN поки мимо, а от швидкість і памʼять — привід поганяти бету на CI вже зараз.

**Cloudflare і VoidZero [показали tsrs](https://blog.cloudflare.com/typescript-rust-port/) — Rust-порт тайпчекера TypeScript 7**

Що робить і що замінює: альтернативна реалізація `tsc` з TS 7 — не форк, а порт, що інкубується в Oxc поруч з Oxlint. Робиться разом з Max Schwenk (Owner.com) і в тісній співпраці з командою TypeScript, плюс є план злити tsc-rs і tsrs в один пакет.

```bash
pnpm add -D tsrs
pnpm exec tsrs --noEmit
```

Чим може покращити: у ранніх бенчах до 8× швидше за TypeScript 7.0 і приблизно на 70% менше памʼяті при тій же кількості воркерів. Частина оптимізацій уже поїхала в 7.1 beta. Має також пришвидшити type-aware лінтинг в Oxlint.

Наскільки стабільний: експеримент. На npm свіжа версія `0.18.0-ts7.1.0-dev.20260929` від 19 жовтня — схема версій прибита до dev-білда TypeScript, який вона трекає. У README мета сформульована як «We aim to release a stable version against TypeScript 7.1 with 100% conformance», є окремий документ з відомими розбіжностями, PR закриті, приймають тільки іш'ю. Відомий баг: помилки можуть зʼявлятись і зникати між запусками через порядок у чекері; опція `--checkerAssignment go` дає Go-сумісну поведінку, але детермінізму не гарантує. 2.2k зірок.

Ставити в CI замість tsc рано — недетермінований вивід помилок це вбʼє. А прогнати раз на великому монорепо і подивитись на цифри — цікаво вже зараз.

**[FastImage переписали під New Architecture](https://github.com/DylanVann/react-native-fast-image/releases/tag/v10.0.0) — і бібліотеку знову активно підтримують**

10.0 вийшла 12 жовтня, а за минулий тиждень лінійка добігла до 10.9: релізи майже щодня, переважно a11y і дрібні фікси Android та iOS.

Що в мажорі:
• FastImage тепер нативний компонент New Architecture і TurboModule — одна вʼюха без дітей
• `objectFit` замінив `resizeMode`, додався `objectPosition`
• на Android Glide ходить через OkHttp самого RN — з інтерсепторами й куками апки, таймаути 15 с
• картинки на Android за дефолтом фейдяться

⚠️ **Міграція:** `resizeMode` → `objectFit` (`stretch` → `fill`, `center` → `scale-down`, `repeat` прибрали), діти більше не рендеряться — замість них `FastImageBackground`, `fallback` викинули, Android-пакет переїхав з `com.dylanvann.fastimage` на `com.fastimage`, `NativeModules.FastImageView` зник. Щоб лишити поведінку 9.x на Android: `FastImage.setDefaults({ transition: false })`. [Релізноути з повним списком](https://github.com/DylanVann/react-native-fast-image/releases/tag/v10.0.0)

Вимоги: RN 0.83+ і тільки New Architecture, Expo SDK 55+, iOS 15.1, Android API 24, SDWebImage 5.21.4+. На легасі-архітектурі лишайся на 9.

Головна новина тут — бібліотека ожила після років тиші. Якщо вже на New Arch, апгрейд вартий заходу, але `resizeMode` по проєкту доведеться вичистити руками.

## 💡 Рецепти

**Викинути з бандла невикористані API React Native — [babel-plugin-react-native-direct-imports](https://github.com/retyui/babel-plugin-react-native-direct-imports)**

`react-native` — це barrel-файл, і бандлери його не тришейкають: імпортуєш один `ReactNativeVersion`, а в бандл залітає все. Плагін переписує barrel-імпорти в прямі `require()` конкретних модулів, причому саме `require`, щоб Babel не доклав interop-хелперів.

```bash
npm install --save-dev babel-plugin-react-native-direct-imports
```

```js
// babel.config.js
module.exports = {
  presets: [
    ['module:@react-native/babel-preset', { disableDeepImportWarnings: true }],
  ],
  plugins: [
    process.env.NODE_ENV !== 'test' && [
      'react-native-direct-imports',
      { reactNativeVersion: require('react-native/package.json').version },
    ],
  ].filter(Boolean),
};
```

Далі один раз скинути кеш Metro: `npx expo start --clear` або `npx react-native start --reset-cache`.

Конфіг і команди — дослівно з README, навів цього тижня This Week In React. На npm версія 1.1.0 від 6 жовтня, автор у README прямо пише, що плагін «is in an early stage».

Обмеження звідти ж: `reactNativeVersion` має точно збігатись з мапою з `maps/`, інакше білд падає — після апгрейду RN оновлюй і плагін. `import * as RN from 'react-native'` дає помилку білда. `Platform` лишається локальною змінною, щоб Metro і далі інлайнив `Platform.OS`, але аліаси типу `Platform as P` цього не отримують. Мапи є для всіх стабільних релізів від 0.70.

Цифр економії автор не наводить — тільки скриншоти до і після плюс порада зміряти власний бандл через react-native-bundle-discovery. Тож це рецепт «спробуй і зміряй», а не гарантовані кілобайти.
