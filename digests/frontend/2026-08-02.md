## ⚛️ React

**Dominic Gannaway, автор Inferno, [представив Octane](https://octanejs.dev/) — фреймворк, який компілює програмну модель React наперед**

Ідея: лишити знайомий API — `useState`, `useEffect`, `memo`, context, portals, transitions, Suspense — але викинути віртуальний DOM і Rules of Hooks. Компілятор сам розуміє, що захоплює твій код, і генерує реактивність: масиви залежностей писати не треба, а хуки можна ставити під умовою чи після early return. Крім JSX/TSX є власний формат `.tsrx`, плюс інтеграції з TanStack, React Three Fiber, Lynx і StyleX.

• **Що замінює:** React у клієнтських апках, де впирається перформанс. `OctaneCompat` дає вбудовувати Octane-компоненти в наявну React 19 апку по шматочках.
• **Наскільки стабільно:** [README](https://github.com/octanejs/octane) не приховує — «Octane is in alpha… but APIs still move». MIT, 973 зірки. Немає класових компонентів, Server Components і синтетичних івентів; замість звичайних циклів у хуках — keyed-директиви `@for`.
• **Чим покращить:** на бенчмарках сайту Octane найшвидший, React 19 зазвичай у 2-3 рази повільніший.

![Octane](https://octanejs.dev/og-image.png)

Для React Native тут поки нічого — Octane про DOM. Але для веб-частини стеку варто хоча б погратись: це найсерйозніша спроба зберегти модель React і зняти її рантайм-податок.

## 📱 React Native та Expo

**React Native [випустили 0.87.0-rc.3](https://github.com/facebook/react-native/releases/tag/v0.87.0-rc.3), а `backgroundImage` [офіційно втрачає префікс](https://github.com/facebook/react-native-website/pull/5191) `experimental_`**

Тобто в 0.87 лінійні й радіальні градієнти працюють з коробки, без сторонньої бібліотеки. Колаборатор у тому ж треді натякає, що `experimental_` знімуть і з інших API — схоже, до стабільної 0.87 доїде ціла пачка стабілізацій.

Сам rc.3 — переважно підтягування Hermes V1 до 250829098.0.16 і dSYM-артефакти.

Апдейт до минулого тижня: 0.86.1 фактично не існує, його не опублікували через проблему з Maven. Замість нього вийшов [0.86.2](https://github.com/facebook/react-native/releases/tag/v0.86.2) з фіксом `display: contents` і синхронізації в Android-рантаймі.

Якщо тримаєш градієнти на окремій бібліотеці — на 0.87 частину з них можна буде просто видалити.

#reactnative

**[react-native-workers](https://ammarahm-ed.github.io/react-native-workers/blog/introducing-react-native-workers/) приніс у RN Web Worker API з реальними тредами** — кожен воркер це окремий Hermes-рантайм на власному OS-треді: свій event loop, свій бандл, свій GC.

```js
const worker = new Worker('./workers/heavy');
worker.onmessage = (e) => console.log('result:', e.data);
worker.postMessage({ items: 100_000 });
```

• **Що замінює:** власні нативні модулі, які писали заради фонових обчислень.
• **Наскільки стабільно:** `1.0.0-alpha` (`@ammarahmed/react-native-workers@alpha`), автор Ammar Ahmed. У доках чесно: Thread API експериментальний і API ще змінюватиметься, structured clone поки не вміє `Map`, `Set`, `RegExp`, `Error`, `BigInt`, release-білди потребують окремого налаштування бандлінгу. Треба RN 0.81.4+, перевірено на RN 0.81–0.86 і Expo SDK 54–57.
• **Чим покращить:** цифри з доків — 0.016ms на round-trip повідомлення, 143MB/s на typed arrays, парсинг лог-файлу 2.58MB за 17ms на 8 воркерах проти 54ms в один тред.

![react-native-workers](https://ammarahm-ed.github.io/react-native-workers/img/workers-social-card.png)

Альфа, тож у прод не тягнути. Але якщо в апці є важкий імпорт даних чи обробка зображень, від якої лагає скрол — це перша бібліотека, що дає такому нормальний дім.

#libraries

**Andrei Calazans [заміряв, чому перенос MMKV-записів у worklet не рятує](https://andrei-calazans.com/posts/2026-07-28-mmkv-writes-worklet-serialization-cost/)** — і опублікував цифри трьох спроб.

Вихідна проблема знайома: запис великого стору в MMKV блокує JS-тред на ~29.56ms. Логічний хід — винести у worklet. Не спрацювало:
• винести тільки запис — `createSerializableString` коштує ті самі ~29.56ms, витрати просто переїхали
• винести весь обʼєкт — ~132ms на JS-треді, бо worklet копіює кожну властивість окремо
• увімкнути Bundle Mode — ~136ms, тобто копіювання він не прискорює

Висновок автора прямий: worklet — не безкоштовний спосіб зняти роботу з JS-треда, якщо треба передати багато даних.

Варто тримати в голові поруч з react-native-workers вище: ціна виносу роботи на інший тред — це серіалізація, а не сам тред.

## 🧰 Бібліотеки й тулінг

**react-native-webgpu [доїхав до 0.8](https://github.com/wcandillon/react-native-webgpu/releases), Skia — [до 2.10.1](https://github.com/Shopify/react-native-skia/releases), і тепер вони [ділять один Dawn](https://wcandillon.github.io/react-native-webgpu/docs/integrations/react-native-skia)**

Graphite-білди Skia рендерять через Dawn — ту саму імплементацію WebGPU. Якщо в проєкті стоять обидва пакети, Skia сама знаходить react-native-webgpu і бере його Dawn замість другої копії.

Далі — обмін текстурами без копіювання в обидва боки: `Skia.getNativeDevice()` віддає вказівник, який `importDevice()` загортає у звичний `GPUDevice`; `GPUTexture.nativePointer` перетворюється на Skia-картинку через `Skia.Image.MakeImageFromNativeTexture`, а назад — `MakeNativeTextureFromImage` плюс `adoptTexture()`.

⚠️ **Міграція:** релізи тримають у lockstep — нативний білд навмисно падає, якщо Dawn-теги пакетів розійшлись, тож оновлювати обидва треба разом. [Доки інтеграції](https://wcandillon.github.io/react-native-webgpu/docs/integrations/react-native-skia)

Ще в 0.8 приїхав Jest-мок — WebGPU-код нарешті можна тестити без девайса.

Не робиш кастомної графіки — пропускай. Робиш — це той момент, коли Skia і WebGPU перестали бути двома окремими світами.

#libraries

**React Navigation 8 [навчився працювати у вебі без react-native-web](https://github.com/react-navigation/react-navigation/pull/13195)** — зміна приїхала в `@react-navigation/native@8.0.0-alpha.40`.

Для веб-збірки більше не треба тягнути `react-native-web` як залежність чи аліас. Разом з цим у липневих альфах: фікс `resetRoot`, який не завжди ресетив стан кореневого навігатора, і пачка правок під concurrent rendering.

⚠️ **Міграція:** `Link` став платформо-залежним — `numberOfLines` лишається тільки на нативі (у вебі роби CSS), `target` більше не дописує підкреслення (пиши `_blank` повністю), `style` приймає лише плоскі обʼєкти (вкладені масиви — через `StyleSheet.compose`), а застарілі `accessibilityX`-пропси прибрали на користь `aria-x`. [PR](https://github.com/react-navigation/react-navigation/pull/13195)

Це все ще альфа, але напрямок правильний: RN Web довго був найважчою частиною веб-збірки RN-проєкту.

Жорсткого дедлайну поки нема. Але якщо в апці є контент з віковими обмеженнями — це саме той сигнал, який раніше доводилось випитувати в юзера самому.

## 💡 Рецепти

**React Navigation 8 [задокументували Suspense і pending UI](https://reactnavigation.org/docs/8.x/suspense/)** — навігація через `useNavigation` чи `useLinkProps` тепер їде як React transition.

Головне рішення — куди ставити boundary. `layout` обгортає весь навігатор: поточний екран лишається видимим і клікабельним, поки новий вантажиться.

```js
const RootStack = createNativeStackNavigator({
  layout: ({ children }) => (
    <React.Suspense fallback={<LoadingPlaceholder />}>
      {children}
    </React.Suspense>
  ),
  screens: {
    Home: HomeScreen,
    Profile: ProfileScreen,
  },
});
```

`screenLayout` натомість обгортає кожен екран окремо — призначення зʼявляється одразу зі своїм fallback. Для стеків доки радять перший варіант, для табів і drawer — другий.

Щоб юзер бачив, що щось відбувається, кнопку загортають у власний transition:

```js
function LinkButton({ in: parent, screen, params, children }) {
  const { onPress, ...rest } = useLinkProps({ in: parent, screen, params });

  const [isPending, startTransition] = React.useTransition();
  const isPendingDeferred = React.useDeferredValue(isPending);

  return (
    <MyButton
      {...rest}
      loading={isPending && isPendingDeferred}
      onPress={(e) => {
        startTransition(() => {
          onPress(e);
        });
      }}
    >
      {children}
    </MyButton>
  );
}
```

`useDeferredValue` тут не для краси: без нього спінер блимає на швидких переходах. Окремо доки попереджають, що перемикання табів і нативні жести через transitions не йдуть — там fallback покажеться одразу.

Код узятий з офіційних доків 8.x. Сама v8 ще в альфі, тож на своєму проєкті перевіряти доведеться.
