## 📱 React Native та Expo

**React Native [зарелізив 0.88](https://reactnative.dev/blog/2026/10/19/react-native-0.88) — події тепер ідуть через W3C EventTarget**

Плагінну систему подій замінили на web-модель: події справді йдуть capture-шляхом до таргета і бабблять назад, `stopPropagation()` і `preventDefault()` працюють як у браузері, а не як реімплементація RN. Старий шлях лишився за внутрішнім флагом, приберуть його в наступному релізі.

Решта:
• `fontVariationSettings` на `Text` і `TextInput` — variable fonts на обох платформах
• SceneDelegate на iOS: без нього UIKit-апка, збілджена Xcode 27, просто не запуститься
• `ArrayBuffer` у Java TurboModules — бінарка без Base64 і масивів чисел
• React 19.3.0, Metro 0.87, Hermes 260318099.0.4

Breaking changes нема. Але перевір три зміни поведінки: iOS RTL тепер вирівнює текст праворуч за дефолтом, Android додав назву і версію апки в User-Agent, радіальні градієнти більше не беруть відсоткові радіуси. `InitializeCore` і `InputAccessoryView` застаріли.

З 0.87 оновлюєшся без правок у коді. А от SwiftPM варто поганяти в preview вже зараз: у 0.89 він стане дефолтом замість CocoaPods.

#reactnative

**Expo [випустив SDK 58](https://expo.dev/changelog/sdk-58) — на RN 0.88 і під iOS 27**

Перескок через 0.87: SDK тягне відразу 0.86 → 0.88.

Головне:
• iOS 27 scene-based lifecycle, prebuild генерує `SceneDelegate.swift`; апки стають resizable, `requireFullScreen` більше не рятує
• `expo-hinge` — стан завісу на iPhone Duo та Android-фолдах
• `expo-app-intents` в альфі: Siri, Shortcuts, Spotlight
• prebuilt `expo-modules-core` — clean debug-білд на Android у їхньому тесті впав з ~80 до ~39 секунд
• Expo UI отримав recycling-списки, `NavigationStack` і `NavigationSplitView`

⚠️ **Міграція:** найболючіше — Strict TypeScript API з RN 0.87: deep imports з `react-native/Libraries/*` стали type error, є тимчасовий opt-out через `customConditions`, але його приберуть після 0.89 ([гайд](https://reactnative.dev/docs/strict-typescript-api#migration-guide)). Плюс `File.write()` в expo-file-system став async, R8 увімкнено за дефолтом, Node мінімум 22.13, а ручний `ios/` переводиться на scene lifecycle [окремо](https://expo.fyi/ios-scene-lifecycle).

![Expo SDK 58](https://cdn.sanity.io/images/9r24npb8/production/ddd5bb6eddbd4b98cc546553c4aea8a8ad6be9ef-1800x1012.png)

Expo Go під 58 ще не в сторах, тож `create-expo-app` поки робить SDK 57 — новий проєкт стартуй через `--template default@sdk-58` і dev-білд. Оновлюватись раджу не в п'ятницю ввечері.

#expo

**Expo Router у SDK 58 [переписав навігаційне ядро](https://docs.expo.dev/router/migrate/sdk-57-to-58/) — це окрема міграція від самого SDK**

Стан навігації і ключі маршрутів стали детермінованими, а `navigation.dispatch` відкладається до кінця поточного React-коміту. Функції-редюсери в dispatch більше не приймаються: читаєш стан, будуєш екшен, диспатчиш.

Що ламається в типовій апці:
• `initialRouteName` прибрали — замість нього `unstable_settings` з `anchor` у лейауті стека
• `Screen` більше не бере `redirect`, `initialParams` і `navigationKey`
• таби, дровери й топ-таби показують лише оголошені в лейауті екрани; сховати маршрут — через `href: null` в options
• `freezeOnBlur` не діє, замість нього `activityEnabled`
• ancestor-параметри більше не копіюються в дочірні маршрути — передавай повний href
• `expo-symbols` і `@expo/ui` стали optional peer deps

⚠️ **Міграція:** якщо імпортуєш з `expo-router/react-navigation`, читаєш navigation state або пишеш власний роутер чи навігатор — там зміни найглибші. [Гайд із таблицею замін](https://docs.expo.dev/router/migrate/sdk-57-to-58/)

Звичайний `Stack` плюс `Link` плюс `useRouter` переживуть апгрейд кількома правками. Кастомний роутер — закладай день і читай гайд до кінця, а не по діагоналі.

#expo

**[react-native-web переходить](https://github.com/necolas/react-native-web/discussions/2872) до React Foundation — підхоплюють Expo і zoontek**

zoontek оголосив, що він, necolas, Expo і ком'юніті беруть RNW на активну підтримку. Репозиторій переїде в GitHub-організацію React Foundation — туди ж, де React і React Native. necolas назвав це «ідеальним результатом для RNW».

Практично: issues і PR почнуть тріажити, фікси поїдуть регулярними релізами. Модернізація йде в гілку `0.22-dev`, і там планують:
• мінімальні браузери вгору: Chrome/Edge 95+, Firefox 93+, Safari 15.1+
• React 19+ у peer deps, React 18 викидають
• прибрати модулі, яких уже нема в ядрі RN: CheckBox, Picker, ProgressBar, InteractionManager, старий Touchable
• Flow → TypeScript, ESM-вихід, менше залежностей
• `babel-plugin-react-native-web` депрекейтять

Дат релізу не називають, робота поки живе у форку і вливатиметься поступово. Після того, як Shopify і Coinbase пішли з RN на нативку, новина про те, що важливий кусок екосистеми хтось підбирає, а не кидає — приємний контраст. Тримаєш веб на RNW — стеж за `0.22-dev`, мінімальні браузери підскочать.

## 🧰 Бібліотеки й тулінг

**Gesture Handler [зарелізив 3.4.0](https://github.com/software-mansion/react-native-gesture-handler/releases/tag/v3.4.0) — зі збіркою через Swift Package Manager**

Одна з перших помітних бібліотек з SPM-збіркою для iOS — акурат у тему того, що RN робить SwiftPM дефолтом у 0.89.

Решта:
• новий проп `immediatePressOut` у Touchable: press-out одразу, не чекаючи анімації, з opt-out для Pressable
• на Android `onPressIn` тепер стріляє, коли починається нативний press
• Web Tap: дефолтний `maxDelay` підтягнули до нативних 200 ms, ScrollView став intercepting-детектором
• бамп до React Native 0.88

Breaking changes в релізі не заявлено. Паралельно вийшла [2.33.1](https://github.com/software-mansion/react-native-gesture-handler/releases/tag/v2.33.1) — бекпорти для тих, хто ще на 2.x: краш на touch-cancel в Android, `manualActivation` після зміни конфіга на iOS, координати трекпада на Web.

Вже на 0.88 — бери 3.4.0. Ще ні — 2.33.1 закриває рівно ті самі баги без апгрейду мажора.

**[Hot Updater](https://github.com/gronxb/hot-updater/releases/tag/v1.0.0) дійшов до 1.0 — OTA-апдейти для RN на власній інфраструктурі**

Сервер публікує каталог релізів, кожен девайс сам перевіряє і вибирає собі апдейт. Консоль хоститься на Node, Docker, Vercel, Netlify або Cloudflare Workers, логін через GitHub чи Google.

Що нового в 1.0:
• Shared Release Catalog — один кешований каталог на скоуп; медіанна перевірка апдейту впала з 301 ms у v0 до 50 ms на Cloudflare (цифри авторські)
• Insights — завантаження, запуски, crash recovery, провалені апдейти, плюс підказки по ролбеку в консолі
• Remote Config — змінювати значення в апці без нового бандла і нативного білда

⚠️ **Міграція:** це не drop-in. v1 потребує окремої інфраструктури і нового нативного білда, а старий v0-ендпоінт треба тримати живим для вже встановлених бінарників. У релізі є гайд v0 → v1 і `BREAKING_CHANGES.md`.

Наскільки стабільне: це перший стабільний реліз v1-лінії, v0 лишилась в окремій гілці. Підтримувані версії RN та Expo у релізноутах не вказані — дивись доки перед міграцією. Чим покращить: 50 ms замість 301 ms на перевірці апдейту помітно на холодному старті, а Insights закриває головний страх OTA — «розкатали і не знаємо, чи не поламали».

## 📲 Платформи і стори

**Apple [оновила App Review Guidelines](https://developer.apple.com/news/?id=92th7e5i) — і виписала окреме правило про сховані фічі**

Нове 2.5.19 (раніше було частиною 2.3.1) дослівно:

> Don't include any hidden, dormant, or undocumented features in your app; your app's functionality should be clear to end users and App Review.

Далі там же: спроба сховати недокументовані фічі в бінарнику, зокрема через обфускацію коду, — підстава викинути апку зі стору і закрити девелоперський акаунт.

Решта змін: нове 2.3.14 про creative assets (можна показувати не лише скриншоти — і на продуктовій сторінці, і в пошуку), 1.2 розширили на non-consensual intimate imagery включно з AI-генерованим, 3.1.1(a) переписали щодо External Purchase Link. Переклади обіцяють протягом місяця.

Для RN-розробника тут цікавий кут OTA. Правило говорить не про апдейти як такі, а про функціональність, приховану від ревʼю. Але якщо ти розкатуєш фіча-флаги через OTA і вмикаєш їх уже після апруву — формулювання «dormant features» тепер стоїть у гайдлайнах окремим пунктом, а не в примітці до 2.3.1.

## 💡 Рецепти

**Увімкнути Rust-трансформер Noxcturnal в Expo SDK 58 — і не вляпатись у вічний білд**

SDK 58 привіз експериментальний трансформер на Rust/oxc. Цифри з [анонсу](https://expo.dev/changelog/sdk-58): per-module трансформ приблизно 3× швидше, cold bundling приблизно 2× — на їхньому найбільшому тестовому апці бандл з ~5500 файлів впав з 5.26 до 2.46 секунди, при тому що 443 файли все одно відпали на Babel.

Вмикається флагом `experiments.noxcturnalTransformWorker` в app config:

```json
{
  "expo": {
    "experiments": {
      "noxcturnalTransformWorker": true
    }
  }
}
```

Шлях ключа — дослівно з анонсу Expo, булева форма — як у решти флагів `experiments` у [доках app config](https://docs.expo.dev/versions/latest/config/app/). Сам я цього не ганяв.

Два застереження з реальних джерел. Перше: `npx expo-doctor` поки не знає цього ключа і сварить —

```
Field: experiments - should NOT have additional property 'noxcturnalTransformWorker'
```

Друге, серйозніше: [issue #51355](https://github.com/expo/expo/issues/51355) — підтверджений Expo баг, коли воркер вішається назавжди: один потік на 100% CPU, Metro не падає і не таймаутиться. Тригер — цикл, у голові якого є функція, що оголошує `let` чи `const`; react-hook-form 7.89.0 у залежностях уже достатньо, щоб бандл не зібрався ніколи. Причина — нативний `blockScoping` у noxcturnal, воркераунд один: прибрати флаг.

І ще: трансформер взагалі не вмикається, якщо в проєкті є кастомний transform worker або свої Babel-плагіни та пресети, а файли, яким потрібні Babel-трансформи Reanimated чи Worklets, він пропускає.

Для чистого проєкту без кастомного Babel це майже безкоштовні 2× на холодному бандлі. Для будь-якого реального — почекай, поки закриють #51355.
