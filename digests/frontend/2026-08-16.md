## 📱 React Native та Expo

**React Native [зарелізили 0.87.0](https://reactnative.dev/blog/2026/08/11/react-native-0.87) — після чотирьох RC стабільна версія на місці**

Чотири головні зміни:
• Strict TypeScript API став дефолтним JS API. Типи тепер генеруються з сорсів RN, а не пишуться руками окремо — дрейф між типами і кодом закінчився
• Metro підняли з 0.84 до 0.87: генерація сорсмапів удвічі швидша, памʼяті вдвічі менше. Зʼявилась стабільна підтримка TS/ESM-конфігів на кшталт `metro.config.mts`
• Експериментальна підтримка Swift Package Manager на iOS — Xcode без Ruby, Bundler і CocoaPods, і без `pod install` після кожної зміни залежностей
• Перший реліз з підтримкою Android Gradle Plugin 9

Мінімалка підросла: Node.js 22.13.0, Kotlin 2.0, compileSdk 37. AGP 9 автори поки радять вимикати через `android.builtInKotlin=false` і `android.newDsl=false`.

⚠️ **Міграція:** deep imports у `react-native/Libraries/*` тепер помилка типів, рефи переїхали на окремі типи (`ViewInstance`, `TextInputInstance`), викинули `InteractionManager`, `DrawerLayoutAndroid` і `useTurboModules`. [Гайд](https://reactnative.dev/docs/strict-typescript-api#migration-guide)

Оновлюватись варто, але не в пʼятницю: Metro і типи дадуть реальний виграш, а SwiftPM поки експеримент і в прод його не тягни. 0.84.x за [support policy](https://github.com/reactwg/react-native-releases/blob/main/docs/support.md) переїхала в unsupported — це вже дедлайн, а не порада.

**Expo [випустили 57.0.9](https://expo.dev/changelog/sdk-57) і закрили memory-регресію Hermes V1, що приїхала ще з SDK 56**

Патч підтягує React Native до 0.86.2. У changelog прямо написано, що регресія «could drastically increase memory usage in apps importing `react-native-worklets` or `react-native-reanimated`» — тобто зачіпає майже кожну апку з анімаціями.

Формулювання Expo однозначне: оновитись до 57.0.9 або новішої для таких апок «crucial».

Це той випадок, коли патч важливіший за мажор. Якщо ти на SDK 56 або 57 і в залежностях є Reanimated — став апдейт сьогодні, не чекаючи наступного спринту.

#expo

**Expo [завезли свій MCP-сервер у директорію конекторів Claude](https://expo.dev/changelog/connect-expo-in-claude) — тепер це підключення в один клік замість ручного конфіга**

Логінишся Expo-акаунтом на сторінці конектора один раз, і зʼєднання тримається. Далі з чату можна запускати продакшен-білди і дивитись їх статус, відправляти збірки в TestFlight, читати crash-репорти і фідбек з TestFlight, дивитись відгуки в App Store і Google Play та відповідати на них.

Більшість тулів ходить в EAS і стори віддалено, тому працюють з будь-якого пристрою — веб, десктоп, мобілка, Claude Code. Локальні речі на кшталт скріншотів і тап-автоматизації, як і раніше, вимагають запущеного dev-сервера поруч із симулятором. Ручний сетап через CLI нікуди не подівся.

Найкорисніше тут не генерація коду, а рутина навколо релізу: подивитись, чи не впав білд, і відповісти на відгук — не перемикаючись у три різні дашборди.

## 🧰 Бібліотеки й тулінг

**Gesture Handler [випустили 3.2.0](https://github.com/software-mansion/react-native-gesture-handler/releases/tag/v3.2.0) — `Pressable` тепер побудований поверх `Touchable`, а не поверх `GestureDetector`**

Рефакторинг проїхався по всіх трьох платформах одразу: на Android, iOS і в вебі `Touchable` більше не тягне за собою `GestureDetector`. Разом з цим у `Touchable` завезли hover-колбеки на всіх платформах.

З платформенного: на Android адаптували AGP v9 (той самий, що й у RN 0.87), на iOS полагодили доставку тач-івентів у віртуальні детектори і гарантії виклику колбеків, коли вʼюха відʼєднується. У вебі пофіксили розрахунок `timeDelta` і зміщення в Tap.

Явних breaking changes у нотатках немає, але рефакторинг глибокий. Якщо в тебе кастомні жести навколо `Pressable` — оновлюйся на тестовій гілці й прокликай сценарії руками. За день вийшов ще й [3.2.1](https://github.com/software-mansion/react-native-gesture-handler/releases/tag/v3.2.1) з фіксом проброшування press-хендлерів, тож бери одразу його.

#libraries

**Software Mansion [зарелізили Worklets 0.12.0](https://github.com/software-mansion/react-native-reanimated/releases/tag/worklets-0.12.0) — на Worklet Runtimes завезли `WeakRef`**

Зробили це через увімкнення мікротаск-черги Hermes і її дренаж з C++ боку. Ще дві зміни:
• завантаження скриптів у Bundle Mode привели до того ж підходу, що і в самому RN: локальні бандли тепер memory-mapped, а на Android дев-сервер стрімить у кеш-файл замість тримати все в памʼяті
• новий параметр `enableLocking` у `createWorkletRuntime` дає створити рантайм без mutex-гардів — для просунутих сценаріїв з тред-безпекою

⚠️ **Міграція:** прибрали deprecated sync API у `WorkletRuntime`. [Реліз](https://github.com/software-mansion/react-native-reanimated/releases/tag/worklets-0.12.0)

`WeakRef` у воркletах — це нарешті нормальна робота з кешами і слухачами без вічних лійків. Якщо сидиш на 0.11.x і сінк-API не юзаєш, перехід має бути безболісним.

**TanStack [показали Form v2 alpha](https://tanstack.com/blog/announcing-tanstack-form-v2-alpha) — валідатори переїхали з обʼєктів-по-івентах на пайплайн**

Що змінилось порівняно з v1:
• кожен валідатор — окремий запис, який сам декларує, які івенти його тригерять; кілька валідаторів можуть ділити один тригер без дублювання
• listeners переїхали на ту саму модель, плюс отримали умовний запуск через `when`
• три режими роботи зі схемами: базовий як у v1, `strictSchema` (схема — джерело правди) і `looseSchema` (пускає null/undefined з дефолтів)
• серверна валідація тепер живе прямо в спільних `formOpts` — без ручного мерджу стану і втрати типів

Бібліотека headless і, за [доками](https://tanstack.com/form/latest/docs/framework/react/guides/react-native), працює в React Native out-of-the-box. Але це альфа й поки тільки React: автори пишуть, що хочуть «iron out the first round of issues» перед портом на інші фреймворки. Персистенс форми і submit meta ще не завезли.

Дивитись варто, ставити в прод — ні. Якщо в тебе на v1 болить саме мультитригерна валідація, є [гайд по міграції](https://tanstack.com/form/alpha/docs/migrate-from-v1).

Якщо релізишся в Кореї — перевір, які дескриптори проставлені в App Store Connect, бо восени рейтинг може стрибнути сам собою і зрізати частину аудиторії. ## 💡 Рецепти

**Як пережити Strict TypeScript API в RN 0.87, якщо мігрувати зараз нема часу — команда RN описала і автоматичну міграцію, і аварійний вимикач у [гайді](https://reactnative.dev/docs/strict-typescript-api#migration-guide)**

Спершу спробуй агентний скіл — він тягне інструкції міграції поверх наявних ESLint-фіксерів:

```bash
npx skills add react-native-community/skills --skill migrate-to-strict-api
```

Не злетіло або помилок надто багато — тимчасово поверни старі типи через custom condition у `tsconfig.json`:

```json
{
  "extends": "@react-native/typescript-config",
  "compilerOptions": {
    "customConditions": ["react-native", "react-native-legacy-deep-imports"]
  }
}
```

Найчастіші ручні правки з гайду:

```diff
- import 'react-native/Libraries/Core/InitializeCore';
+ import 'react-native/setup-env';

- const inputRef = useRef<TextInput>(null);
+ const inputRef = useRef<TextInputInstance>(null);
```

Джерело — офіційні доки RN 0.87, команди і снипети взяті звідти дослівно. Автори окремо радять лишити `skipLibCheck: true` і спершу оновити залежності: частину помилок закриють самі бібліотеки.

Важливо: вимикач працює тільки до React Native 0.88 включно. Це відстрочка на один реліз, а не рішення — плануй міграцію в наступний спринт.
