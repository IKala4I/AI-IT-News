## ⚛️ React

**React [увімкнув `enableParallelTransitions` за замовчуванням](https://github.com/facebook/react/pull/37290) — у canary і в усіх хардкоджених форках, включно з RN**

Раніше React схильний був сплутувати (entangle) transition-лейни між собою: два незалежні transition'и комітились разом, навіть коли між ними немає жодної залежності. Тепер React повертає лейн з найвищим пріоритетом замість того, щоб зливати всі transition-лейни в один — і незалежні transition'и завершуються окремо.

Флаг додали ще в лютому, «щоб поекспериментувати з рідшим entangling». Тепер його перевели в дефолт OSS/canary і в native (RN) форки; www у Meta лишається на власному GK. Аргумент на користь пропуску стадії `__EXPERIMENTAL__` простий: воно вже крутиться в проді Meta.

Змерджили це 14 серпня, але в ньюслетери й canary воно доїхало щойно. У стабільних React і RN зміни ще немає — але якщо ти десь покладався на те, що два `startTransition` комітяться разом, перевірити варто заздалегідь.

## 📱 React Native та Expo

**React Native [випустив 0.87.1](https://github.com/facebook/react-native/releases/tag/v0.87.1) — з фіксом крашу «Wrong bytecode version» у релізних білдах**

Головне: розʼїхались версії Hermes-рантайму і компілятора, через що релізна збірка падала. Hermes підняли до 250829098.0.17.

Решта:
• типи `Animated` перестали бути `any` — `Animated.Value.addListener()` тепер типізує пейлоад як `{value: number}`, `Animated.event()` — як хендлер події
• SwiftPM: зрозуміла помилка замість тиші, коли autolinking-плагін вказано як залежність, розбір колізій імен у Swift-маніфестах
• CocoaPods: header search paths з пробілами більше не втрачають лапки

Паралельно [0.86.3](https://github.com/facebook/react-native/releases/tag/v0.86.3) полагодив вагу кастомних шрифтів на New Architecture — рендерилось максимальною вагою незалежно від `fontWeight`. А [Expo 57.0.17](https://expo.dev/changelog/sdk-57) підтягнув цей 0.86.3 і закрив регресію Hermes V1, що збільшувала час старту в деві.

Якщо ти на 0.87 — оновлюйся без роздумів: краш у релізному білді це не те, з чим живуть до наступного мінора.

#reactnative

**Margelo [розповіли, як Expensify переїхав на NitroFetch](https://margelo.com/blog/speeding-up-expensifys-networking-with-nitro-fetch) — і показали цифри**

• **Що замінює:** вбудований мережевий стек RN разом з його `fetch` (у RN це JS-полифіл). `react-native-nitro-fetch` — WHATWG-сумісна реалізація на Nitro Modules, яка ганяє запити через Cronet на Android і URLSession на iOS. HTTP/3, стрімінг, префетч, парсинг JSON поза JS-тредом.
• **Наскільки стабільно:** останній реліз 1.6.3 від 26 серпня, вимога — RN 0.75+. У Expensify увімкнено глобально в проді.
• **Чим покращить:** середня тривалість запиту менша на 15–30%. Теплий старт P50 на iOS: 1676 → 1409 мс, на Android: 3223.5 → 2573 мс.

Підводні камені автори не ховають: на Android потрібна ручна ініціалізація в `Application.onCreate()` до завантаження RN, а certificate pinning довелось реалізовувати окремо — Cronet не успадковує пінів OkHttp.

## 🧰 Бібліотеки й тулінг

**Arunabh Verma зробив [expo-paste-input](https://github.com/arunabhverma/expo-paste-input) — вставку картинок, гіфок і стикерів у звичайний `TextInput`**

• **Що замінює:** старі рішення для paste-івентів, які поламались після переїзду на New Architecture. Це тонкий врапер навколо рідного `TextInput`, а не свій власний компонент.
• **Наскільки стабільно:** iOS і Android працюють, на вебі — no-op заглушка, щоб імпорт не валив збірку. Expo Go не підтримується, потрібен ребілд нативу. Автор прямо пише, що URI вставлених картинок тимчасові — хочеш зберегти, копіюй сам.
• **Чим покращить:** нативний paste у чаті без окремого пікера і без форку `TextInput`.

```jsx
import { TextInputWrapper } from "expo-paste-input";
import { TextInput } from "react-native";

<TextInputWrapper onPaste={(payload) => console.log(payload)}>
  <TextInput placeholder="Paste here..." />
</TextInputWrapper>
```

Типи пейлоада — `"text"`, `"images"` або `"unsupported"`. Ставиться через `npx expo install expo-paste-input`.

![expo-paste-input](https://cdn.sanity.io/images/9r24npb8/production/2719b7938b17350b92d9b8c4168226378e39b41a-2400x1350.png)

Якщо в тебе чат — це рівно та дірка, яку всі затикають костилями. Тут вона закрита однією обгорткою, і виглядає це чесніше за форк.

#libraries

**TanStack Query [у 5.102 додав `query()` і `infiniteQuery()`](https://github.com/TanStack/query/releases/tag/release-2026-08-22-1856) — прості імперативні методи замість зоопарку `fetch*`**

Нові методи на `QueryClient` віддають кешовані дані, коли вони є, поважають `select`, `enabled` і `queryFn === skipToken`, і кидають помилку, якщо запит вимкнено, а віддати нічого. Додався `staleTime: 'static'` — «візьми тільки з кешу, в мережу не лізь».

⚠️ **Міграція:** `fetchQuery`, `fetchInfiniteQuery`, `prefetchQuery`, `ensureQueryData` і `ensureInfiniteQueryData` позначені deprecated. Порядок дженериків у `query()` збережено від `fetchQuery()`, тож заміна здебільшого механічна — [PR з деталями](https://github.com/TanStack/query/pull/10658).

Ламати нічого не поспішають, deprecated поки що просто deprecated. Але якщо ти прогріваєш кеш перед навігацією через `prefetchQuery`, переїхати варто зараз, поки це один sed.

## 📲 Платформи і стори

**Apple [міняють домен для Sign in with Apple](https://developer.apple.com/news/?id=1ptvdtcm) — нові адреси видаватимуть на `private.icloud.com`**

Що змінюється: relay-адреси, які раніше видавались на `privaterelay.appleid.com`, поїдуть на новий домен. Старі продовжать працювати і форвардити пошту без перерв. Hide My Email в iCloud+ після фідбеку ком'юніті лишається на `icloud.com`.

Що робити: перевірити, що бекенд, валідація email і allowlist'и приймають обидва домени. Дату Apple називають розмито — «пізніше цього року».

Для RN це не про клієнт, а про твій сервер і будь-яку регулярку, яка колись матчила `privaterelay.appleid.com`. П'ять хвилин роботи зараз проти зламаної реєстрації через пів року.

## 💡 Рецепти

**Витягнути перший запит апки за межі JS-старту через NitroFetch**

Ідея з розбору Expensify: нативний код стартує запит ще до того, як завантажився JS-бандл, а `fetch()` потім усиновлює готову відповідь замість того, щоб починати з нуля.

Ставиться в пару:

```bash
npm i react-native-nitro-fetch react-native-nitro-modules
```

Реєструємо запит, який має піти на наступному старті:

```js
import { prefetchOnAppStart } from 'react-native-nitro-fetch'

await prefetchOnAppStart('https://httpbin.org/uuid', {
  prefetchKey: 'uuid'
})
```

Разовий префетч у межах сесії — так:

```js
import { prefetch } from 'react-native-nitro-fetch'

await prefetch('https://httpbin.org/uuid', {
  headers: { prefetchKey: 'uuid' }
})
```

Три обмеження, названі в джерелах прямо: працює з другого холодного старту (JS має один раз відпрацювати і засіяти чергу); матчинг за `prefetchKey` строгий — URL і body мають описувати ідентичний запит; на Android потрібна явна ініціалізація в `Application.onCreate()` до завантаження RN. У Expensify в allowlist був рівно один запит — `ReconnectApp`.

Звідки: код дослівно з [README](https://github.com/margelo/react-native-nitro-fetch/blob/main/README.md), механіка і застереження — з [розбору Margelo](https://margelo.com/blog/speeding-up-expensifys-networking-with-nitro-fetch).
