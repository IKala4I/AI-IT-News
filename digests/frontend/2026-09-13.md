## ⚛️ React

**React [зарелізив 19.3](https://react.dev/blog/2026/09/09/react-19-3) — ViewTransition, Fragment Refs і `use(browser())` нарешті стабільні**

Що доїхало в stable:
• `<ViewTransition>` плюс `addTransitionType` — анімації входу, виходу і переїзду через браузерний View Transition API
• `ref` на `<Fragment>` — `FragmentInstance` вміє `focus()`, `addEventListener`, `observeUsing()` з Intersection/ResizeObserver і `getClientRects()`
• `browser()` з `react-dom` — компонент, який рендериться тільки в браузері, без танців з `useEffect` і `mounted`-стейтом

Тихіша, але приємна зміна: транзишени тепер рендеряться незалежно, тож повільний більше не тримає решту.

Головний нюанс для нас: `ViewTransition` поки що DOM-only, підтримка в React Native, за словами команди, «in development». Fragment Refs теж живуть у react-dom.

На вебі оновлюватись можна вже — `npm install react@19.3 react-dom@19.3`. У RN чекаємо, поки рендерер підтягнеться.

## 📱 React Native та Expo

**React Native [випустив 0.88.0-rc.0](https://github.com/facebook/react-native/releases/tag/v0.88.0-rc.0) — зі SwiftPM-тулінгом і `fontVariationSettings`**

Що всередині:
• `npx react-native spm` — генерація SwiftPM-пакетів, opt-in, CocoaPods нікуди не зникає
• `fontVariationSettings` для `Text` і `TextInput` на обох платформах, з object-синтаксисом
• нові umbrella-хедери `<React/FeatureFlags.h>`, `<React/RendererBridging.h>`, `<React/Timing.h>` — продовження того RFC про рівні C++ API, про який писали минулого тижня
• SceneDelegate-лайфцикл на iOS, pull model mounting на Android за флагом `enableMountingCoordinatorPullModelAndroid`
• у DevTools — скріншоти в перформанс-треку (experimental) і WebSocket-івенти в Network-панелі (canary)

⚠️ **Міграція:** codegen тепер емітить `RCTArrayBuffer *` замість `NSMutableData *` для TurboModule-методів, що приймають або віддають ArrayBuffer. Якщо ти підхопив ObjC ArrayBuffer ще в 0.87 — модуль не збереться без правок. [Changelog](https://github.com/facebook/react-native/blob/main/CHANGELOG.md)

Це RC, не stable — на проді чекаємо. Але якщо маєш свій нативний iOS-модуль з ArrayBuffer, зібратись проти RC варто вже зараз.

#reactnative

**Expo [показали ранній Modules 2.0](https://expo.dev/blog/an-early-look-at-expo-modules-2-0) — нативний модуль без DSL і до 5.6× швидші виклики**

Замість `definition()` з result-білдерами модуль стає звичайним анотованим класом: `@ExpoModule` на клас, `@JS` на методи і властивості, плюс `@Record`, `@SharedObject` і `@Event`. Async-методи самі стають Promise, а Swift `var`/`let` — writable і read-only властивостями.

Бенчмарк авторів, iPhone 16 Pro, 100 000 викликів у Release:
• sync no-op — 9 ms проти 52 ms на 1.0
• додавання даблів — 19 ms проти 97 ms
• конкатенація рядків — 48 ms проти 121 ms

Виграш у тому, що макрос `@JS` читає сигнатури на етапі білду, а не через рантайм-рефлексію.

Статус чесний: макроси вже лежать у SDK 57 для iOS, але автори пишуть — «they're not documented yet, so consider them experimental: the API can still change». Офіційна бета буде в SDK 58, Android ще в роботі. Мігрувати можна поступово: 1.0 і 2.0 співіснують в одному модулі.

Пишеш нативні модулі — подивись на форму API зараз, щоб потім не переписувати наосліп. У прод — після SDK 58.

## 🧰 Бібліотеки й тулінг

**React DevTools [готують 8.0](https://github.com/facebook/react/blob/main/packages/react-devtools/CHANGELOG.md) — Suspense-таб за замовчуванням і мінус Timeline-профайлер**

Головне з ченджлогу:
• Suspense-таб увімкнено з коробки: видно, що саме підвісило компонент, без окремих флагів
• панель React Element — інспектиш DOM-ноду в Elements і бачиш відповідний React-компонент
• Activity-сабтрі показуються притемненими, зʼявився список іменованих Activity

⚠️ **Міграція:** таб Timeline profiler прибрали. У ченджлозі прямо: «To profile React, use your browser's Performance panel — it includes React tracks».

Ченджлог датований 8 вересня і вже змерджений, але в npm і екстеншн-сторах релізу ще немає — [TWIR](https://thisweekinreact.com/newsletter/296) пише, що оновлені DevTools «coming soon». Поруч визріває експериментальний пакет `react-devtools-cdt-mcp`, який віддає React-тули в Chrome DevTools через MCP, щоб агент міг сам профайлити апку.

Якщо ти жив у Timeline — час переучуватись на Performance-панель. Для RN-дебагу поки нічого не ламається.

**[QuickJS для React Native](https://github.com/react-native-quickjs/quickjs) — спроба викинути Hermes зовсім**

Що робить і що замінює: JSI-рантайм на QuickJS, який компілюється з сорсів під час білду і стає єдиним движком у застосунку — без Hermes і без JSC. Для бібліотек, які чекають саме на Hermes, є compat-шим приблизно на 100 KB.

Чим може покращити: на Android залежність JSC важить близько 10 MB на архітектуру, і її прибирають повністю. Бенчмарків швидкості автори не дають, тож обіцянка тут рівно одна — розмір.

Наскільки стабільно: у README чесно написано «Alpha. See Known limitations. Breaking changes are expected.», у npm пакет живе під тегом `@alpha`. Вимоги — RN 0.85+, iOS 15.1+, Android 7.0+. З відомого: на iOS RN core збирається з сорсів, тож білди довші; умовні брейкпоінти не обчислюються і спиняють завжди; сам RN патчиться під час інсталу пʼятьма воркараундами, які поламаються, якщо RN зміниться.

Подивитись цікаво, ставити в прод — рано. Патчинг RN на інсталі це та річ, яка вибухає на найближчому мінорі.

## 📲 Платформи і стори

**Apple [відкрила прийом застосунків](https://developer.apple.com/news/?id=k1mtkt1k) під iOS 27 і решту нових ОС**

Збирати треба на Xcode 27 RC. Крім самого факту, звідти два дедлайни в календар:
• з квітня 2027 сабмішени вимагатимуть iOS 27 / iPadOS 27 / tvOS 27 / visionOS 27 / watchOS 27 SDK або новіший
• macOS 27 — тільки Apple silicon, Intel-Маки на неї не оновляться; Apple радить ставити build architecture в `arm64` і перевипускати. Це той самий сюжет з Rosetta, про який писали минулого тижня, тепер із прив'язкою до релізу

Ще зʼявилось питання про social-media можливості в age rating — відповісти треба в App Store Connect, інакше рейтинг не проставиться.

RN-нику зараз актуальне одне: перевірити, що CI збирає на Xcode 27 і що жоден нативний модуль не відвалився. Квітень 2027 далеко, але Xcode-апгрейд краще робити не в останню ніч.

**Google [переробив ADB по Wi-Fi](https://android-developers.googleblog.com/2026/09/wireless-debugging-adb-wifi-2.html) — новий mDNS-стек замість Bonjour і +66% до швидкості конекту**

Переписали всі три частини: сервер `adb`, демон `adbd` і Android Studio. Замість Bonjour і легасі-mDNS — власний стек, який переживає зміни мережі. Демон сам вимикає ADB Wi-Fi у недовіреній мережі й вмикає назад у дозволеній.

Цифри від Google: успішність автоконекту виросла на 32%, швидкість конекту — на 66% для 90% зʼєднань.

Щоб це працювало, треба Android 17 на девайсі, SDK Platform-Tools 37.0.0 і Android Studio Quail 3+. Далі Developer options → Wireless debugging, а в Device Manager — іконка pair over Wi-Fi і QR-код.

Вимоги кусючі: Android 17 поки що мало в кого. Але якщо тестуєш на свіжих Pixel, підтягнути platform-tools точно варто — дротом тягати девайс набридло всім.

## 💡 Рецепти

**Згенерувати скриншоти для App Store і Google Play однією командою**

[Goldie](https://github.com/kacperkapusciak/goldie) ганяє апку по симулятору чи емулятору, знімає флоу, обрамляє девайс-безелями і перевіряє результат проти правил сторів. Framework-agnostic: React Native, Flutter, SwiftUI, Compose, KMP.

```bash
npm i -g goldie

goldie doctor   # перевіряє тули і симулятори
goldie all      # знімає, обрамляє, рендерить
goldie studio   # превʼю і редагування асетів
```

Є і скіл для агентів — тоді достатньо сказати «create app store screenshots using goldie»:

```bash
npx skills add kacperkapusciak/goldie
```

Звідки це: команди з README самого проєкту, не з особистого досвіду. Автор окремо попереджає, що потрібен Release-білд і що флоу падають, коли апка змінюється.

Ручне перезняття скриншотів під кожен розмір екрана — рівно та рутина, яку гріх не автоматизувати. Але закладай час на підтримку флоу після кожного релізу з помітними UI-змінами.
