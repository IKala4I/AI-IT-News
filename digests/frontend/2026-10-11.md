## ⚛️ React

**Jenna Smith [перевірила на бенчмарку](https://jjenzz.com/making-react-context-cheap/), чи потрібні ще context-селектори, коли є React Compiler**

Сетап: 5000 радіо-кнопок у продакшен-білді, один контекст із вибраним значенням, p95 у Chrome на M3 Pro. Три підходи — стор на `useSyncExternalStore`, контекст із memo-обгорткою і просто контекст під компілятором.

Час на клік, 1× / 4× CPU throttling:
• `useSyncExternalStore` — 19.2 / 64.9 ms
• контекст + memo — 18.9 / 72.6 ms
• контекст + компілятор — 18.4 / 63.6 ms

Компілятор не прибирає ререндери: усі 5000 радіо рендеряться на кожен клік. Але він перевикористовує JSX і проміжні значення там, де інпути не змінились, тож сам рендер стає майже безкоштовним.

Автор чесно позначає, що бенчмарки генерував Codex і тест вузький. Висновок усе одно практичний: з увімкненим компілятором тягнути окремий стор лише щоб обійти ререндери контексту — вже не обовʼязково.

## 📱 React Native та Expo

**React Native Skia [зарелізила 3.0](https://github.com/wcandillon/react-native-skia/releases/tag/v3.0.0) — повністю на Graphite і Vulkan**

Що під капотом:
• рендер через Skia Graphite на Dawn — Metal на Apple, Vulkan на Android замість OpenGL ES
• бінарники приїжджають окремими npm-пакетами (`react-native-skia-graphite-android` і `-apple-*`), нативні білд-системи резолвлять їх самі
• drawing API не змінився — компоненти і хуки ті самі
• пакет змінив скоуп: `@shopify/react-native-skia` спиняється на 2.14, далі це просто `react-native-skia`

За тиждень після 3.0 уже 3.3.0: snapshot API, Graphite на Mac Catalyst, фікс Vulkan shared-fence на Android.

⚠️ **Міграція:** нова назва пакета, Android minSdk 26, iOS 15.1, прибрали пропси `debug`, `colorSpace` і `androidWarmup`; tvOS і Android TV лишаються на v2. [Гайд](https://wcandillon.github.io/react-native-skia/docs/getting-started/migration/), покроково — у рецепті нижче.

Темп патчів високий, тож якщо Skia у тебе на критичному екрані — почекай тижнів зо два. Якщо tvOS, то взагалі нікуди не йдеш.

**Expo [навчив Observe ловити нативні краші](https://expo.dev/changelog/native-crash-reporting-in-eas-observe), а не тільки JS-помилки**

До цього `expo-observe` бачив лише JS-рівень. Тепер у ту ж панель приїжджає те, через що апка просто зникає з екрана без жодного JS-стектрейсу:
• Android — неперехоплені Java/Kotlin-виключення плюс системні crash records з Android 11+
• iOS — Mach exceptions (`EXC_BAD_ACCESS`), Unix-сигнали (`SIGSEGV`), неперехоплені Objective-C і Swift

Нативні краші лежать поруч із JS-помилками, фільтруються за джерелом і показують стектрейс, записи сесії перед падінням і розбивку за версією, ОС, девайсом і країною. Є кнопка «Hand off to AI», яка віддає краш із контекстом у Claude Code або Codex.

Сетапу не треба, умова одна: `57.0.21` або новіший на SDK 57. Фіча позначена як preview.

Якщо ти вже на Observe — це безкоштовне розширення покриття за ціною бампу версії. Якщо тримав Sentry саме через нативні краші — принаймні зʼявився предмет для порівняння.

## 🧰 Бібліотеки й тулінг

**Vite [закрив три дірки](https://github.com/vitejs/vite/security/advisories) у файловому доступі дев-сервера і бекпортнув фікси на всі живі ветки**

Два advisories moderate (CVSS 6.3) і один low:
• на non-Windows імпорт, чий шлях збігається з абсолютним системним, віддавав файл поза `server.fs.allow` — [GHSA-rq7h-c2jc-7f22](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22)
• запит із `?vite-wasm-instance` зливав перші 4 байти файлу поза `server.fs` через текст помилки парсингу WebAssembly — [GHSA-vfpm-58rq-9qcg](https://github.com/vitejs/vite/security/advisories/GHSA-vfpm-58rq-9qcg)
• виконання скрипта з чужого origin через кастомний middleware — [GHSA-9jrq-w75r-8gcw](https://github.com/vitejs/vite/security/advisories/GHSA-9jrq-w75r-8gcw)

Пропатчені: 8.3.3, 8.2.4, 8.1.6, 7.3.7, 6.4.4, а також `vite-plus` 1.1.0.

Усі три працюють тільки коли дев-сервер відкритий у мережу — тобто той самий `--host`, щоб глянути збірку з телефона чи з іншої машини. Кейс настільки побутовий, що оновлятись варто сьогодні, а не «як дійдуть руки».

**TanStack [зарелізив Charts 1.0](https://tanstack.com/blog/tanstack-charts-1-0) — графіки з марок і скейлів, а не з готових типів чартів**

Заміна react-charts того ж автора, але побудована інакше: замість «вибери line chart» ти складаєш графік із марок (line, point, bar) і скейлів, а типи тягнуться від даних через скейли до марок і інтеракцій. Ідейно — Grammar of Graphics та Observable Plot.

Конкретика: пакет `@tanstack/charts`, React-адаптер у `@tanstack/charts/react`, рендер у SVG за замовчуванням, Canvas — через `@tanstack/charts/canvas` і `canvasChartRenderer`. Бібліотека нарізана на дрібні частини, щоб не роздувати бандл; анімацій у коробці немає — додаєш сам.

Наскільки стабільно: Таннер пише, що «1.0 ultimately means I'm ready to support people building on this API», і що майбутні зміни API йтимуть з міграційним шляхом. RN-адаптер у доках прямо позначений як experimental.

На вебі можна брати вже. На RN — тільки якщо готовий жити з експериментальним адаптером.

#libraries

**Unistyles [випустив 3.5.0](https://github.com/jpudysz/react-native-unistyles/releases/tag/v3.5.0) — реліз суто про стабільність**

Жодної нової фічі, зате майже два десятки фіксів, і серед них болючі:
• `updateTheme` та інлайн-пропси більше не губляться — Unistyles перестав перезаписувати вивід рендера React
• розмороження екранів більше не блокує JS на секунди
• поправили reference cycle між `StyleSheet` і `Unistyle`, який течив памʼяттю на кожен релоуд
• `useUnistyles`, `withUnistyles`, `Display` і `Hide` знову реагують на зміну орієнтації
• на AGP 9 Android більше не підключає Kotlin-плагін явно, бо він там уже вбудований

Плюс швидший лукап стилів і фікс білд-помилки `parseUnprocessedTransformOriginString` на RN нижче 0.85.

Breaking changes немає, тож якщо ти на 3.x — апдейт без роздумів. Список полагодженого підозріло схожий на список відкритих issues у середньому проєкті з Unistyles.

## 💡 Рецепти

**Перевести проєкт на [`react-native-skia` 3](https://wcandillon.github.io/react-native-skia/docs/getting-started/migration/), не зламавши білд**

Пакет змінив скоуп, тож це не звичайний бамп. Усе нижче — дослівно з офіційного гайду міграції, станом на 3.3.0; на своєму проєкті не перевіряв.

```bash
yarn remove @shopify/react-native-skia
yarn add react-native-skia
```

На Expo — через `expo install`, плюс `expo-build-properties`, бо Expo Go досі носить нативний код v2 і v3 там не запуститься: потрібен dev-білд.

```bash
npx expo install react-native-skia expo-build-properties
```

Android minSdk 26 — у плагінах Expo-конфіга:

```json
["expo-build-properties", { "android": { "minSdkVersion": 26 } }]
```

Або в `ext`-блоці `android/build.gradle` для bare:

```groovy
buildscript {
    ext {
        minSdkVersion = 26
    }
}
```

Jest теж переїжджає:

```js
testEnvironment: "react-native-skia/jestEnv.js",
setupFilesAfterEnv: ["react-native-skia/jestSetup.js"],
```

У `transformIgnorePatterns` заміни `@shopify/react-native-skia` на `react-native-skia`.

Три граблі з гайду: не тримай обидва пакети одночасно (вони несуть один нативний модуль); `react-native-webgpu` оновлюй разом зі Skia, бо розбіжність версій Dawn валить білд; скриншот-тести перезніми — Graphite рендерить трохи інакше за v2. Після апгрейду — `pod install`.
