## 📱 React Native та Expo

**React Native [випустив 0.88.0-rc.3](https://github.com/facebook/react-native/releases/tag/v0.88.0-rc.3) — останній RC перед стабільною**

Реліз майже повністю про фікси:
• Hermes піднявся до 260318099.0.4 — прибрали квадратичний `reserve()` у `ConsecutiveStringStorage` під час lazy compilation
• `androidx.collection` до 1.4.4 — більше не губляться дані view registry в `SurfaceMountingManager`
• SwiftPM-автолінкінг перестав перестворювати package roots на кожному синку, що ламало білди в Xcode для апок із власним `Package.swift`
• полагодили warning про package exports на шляху `react-native/virtualized-lists`

У нотатках до rc.2 команда прямо пише, що [0.88 — non-breaking реліз](https://github.com/facebook/react-native/releases/tag/v0.88.0-rc.2), тож апгрейд має бути спокійним. Якщо юзаєш SwiftPM або кастомний `Package.swift` — саме цей RC варто ставити на тест просто зараз, бо фікс автолінкінгу прицільно про тебе.

## 🧰 Бібліотеки й тулінг

**MSW [зарелізив 3.0](https://github.com/mswjs/msw/releases/tag/v3.0.0) і виніс React Native в окремий пакет**

Експорт `msw/native` прибрали зовсім — замість нього [`@msw/react-native`](https://mswjs.io/docs/integrations/react-native/). Сетап теж інший: `setupServer(...handlers)` став `network.configure({ handlers })`, а сам пакет треба імпортувати ДО будь-чого з `msw`.

Решта великого в релізі: ESM-only, мінімальний Node тепер 22, мінімальний TypeScript — 5.9, `graphql` переїхав у `msw/graphql`, `worker.stop()` повертає Promise. Тарбол схуд на 43%, тайпінги — на 50%.

⚠️ **Міграція:** `msw/native` видалено, ESM-only, Node 18/20 і TS 5.1-5.2 більше не підтримуються. [Гайд 2.x → 3.x](https://mswjs.io/docs/migrations/2.x-to-3.x)

Якщо мокаєш мережу в RN-тестах — це не той апдейт, що проїде сам собою. Мінорна версія Node у CI теж може стати сюрпризом.

**Reanimated [випустив 4.7.1](https://github.com/software-mansion/react-native-reanimated/releases/tag/4.7.1) — зачистка крашів після нового движка layout-анімацій**

Минулого тижня 4.7.0 зробив новий движок дефолтним, і ось хвіст наслідків:
• краш у Layout Animations proxy, коли view флатиться одночасно з розфлачуванням батька
• полагодили лік view від exiting-анімацій на Android під mounting coordinator pull model
• `useAnimatedSensor` не падає на невідомому типі сенсора
• полагодили краш із `react-native-screens` при видаленні екранів нативного стека
• синхронно оновлені пропси більше не відкочуються до старих значень, коли view зсувається через зміну zIndex у сусіда
• `useAnimatedKeyboard` не падає на iOS в апках на UIScene lifecycle

Breaking changes немає. Якщо ти відкладав 4.7 через нестабільність нового движка — це саме той патч, на якому варто спробувати ще раз.

**React Native Skia [дійшла до 2.14.0](https://github.com/Shopify/react-native-skia/releases/tag/v2.14.0), дорогою викинувши legacy-архітектуру**

У 2.14.0 прибрали deprecated mutable SkPath API разом із ворнінгами — курс на іммутабельні шляхи. Плюс фікс, який змушував вручну викликати GC у декларативному рендерері.

Трохи раніше [2.13.0](https://github.com/Shopify/react-native-skia/releases/tag/v2.13.0) прибрав підтримку legacy-архітектури і додав вибір backing view на Android через `android.surfaceType`.

⚠️ **Міграція:** mutable SkPath API видалено (2.14.0), legacy-архітектура більше не підтримується (2.13.0) — обидва релізи ламають код, який на них спирався.

▶ [Дивитись](https://www.youtube.com/watch?v=L-PNQi1nBSA) — William Candillon показує Skia Graphite, Three.js, Lottie і Android-інтеграції (2 жовтня)

Після того як Shopify передала проєкт, темп релізів не впав — за тиждень три версії. Якщо досі на legacy arch, апгрейд Skia тепер заблокований до переходу на New Architecture.

**[Lucent](https://github.com/Fausto95/lucent) — нативні модулі для RN на TypeScript, що компіляться в C++**

Заміна Swift/Kotlin-модулям, але з TypeScript: Lucent компілює перевірений підмножинний TS у C++ і викликає його через JSI. Автор формулює так: «no Swift or Kotlin to write».

Наскільки стабільна — тут усе дуже прямо. У README написано дослівно: «Experimental: not for production. APIs and the language subset change without a migration path.» Тобто API змінюватимуться без гайдів міграції. У репозиторії 30 зірок і 25 відкритих issues, потрібен RN 0.88+ або Expo SDK 58+ із dev-білдами, для e2e-тестів — Hermes.

Чим може покращити апку: поки що виграш суто в DX — одна мова замість трьох. Бенчмарків автор не опублікував, хоч папка `benchmarks` у репо є, тож про перформанс чесніше сказати «невідомо».

```bash
npm i -D @lucent-lang/lucent
npx lucent init
```

Цікаво стежити, але в продакшен-апку я б це поки не тягнув — попередження автора варто читати буквально.

**Lynx [зарелізив 4.0](https://lynxjs.org/next/blog/lynx-4-0) — фолди, blur-view і власний webview**

Головне в релізі:
• підтримка фолдів із динамічним оновленням конфігурації екрана і CSS Media Queries Level 4
• відкрили елемент `blur-view` — Liquid Glass на iOS і нативний backdrop blur на решті платформ
• новий елемент `webview` для Android, iOS, HarmonyOS, macOS і Windows
• у ReactLynx з'явились `createElement` і `cloneElement`, плюс запити памʼяті на iOS та Android

Команда окремо зазначає, що мажорна версія не означає breaking changes — міграція зводиться до підняття залежностей на 4.0.x.

Не привід кидати React Native, але показово, як швидко до Lynx доїжджають фолди і нативний блюр. У RN за тим самим доводиться йти в сторонні бібліотеки.

## 📲 Платформи і стори

**Google Play [розширив платформу підписок](https://android-developers.googleblog.com/2026/09/unlocking-Google-play-subscription-growth.html) — мультисіти, usage-based білінг і змішані корзини**

Що з'явилось для монетизації:
• Multi-Quantity Subscription Purchase — кілька сітів підписки в одній транзакції, під команди і навчання
• Usage-Based Billing — prepaid metered з автоматичними топапами, прицільно під AI-тули зі змінною собівартістю
• Mixed Carts — підписка і one-time продукт в одному чекауті через один виклик API
• Cross-Developer Bundling — бандли підписок між апками або з партнерами

З боку ретеншена: In-App Messaging API (уже доступний усім) для повідомлень про відмови платежів і зміни цін, Dynamic Grace Period на ML, Retention і Winback офери.

Частина фіч ще розкочується через Early Access Program із окремими партнерами, а конкретні версії Play Billing Library в пості не названі — їх треба дивитись у доках.

Якщо в апці є підписки, найпрактичніше тут — In-App Messaging API: він уже загальнодоступний і закриває найбільшу дірку в ретеншені, відмови платежів.

## 💡 Рецепти

**Один файл шрифту замість шести ваг — [variable fonts у RN 0.88](https://reactnative.dev/docs/next/text-style-props)**

У 0.88 у `Text` з'явився проп `fontVariationSettings`. Сигнатура з доків:
`fontVariationSettings: string | object: {[axis: string]: number}`

Приклад прямо з доків — обидві форми еквівалентні:

```tsx
<Text style={{ fontVariationSettings: { wght: 500 } }}>
  Variable font
</Text>

<Text style={{ fontVariationSettings: "'wght' 500" }}>
  Variable font
</Text>
```

Осі залежать від шрифту: `wght` (вага), `wdth` (ширина), `opsz` (оптичний розмір) плюс кастомні. Рядкова форма — CSS-сумісна, тож конфіг можна тягати між вебом і RN.

Звідки це: офіційні доки RN у версії next, тобто 0.88. Обмежень по платформах у доках не вказано, але на стабільній 0.87 пропа ще немає — перевірити зможеш тільки на RC.

Головний практичний виграш — assets: замість шести статичних файлів ваг одна variable-ітерація шрифту. Для апок із великою типографікою це помітні кілобайти в бандлі.
