## ⚛️ React

**TanStack [показав Redact](https://tanstack.com/blog/introducing-tanstack-redact) — зменшену заміну react-dom у браузері**

Що робить і що замінює: реалізує ті React-API, які апка реально юзає для рендеру й апдейтів, і підміняє собою React та React DOM тільки в браузері. Імпорти, компоненти, хуки й залежності лишаються ті самі.

Чим може покращити — економія клієнтського бандла з їхніх бенчів (gzip, JS плюс CSS, дефолтні білди):
• Vite — 68.3 → 20.1 KB, мінус 70.5%
• TanStack Start — 109.3 → 62.3 KB, мінус 43%
• Vinext — 138.1 → 98.8 KB, мінус 28.5%

Наскільки стабільний: версія 0.2.0. Автор пише, що інші команди вже юзають його в проді і що сама команда TanStack на нього спирається. Головне обмеження виписане в анонсі прямо: Redact рендерить синхронно, тож time slicing і прерваного рендеру немає — дорогий рендер і далі заблокує інпут.

React Native це не торкається взагалі. Але якщо тримаєш веб-частину на Vite, мінус 48 кілобайт за підміну двох пакетів — цифра, яку варто перевірити на своєму білді.

## 📱 React Native та Expo

**React Native [випустив 0.88.1](https://github.com/facebook/react-native/releases/tag/v0.88.1) — і заодно перевів iOS-збірку на `-O2`**

Патч від 27 жовтня. Найцікавіше тут не фікси, а зміна флагів: C/C++/Objective-C код React Native у Release тепер компілюється з `-O2` замість `-Os`, а Yoga і glog перейшли на `-O2` у всіх білдах, як на Android.

З фіксів, які справді видно:
• StatusBar (style і visibility) знову працює на iOS 27, якщо апка збирається під iOS 27 SDK і `UIViewControllerBasedStatusBarAppearance` стоїть у `YES`
• recycled image view на iOS більше не показує картинку попереднього source
• Text без background color не малює напівпрозору підкладку
• LogBox полагодили під iPhone Duo

⚠️ **Міграція:** `spm add` і `spm update` тепер пишуть build settings та скрипти в `ReactNativeSPM/`, щоб бампи версій не чіпали `project.pbxproj`. Власні xcconfig мусять робити `#include` згенерованого файлу, а таргет-налаштування, що перекривають значення, потребують `$(inherited)`. Окремо: щоб запрацювала pre-action «Sync SPM Autolinking», існуючу схему треба один раз перезаписати через `npx react-native spm update`. [Релізноути](https://github.com/facebook/react-native/releases/tag/v0.88.1)

Для більшості це безболісний патч. Але якщо ти на SwiftPM — не відкладай: без одноразового `spm update` автолінкінг просто не підхопиться.

**Expo [представив @expo/agent-cli](https://expo.dev/blog/introducing-expo-agent-cli) — CLI, написаний під кодинг-агентів**

Ідея проста: агент не має вгадувати, чи достатньо Expo Go, чи треба нативний ребілд. `status` інспектить проєкт і каже, що робити далі, нічого не запускаючи. `dev` сам обирає між Expo Go і dev-білдом та переюзує готові білди, `dev --plan` спершу показує план. `smoke` стартує апку, перевіряє, що вона завантажилась, і шукає рантайм-помилки.

```bash
npx --yes @expo/agent-cli@latest status
npx --yes @expo/agent-cli@latest dev --ios
npx --yes @expo/agent-cli@latest smoke --ios
npx --yes @expo/agent-cli@latest agents:setup
```

Дві речі вирішують реальний біль: кожен git worktree отримує власний симулятор чи емулятор, тож паралельні агенти не бʼються за девайс, а пакети можуть везти власні skills, які CLI синхронізує в папку скілів агента (це прибито до SDK 58).

Наскільки стабільний: експериментальний, автори пишуть, що команди й вивід ще змінюватимуться. Локальний режим — дефолт, на EAS CLI сам не переключиться, тільки з `--eas`, і це їсть кредити.

![expo agent-cli](https://cdn.sanity.io/images/9r24npb8/production/03dabb891658e1f9819fa4a8e717137d1a2f1e6d-3600x2025.png?auto=format&fit=max&q=75&w=1200)

Ізоляція симулятора по worktree варта спроби вже зараз — це найболючіше місце при паралельних агентах. Решту тримав би на дистанції: експериментальний CLI у критичному шляху білда дебажити не хочеться.

**William Candillon [виклав цифри перформансу](https://wcandillon.dev/article/hello-graphite-performance) Skia на Graphite — і вони великі**

Продовження переїзду Skia на Graphite, який я згадував 11 жовтня: тоді був сам реліз, тепер заміри. Тест — Reanimated-анімація поруч з канвасом, що малює прямокутники:
• Pixel 8: v2 падає з 76.2 fps на 1K прямокутниках до 1.0 fps на 48K; v3 тримає близько 120 fps до 24K і 96.3 fps на 48K
• iPhone 14 Pro: v2 — з 119.7 до 4.3 fps, v3 — стабільні близько 119.8 fps по всьому діапазону
• frame pacing на Pixel 8 (120 Hz, TextureView): 58.7 fps у v2 проти 115.9 fps у v3 за даними SurfaceFlinger

Graphite мультитредить рендер за дефолтом, жодних опцій вмикати не треба. Розбити важку сцену на кілька канвасів допомагає, але недовго: на Pixel 8 чотири канваси гірші за два.

▶ [Дивитись](https://www.youtube.com/watch?v=L-PNQi1nBSA)

Головне тут не fps, а те, що важка робота на канвасі більше не тягне вниз нативні анімації — UI-тред вільний. Якщо ти відкладав міграцію на `react-native-skia` 3 через ризик, це найсильніший аргумент за.

#reactnative

**react-native-screens [додав ScrollViewMarker](https://swmansion.com/blog/introducing-scroll-view-marker-in-react-native-screens/) — щоб платформа більше не вгадувала, який скрол головний**

Великий заголовок на iOS згортається, таб-бар на iOS 26+ мінімізується, Material app bar на Android піднімається — усе це платформа чіпляє до «головного» скролу екрана, знаходячи його евристикою по вʼю-ієрархії. Евристика тихо ламається, якщо обгортка отримала background color або RN сплющив вʼюху: ефекту просто немає. Раніше лікувалось тим, що скрол тримали першою дитиною, або `collapsable={false}`.

Тепер скрол позначається явно:

```jsx
<ScrollViewMarker style={{ flex: 1 }}>
  <FlatList data={chats} renderItem={renderChat} />
</ScrollViewMarker>
```

Маркер приймає одну дитину, по одному на екран (якщо кілька — виграє останній) і працює як звичайна лейаут-вʼюха, тож `flex: 1` зі списку треба перенести на нього. LegendList обгортається як FlatList, FlashList потребує прокидання через `renderScrollComponent`.

Доїхало в react-native-screens 5 — поки 5.0.0-alpha. На 4.x лишається `scrollEdgeEffects` на екрані й та сама евристика.

Альфа, тож у прод не завтра. Але якщо ти колись дебажив «чому не згортається великий заголовок» — це саме той фікс, на який варто чекати.

## 🧰 Бібліотеки й тулінг

**Nitro [випустив першу альфу V1](https://github.com/margelo/nitro/pull/1802) — ядро відʼєднали від React Native**

Marc Rousavy [анонсував альфу](https://x.com/mrousavy/status/2113257713169821719) 22 жовтня, нічні білди `v1.0.0-alpha.*` сипляться далі, останній — 28 жовтня. Зміна архітектурна: новий `nitro-core` більше не знає про React Native, а RN-адаптери (Fabric-хелпери, CallInvoker-диспетчер, TurboModule-бутстрап) переїхали в `react-native-nitro-modules`. Автор пише, що це робиться, щоб принести Nitro в NativeScript, LynxJS та інші мобільні JS-фреймворки. Друга зміна — для авторів бібліотек: HybridObject став справжнім класом, з конструкторами, статичними методами й реєстром, замість старого interface API.

⚠️ **Міграція:** багато. Викинули старий interface API, `Sync`, `AnyMap` і `getHybridObjectConstructor`, прибрали Date; блок `autolinking` у nitro.json більше не приймається; ключі перейменовані без фолбеку (`apple.appleModuleName` → `apple.moduleName`, `android.androidNamespace` → `android.namespace`, `android.androidCxxLibName` → `android.cxxLibName`); Kotlin-колбеки з лямбд перейшли на дженерик `Callback`; iOS-білд переїхав на Swift Package Manager. Вимоги — RN 0.88 і New Architecture. Окремого migration guide поки немає, тільки [PR V1](https://github.com/margelo/nitro/pull/1802) і прев'ю-деплої доків.

Nitro напряму майже ніхто не ставить, тож більшість це зачепить через апдейти бібліотек на кшталт Nitro Fetch. Авторам нітро-модулів варто поганяти альфу зараз, решті — чекати стабільного V1 і нормальних релізнот.

**Тиждень React Native на десктопі: [RNW 0.85](https://devblogs.microsoft.com/react-native/react-native-windows-v0-85-is-here/), [Expo Desktop](https://expo-desktop-docs.vercel.app) і [Legend Spark](https://legend.so/spark)**

React Native Windows 0.85 (на RN 0.85.3) добила перехід: легасі-архітектуру видалили повністю. З дрібного — `hideTitleBar` і `hideBorder` для модалок, `outline` на View, швидший рендер тексту.

⚠️ **Міграція:** апки на старій архітектурі мусять переїхати на Fabric до апгрейду. Потрібні Visual Studio 2026, .NET 10 і Windows App SDK 1.8. Прибрали `WinRTWebSocketResource` та `JSBigStringResourceDll` — форки, що на них спирались, доведеться правити. [Анонс](https://devblogs.microsoft.com/react-native/react-native-windows-v0-85-is-here/)

Поруч — два незалежні проєкти. **Expo Desktop** Jamie Birch: CLI `expo-desktop` плюс config-плагіни, що дають Expo-апці macOS і Windows через один `prebuild`. Expo його не підтримує і не схвалює, і scope-сторінка чесна — версія RN тут найменший спільний знаменник RN macOS і RN Windows, тож відстає на кілька мінорів; для macOS збирається приблизно третина iOS-модулів Expo SDK, для Windows Expo Modules Core «basically a stub for now»; EAS не працює, бо немає Windows-раннерів; Linux немає.

**Legend Spark** — надбудова над Expo Desktop: один пакет `@legendapp/spark` з нативними вікнами, меню, шорткатами, файлами й діалогами, Hermes і без браузера всередині. Версія 0.0.1, самі пишуть «Experimental — not for production», цільова платформа — macOS 14+ на Apple Silicon.

Потрібен десктоп сьогодні — це RNW або Electron. Ці два поки цікавий напрямок і не більше: 0.0.1 і «не схвалено Expo» в описі говорять самі за себе.

## 💡 Рецепти

**Прибрати Babel-плагін Unistyles і перейти на [Metro-інтеграцію](https://www.unistyl.es/v3/other/metro/)**

Unistyles 3.6 привіз `react-native-unistyles/metro` — альтернативу Babel-плагіну взагалі без трансформу. Замість переписування коду Metro-резолвер підміняє RN-компоненти на Unistyles-версії в рантаймі, а StyleSheet сам трекає свої залежності під час виконання.

Практичний виграш: тему отримують і сторонні компоненти, включно з тими, що лежать у `node_modules` — те, що Babel-плагін не покривав.

```js
// metro.config.js
const { getDefaultConfig } = require('expo/metro-config')
const { withUnistylesConfig } = require('react-native-unistyles/metro')

const config = getDefaultConfig(__dirname)

module.exports = withUnistylesConfig(config)
```

Для bare RN перший рядок — `require('@react-native/metro-config')`. Опцій інтеграція не приймає.

Далі обовʼязковий крок: прибрати `react-native-unistyles/plugin` з `babel.config.js`. Якщо залишити обидва, Unistyles кидає помилку.

Конфіг дослівно з доків Unistyles, самі вони позначають інтеграцію як experimental, а Babel-плагін лишається дефолтом. Тож це «спробуй на гілці», а не «переводь прод».

Заодно в 3.6 поїхала оптимізація: вʼю, у чиєму `style` немає unistyle, більше не лінкуються. У їхньому бенчі на 900 вʼюхах (iOS-симулятор, Release, 3.5.3 → 3.6.0) ре-рендер плоскої вʼюхи впав з 13.0 до 6.4 мс, анмаунт — з 5.0 до 1.3 мс.
